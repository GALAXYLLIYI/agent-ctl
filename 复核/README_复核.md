# 复核护栏（仓内副本）

本目录是「主控复核护栏」的**仓内自洽副本**：原件在本机活件区
`work\_M19_语义修复_20221023\主控复核\`，但 `work\` 整个被 `.gitignore` 排除
⇒ 干净克隆上原本**没有**这套护栏 ⇒「形状白名单 + 数量账本」双保险**只在本机生效**。
本目录把它复制进仓，让任何拿到干净克隆的人都能跑同一套八组检查。

> 本目录只做「复制 + 可移植化 + 自检」：**不碰** `tests\` 下任何判据、
> **不碰**产品代码（`src\` / `legacy_tools\` / `contract\`）、**不碰** `work\` 下的活件、
> 不改 `.gitignore`、不 `git add` / `commit`、不登记进 `tests\run_all.py`。

### 为什么落点在仓根，不在 `tools\` 或 `tests\`

* `tools\*` 与 `tests\*` 在 `.gitignore` 里都是**白名单制**（只放行个别文件）
  ⇒ 放进去必须改 `.gitignore` 才能进干净克隆；
* 两处都在 `tests\_写死路径判据.py` 的**扫描范围**内
  （`src/ tools/ tests/ contract/ verify/ build/ legacy_tools/ docs/`）
  ⇒ 两份**基线快照**里各有 5~6 处盘符路径（冻结的历史产物，按设计带着）
  ⇒ 放进去会让那条判据的「命中计数自证」再多出 3 个文件 / 12 行（它现在**本来就红**，
  本单不碰它，也不该让它更红）；
* 仓根一层目录**不在**那条判据的扫描范围里（它只扫「代码面」），
  而 `work\` 也同样被排除在代码面外（理由写在 `.gitignore` 里：work 是留痕材料）。
  ⇒ 护栏 = 护栏 + 基线快照，属同一类「留痕材料」。

## 八组检查

①三处 act.py MD5 全等 ②不变量零改动 ③常量零改动 ④行尾 LF
⑤M19′/M19P 合法改动块 ⑤-b 改动真代码行**数量**账本 ⑥「生效」出口清单
⑦判据四种跑法退出码 ⑧二次判差检查（性能不变式）

## 三条诚实边界

1. **live 不在仓里**。live（真在跑的那份 legacy）由 `build\local_legacy_home.txt`
   指针指向，**是本机状态、未 tracked** ⇒ 干净克隆上定位不到，属「验不了」。
   本副本此时把 ① 组的 live 一格**明确打印后跳过**（不判红、也不静默跳过），
   仓内两处（真源 / 产物）仍全等。live 漂移由 `tools\check_live_sync.py` 专责
   （它自己就是三档退出码：0 一致 / 1 有红 / 2 验不了，发包侧对 2 是「跳过并提示」）。
2. **签出行尾由每台机器的 git 配置决定**。本仓**没有** `.gitattributes`：
   入库的 blob 是 LF（逐字节护栏就按这个算），但全局/系统 `core.autocrlf=true` 的机器上，
   普通 clone 会把 LF **改成 CRLF** ⇒ ②③④⑤ 组在那种克隆上必红 ——
   **与护栏是否进仓无关**，是仓级既存问题（与「写死路径」那单同类）。
   自检脚本的克隆演练用 `git -c core.autocrlf=false clone` 复现**入库字节**。
3. **副本与活件会漂**。本目录是 2026-10-23 的快照；主控每往活件账本里追加一段，
   就要把 `复核\M19\` 里的四个文件同步过来。

## 与活件的差异（只有复核脚本的路径可移植化）

活件版 `work\_M19_语义修复_20221023\主控复核\复核_M19_20221023.py` 把仓根与 live
写死成了盘符绝对路径。照抄进仓会有两个后果，两个都要命：

* 干净克隆上验的是**开发机的工作树**，不是入库物 ⇒ 绿灯与入库物无关（闸门会撒谎）；
* 仓内多出盘符绝对路径 ⇒ 撞 `tests\_写死路径判据.py` 的命中计数自证。

所以仓内副本只改这几处（其余**逐字节相同**）：

| 位置 | 活件版 | 仓内副本 |
|---|---|---|
| `ROOT` | `r"<仓根>"`（活件版里是本机绝对路径） | 从 `__file__` 推（`复核\M19\` 的上一级 = 仓根），保留 `AGENTCTL_ROOT` 覆盖口 |
| `BAK` | `work\...\backup_before\...` | `复核\backup_before\...`（同包相对） |
| `LIVE` | `r"<live 目录>\tools\act.py"`（活件版里是本机绝对路径） | 运行时定位（`AGENTCTL_LIVE_ACT` → `build\local_legacy_home.txt` 指针）；定位不到 = 验不了 = 明确打印后跳过该格 |

口径与仓内既有约定一致：`tests\check_t1_w1.py` / `tests\run_all.py` 同一套
「`__file__` 推仓根 + `AGENTCTL_ROOT` 覆盖口」（由 `tests\_M_可移植性判据.py` A 段守着）。

### 账本为什么**一个字节都没改**

账本里 `files["act.py"].baseline.path` = `../backup_before/act_1_src__legacy_tools__act.py`
是**相对账本所在目录**的相对路径。本目录**照搬了活件的同形布局**
（`M19\` ≡ `主控复核\`，`backup_before\` 仍是它的兄弟目录）
⇒ 那条相对路径在新落点下**原样指得到**
⇒ 账本 / 账本工具 / 两份基线快照与活件**逐字节相同**，整本指纹仍是 `793d5886…`，
**不需要**（也不应该）重算任何校验值。
