# 工单模板 v1（2026-10-19 DSH 立，用户批评后修正）

> **起因**：用户指出——「工单只说干什么，没说结果应该怎么样、什么样的问题可以解决，
> 导致后面各自的结果不一致」。本模板把后果前置：**先定义"完成长什么样"，再谈做什么。**
> 适用范围：派给 Codex / MiMo / OpenCode / ZCode / DSH 自己的每一张单。
> 缺任一栏 ⇒ 接单方**有权退回**（不接半张单）。

---

## 0. 一句话目标（≤40 字）
> 用一句话说清"要达成什么状态"，不是"要执行什么动作"。
> ❌ "加一条判据"　✅ "让『判不了』永远不被当成成功，并且能被一条判据当场抓住"

## 1. 结果定义（交付物必须长什么样）
逐项列出**可检查的产物**，不是描述过程：
```
① 文件路径 + 必须包含的内容（关键字段/函数/行为）
② 代码：函数名/返回码/新字段名（要精确到能被 grep 到）
③ 文档：哪一节、写什么结论
④ 数据：哪份日志、哪一行汇总必须出现
```

## 2. 判定口径（什么算解决 / 什么不算 / 什么算验不了）
| 档 | 定义 | 例 |
|---|---|---|
| **算解决** | 判据复跑绿 + 证据落盘 + 与真源一致 | 判据 34 绿（0 处 `is not False`）+ md5==真源 |
| **不算解决** | 代码改了但判据没复跑 / 改了运行时没留 md5 / "应该好了" | 声称已刷新但 md5 仍是旧值 |
| **算验不了** | 环境不满足（无通行证/无窗口/无网络），**必须显式说验不了，不许写绿** | 无证 ⇒ rc=2 |

## 3. 证据要求（没证据 = 没做）
```
· 每个"绿"必须留原始输出文件路径（txt/log）
· 每个"改了"必须留前 md5 / 后 md5
· 每个"判据有效"必须留 --inject 变红的输出
· 结论里出现的每个数字，都要能在盘上找到出处
```

## 4. 边界（明确不许做什么）
```
· 不许改的产品口径（例如：提交按钮永不点）
· 不许动的目录/文件（运行时目录要改必须走"备份+刷新+md5"三步）
· 不许擅自扩范围（发现别的问题 → 写进"顺手发现"回报，不自行开工）
```

## 5. 分工与模型预算
```
主控（定判据/验收/写文档）：DSH
执行（改代码/跑判据）：按活的性质派
审核（独立复跑/挑错）：ZCode（第三方异构）
批量（重复劳动）：MiMo（便宜）
GLM：只留给必须强推理的少数步，不进常规回路
★ 本单允许的模型：______ ｜ 超预算就换廉价路，不许硬烧
```

## 6. 回报格式（固定六行，多一个字都不要）
```
① 做成了什么（对应 §1 逐项）
② 没做成什么 + 为什么
③ 判据结果：绿 x / 红 y / 验不了 z（附输出文件路径）
④ 证据：md5 前→后 / 关键日志行
⑤ 顺手发现（不改，只报）
⑥ 需要我拍板的（≤2 条）
```

---

## 附：为什么这样能治"结果不一致"
> 以前各自自由发挥是因为**验收标准藏在主控脑子里**。
> 现在标准写在单上：**三档判定 + 证据要求 + 固定回报格式**——
> 谁接单，交出来的东西形态都一样，主控只需要"对表"，不需要"猜意图"。
