# 加贡献者协作者 · 可直接复制的命令

> 用途：给贡献者授予 **maintain** 权限（可管分支与 release，不能改危险设置）。
> 仓库：GitHub `GALAXYLLIYI/computer-use-gate` ／ Gitee `GALAXYLIYI/computer-use-gate`
> 生成时间：2026-10-26

---

## 〇、最省事的做法：跑仓里的脚本

```powershell
python -X utf8 tools\加协作者.py
```

交互式 —— 它会逐个问你要账号名，**先查账号存不存在、再发邀请、最后回读确认**。

也可以一次给多个：

```powershell
python -X utf8 tools\加协作者.py 用户名1 用户名2 用户名3
```

或从文件读（一行一个，`#` 开头为注释）：

```powershell
python -X utf8 tools\加协作者.py --file contributors.txt
```

> ⚠ **别把下面的手工命令当首选**：`<GitHub用户名>` 这个占位符如果忘了替换，
> 会发出一次**无效请求**并返回 404 —— 看起来像「没权限」，其实只是「用户不存在」。
> 脚本会在发请求前就查清楚，并把原因写明。

## 〇·二、⚠ GitHub 的权限天花板：maintain 不是想给就能给

**实测结论（2026-10-26）**：GitHub **只允许把 maintain / triage 授予「组织或企业成员」**。
个人账号（不属于任何 org/enterprise）**最高只能给 push**。

给个人账号授 maintain 会被拒，报错长这样：

```
HTTP 422 {"message":"Validation Failed",
          "errors":"Cannot assign <用户名> permission of maintain"}
```

⚠ 这条报错**很容易被误读成「仓库配置有问题」**或「权限不够」，
实际是 **GitHub 的账号类型限制**，跟你这边的配置无关。

**怎么办**：

- 想要 maintain ⇒ 只能把仓库转到 org，或建个 org 把对方加进去
- 不想折腾 ⇒ **用 push**（本仓 `tools\加协作者.py` 会自动降级重试，已实测跑通）
- push 够不够用？见下面 §一·三 的对照表 —— **对绝大多数贡献场景，push 足够**

### 各权限级能干什么（GitHub 官方矩阵，摘与本仓相关的行）

| 操作 | 读 | triage | **push** | maintain | admin |
|---|---|---|---|---|---|
| 推分支、开 PR | ✗ | ✗ | **✓** | ✓ | ✓ |
| 合并 PR | ✗ | ✗ | **✓** | ✓ | ✓ |
| 批准/请求更改 PR | ✗ | ✗ | **✓** | ✓ | ✓ |
| 创建和编辑发布版 | ✗ | ✗ | **✓** | ✓ | ✓ |
| 管 issue / 标签 / 里程碑 | 部分 | ✓ | **✓** | ✓ | ✓ |
| 跑 CI、看日志 | ✓ | ✓ | **✓** | ✓ | ✓ |
| 锁定对话 | ✗ | ✗ | ✗ | **✓** | ✓ |
| 管 Webhook / 部署密钥 | ✗ | ✗ | ✗ | **✓** | ✓ |
| 改分支保护 / 规则集 | ✗ | ✗ | ✗ | ✗ | **✓** |
| 改仓库设置、管协作者、删仓库 | ✗ | ✗ | ✗ | ✗ | **✓** |

## 一、GitHub（推荐先做这个）

### 1.1 发邀请（手工方式）

> ⚠ 手工方式**必须把 `<GitHub用户名>` 换成真实用户名**。忘了换会得到 404，
> 那是「用户不存在」，不是「没权限」。建议直接用上面的 `tools\加协作者.py`。

把 `<GitHub用户名>` 换成对方的 GitHub 用户名（不是昵称、不是邮箱）：

```powershell
gh api -X PUT repos/GALAXYLLIYI/computer-use-gate/collaborators/<GitHub用户名> -f permission=maintain
```

成功时无输出、退出码 0。验证：

```powershell
gh api repos/GALAXYLLIYI/computer-use-gate/collaborators --jq '.[] | "\(.login) | admin=\(.permissions.admin) | maintain=\(.permissions.maintain)"'
```

### 1.2 批量（多个贡献者，逐个执行）

```powershell
foreach ($u in @('用户名1','用户名2','用户名3')) {
  gh api -X PUT repos/GALAXYLLIYI/computer-use-gate/collaborators/$u -f permission=maintain
  Write-Host "$u -> exit=$LASTEXITCODE"
}
```

### 1.3 怎么把用户名给到对方

对方接受邀请有三条路，任选其一：

- **网页**：https://github.com/GALAXYLLIYI/computer-use-gate/invitations
- **通知栏**：GitHub 右上角铃铛里有邀请
- **邮件**：邀请会发到对方 GitHub 账号绑定的邮箱

> ⏳ **邀请 7 天过期**。过期后在上面那个 `/invitations` 页面点 "Resend" 重发，或重跑 1.1 的命令。

### 1.4 授予后对方能做什么

**push 权限（个人账号能拿到的最高档）**：

| 能 | 不能 |
|---|---|
| 切分支、推自己的分支 | 直推 `main`（已开保护，必须走 PR） |
| 开 PR、评论、review | 合并自己的 PR（不能自批自合） |
| **批准/请求更改别人的 PR** | 绕过 `main` 的 PR + 1 批准 + CI 绿三道闸 |
| **创建和编辑发布版（release）** | 改仓库设置、管协作者、删仓库、改可见性 |
| 管 issue / 标签 / 里程碑 | 锁定对话、管 Webhook（这两项要 maintain） |
| 跑 CI、看日志、重跑 workflow | 改分支保护规则 / 规则集（只有 admin） |

> 💡 结论：**push 足够贡献者干活**。协作者能推代码、开 PR、review 别人的 PR、
> 甚至发 release —— 日常协作不缺能力。真正被锁在 admin 门外的只有
> 「改仓库设置 / 改保护规则 / 管协作者」这类**危险动作**，本来就该只留给你。

**maintain 多出来的三样**（个人账号拿不到，除非建 org）：锁定对话、管 Webhook / 部署密钥、
把仓库转移到组织。

### 1.5 本仓 main 的三道闸（对方一定会撞上，先告诉他）

`main` 上挂了 ruleset `main-contribution-gate`：

1. **必须走 PR** —— 直推 main 会被拒
2. **1 个批准** —— 需要**别人**批准，作者本人是 admin 可 bypass
3. **CI 闸门绿** —— `闸门（无桌面依赖）` 必须过
   （另有 `观察位（已知红 · 不阻塞）`，那条**故意不阻塞**，别被它吓到）

外加：**禁 force push、禁删分支、禁自批自合（`require_last_push_approval`）**、
**对话必须全部解决**才能合。合并方式限 `merge` 与 `squash`（无 rebase）。

## 二、Gitee

Gitee 的账号名**通常和 GitHub 不同**，需要单独给。

### 2.1 发邀请

先取本机已存的 Gitee 凭据（不会打印明文）：

```powershell
$psi = New-Object System.Diagnostics.ProcessStartInfo
$psi.FileName='git'; $psi.Arguments='credential fill'
$psi.RedirectStandardInput=$true; $psi.RedirectStandardOutput=$true
$psi.RedirectStandardError=$true; $psi.UseShellExecute=$false
$p=[System.Diagnostics.Process]::Start($psi)
$p.StandardInput.Write("protocol=https`nhost=gitee.com`n`n"); $p.StandardInput.Close()
$out=$p.StandardOutput.ReadToEnd(); $p.WaitForExit()
$tok=((($out -split "`r?`n") | Where-Object { $_ -like 'password=*' }) -replace '^password=','')
$tok=[uri]::EscapeDataString($tok)
```

再逐个加（`<Gitee用户名>` 换成对方 Gitee 用户名）：

```powershell
foreach ($u in @('Gitee用户名1','Gitee用户名2')) {
  Invoke-RestMethod -Uri "https://gitee.com/api/v5/repos/GALAXYLIYI/computer-use-gate/collaborators/$u?access_token=$tok&access_level=3" -Method Put
  Write-Host "$u -> done"
}
```

### 2.2 验证

```powershell
Invoke-RestMethod -Uri "https://gitee.com/api/v5/repos/GALAXYLIYI/computer-use-gate/collaborators?access_token=$tok" |
  ForEach-Object { "$($_.login) | name=$($_.name)" }
```

### 2.3 access_level 取值

| 值 | 含义 | 对应 GitHub |
|---|---|---|
| 1 | 个人权限 | — |
| 2 | 开发（只读） | `triage` |
| **3** | **维护（读写）** | **`maintain`** ← 本次用这个 |
| 4 | 管理员（可设保护） | `admin` |

### 2.4 备选：网页加

若 API 报 400/404（用户名不存在或无权限），走网页：
https://gitee.com/GALAXYLIYI/computer-use-gate/settings/collaborators
（设置 → 仓库成员管理 → 添加成员）

> ⚠ **Gitee 侧还没配保护分支**。GitHub 那边已经配好「必须 PR + 1 批准 + CI 绿」，
> Gitee 这边如果也要同样的规矩，需要单独配一套（Gitee 的保护分支设置与 GitHub 不是同一套机制）。

## 三、加完之后别忘了填名单

平台授权只是第一步，仓里的名单还要跟上。编辑 `CONTRIBUTORS.md`：

- 第 19 行：`| _待填：GitHub 用户名_ | GitHub | 2026-10-26 | _待填_ |`
- 第 25 行：`| _待填_ | _GitHub / Gitee_ | _待填_ |`

然后提交推送：

```powershell
git add CONTRIBUTORS.md
git commit -m "贡献者名单：补 N 位协作者（<用户名>）"
git push github main
git push origin main
```

> ⚠ `main` 现在有保护规则，你作为 admin 能直推（bypass）；**协作者不能**，他们要走 PR。

## 四、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| GitHub 邀请发不出去 | 用户名拼错（用了昵称/邮箱） | 用 `gh api users/<用户名>` 查准确 ID |
| GitHub 返回 404 | 该用户名不存在 | 同上 |
| Gitee 返回 400 | 用户名不存在或 token 权限不足 | 检查 token 有效期；或走网页加 |
| 对方说没收到 | 换了邮箱 / 邮件被拦 | 让对方直接开 `/invitations` 页面看 |
| 邀请过期 | 7 天有效期 | 页面点 Resend，或重跑命令 |
| 对方推不了 main | 分支保护生效（预期行为） | 让对方切分支提 PR |
