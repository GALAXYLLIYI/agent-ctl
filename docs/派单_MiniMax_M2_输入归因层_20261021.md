## 0. 一句话目标（≤40 字）

> 让本机每一笔输入动作都能判定来源：agent 做的 / 电脑前真人敲的 / 远程或其他程序注入的。

## 背景（统一目标）

> **以最小代价让 agent 具备电脑控制能力，进而实现自动化；只在 GUI 层面做。**

用户追加的两条诉求，本单一并回答：
1. 「捕捉图形变化 + 抓取文字图像」——需要查清本机**已经有什么**，再判断「训练一个识别器」值不值。
2. 「后台监控：动作是 agent 做的，还是电脑前的人在操控，还是远程程序在操控」——**这就是本单主体**。

## 2. 判定口径

| 档 | 定义 |
|---|---|
| **算解决** | 三件交付物齐全；探针真跑起来并留下原始输出；判据 --inject 会变红 |
| **不算解决** | 只写设计不写可跑的；探针跑不起来却说「应该可以」；判据恒绿 |
| **算验不了** | 钩子权限/环境不允许 ⇒ **显式说验不了并写清缺什么**，不许写绿、不许编数据 |

## 3. 证据要求

- 每个「绿」附盘上真实路径与原始输出
- 结论里每个数字能在盘上找到出处
- 失败要留错误原文，不许只报结论

## 4. 边界（明确不许做什么）

- **禁止拦截/吞噬/改写输入**（只观察）
- 禁止改 `agent-ctl/src`、`agent-ctl/contract`、禁止装依赖、禁止起常驻进程
- 禁止读取任何含密钥/密码的文件
- 发现别的问题 → 写进「顺手发现」回报，不自行开工

## 5. 已知线索（自己核，别照抄；错了要指出）

- Windows 低级钩子 `WH_KEYBOARD_LL` / `WH_MOUSE_LL` 的 `KLLHOOKSTRUCT.flags`：
  `LLKHF_INJECTED (0x10)` = 程序注入，`LLKHF_LOWER_IL_INJECTED (0x02)` = 低层注入；物理硬件输入没有这些位
- agentctl 自己的动作走 `SendInput`（属注入），且 `timeline.db` 有事件流水 ⇒ 可做时间对账
- agentctl 已有感知通道：`uia_tree.py` / `ocr.py` / `eye.py`，以及 `ctl_screen` 的 `screen_version` / `watch` / `watch_text` 机制（改动可报、文本变更可报）
