### 单 E：语义屏判据的「无通行证」该判**验不了**而不是红（顺手发现，本轮只报不改）

**现象**：tests/_语义屏判据.py 在「本机没有有效通行证」时，把 ① / ③ / ④ / ⑤ 六条打成**红**，
而它自己在文档里写着的口径是「环境不满足 ⇒ rc=2 验不了，不许写绿也不许算红」
（该文件里已有 blocked ⇒ return 2 的机制）。

**实测**：2026-10-21 同一份代码、同一条判据，两次全量跑出来的结果不一样 ——
一次「验不了（rc=2）」，一次「红（rc=1）」，差别是**当时能不能抢到前台窗口**：
抢得到就会走到 act.py 那一路 ⇒ 沙箱里没有有效通行证 ⇒ code=9「未获授权」⇒ 被当成红。

**为什么这是病**：红应该表示「东西坏了」。把「环境没准备好」算成红，
会让「红」这个信号贬值 —— 无人值守的夜间跑批就会一直红，真正的坏的红反而被淹掉。

**要做的事**：判据里凡是拿到 code=9（未获授权）或缺通行证的位置，一律归入 blocked ⇒ rc=2；
真红留给「内容变了 / 行为不符」。改完要留 --inject 证据（注入真缺陷仍必须红）。

## 2. 判定口径

| 档 | 定义 | 例 |
|---|---|---|
| **算解决** | 判据复跑绿 + 证据落盘 + 与真源一致 + --inject 变红 | 单 A 判据绿 8/红 0，注入后红 ≥1 |
| **不算解决** | 代码改了但判据没复跑 / 只测了顺路径 / 没写注入跑红 | 「统一了哈希来源」但没测「内容变了要拒绝」 |
| **算验不了** | 环境不满足（无真窗口/无通行证），**必须显式说验不了，不许写绿** | 无前台窗口 ⇒ rc=2 |

★ **单 B 的语义没拍板之前，单 B 的一切代码改动都算「不算解决」**。

## 3. 证据要求

    · 每个「绿」必须留原始输出文件路径（work/ 下的 .out / .txt）
    · 每个「改了」必须留前 md5 / 后 md5
    · 每个「判据有效」必须留 --inject 变红的输出
    · 结论里出现的每个数字，都要能在盘上找到出处（别写「大约快了三成」）

## 4. 边界

    · 不许改的产品口径：急停一票否决 / 急停不许 agent 自解 / 旧帧不许点新画面 / 密钥不经模型
    · 不许手改 legacy_tools 产物（真源在 legacy_tools/_src/，用 tools/gen_legacy.py 生成）
    · 不许改判据来让自己变绿（元判据①会抓）
    · 不许擅自扩范围（发现了别的坑 → 写进「顺手发现」回报，不自行开工）
    · 授权弹窗永远由人输密钥 —— agent 拿不到写权限时**不许自签通行证**
