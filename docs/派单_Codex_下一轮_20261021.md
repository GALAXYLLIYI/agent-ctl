## 2. 判定口径

| 档 | 定义 | 例 |
|---|---|---|
| **算解决** | 判据复跑绿 + 证据落盘 + 与真源一致 + --inject 变红 | 单 A 判据绿 8/红 0，注入后红 ≥1 |
| **不算解决** | 代码改了但判据没复跑 / 只测了顺路径 / 没写注入跑红 | 「统一了哈希来源」但没测「内容变了要拒绝」 |
| **算验不了** | 环境不满足（无真窗口/无通行证），**必须显式说验不了，不许写绿** | 无前台窗口 ⇒ rc=2 |

★ **单 B 的语义没拍板之前，单 B 的一切代码改动都算「不算解决」**。

## 3. 证据要求

    · 每个「绿」必须留原始输出文件路径（work/ 下的 .out / .txt）
    · 每个「改了」必须留前 md5 / 后 md5
    · 每个「判据有效」必须留 --inject 变红的输出
    · 结论里出现的每个数字，都要能在盘上找到出处（别写「大约快了三成」）

## 4. 边界

    · 不许改的产品口径：急停一票否决 / 急停不许 agent 自解 / 旧帧不许点新画面 / 密钥不经模型
    · 不许手改 legacy_tools 产物（真源在 legacy_tools/_src/，用 tools/gen_legacy.py 生成）
    · 不许改判据来让自己变绿（元判据①会抓）
    · 不许擅自扩范围（发现了别的坑 → 写进「顺手发现」回报，不自行开工）
    · 授权弹窗永远由人输密钥 —— agent 拿不到写权限时**不许自签通行证**

    ④ 证据：md5 前→后 / 关键日志行
    ⑤ 顺手发现（不改，只报）
    ⑥ 需要我拍板的（≤2 条）
