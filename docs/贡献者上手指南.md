# 上手指南：怎么进这个仓并提第一个 PR

> 面向已收到协作者邀请的贡献者。仓库：**https://github.com/GALAXYLLIYI/computer-use-gate**
> 全文按顺序做一遍，大约 15~30 分钟（含依赖安装）。

---

## 一、接受协作者邀请（★ 第一步，必须先做）

收到邀请邮件后，或者直接打开这个链接：

**https://github.com/GALAXYLLIYI/computer-use-gate/invitations**

点那个 **Accept invitation** 按钮。

> ⚠ **没点接受之前，后面全部走不通** —— 权限还没落到你账号上。
> 接受后右上角头像菜单里会多一个该仓库入口，URL 栏也会出现它。
>
> 邀请 **7 天有效**。过期了让维护者重发，或自己在那个页面上点 Resend。

### 1.1 ⚠ 点完发现"没生效"？先查这三样

**症状**：点了 Accept，但仓库页面还是进不去 / 权限没加上去 / 维护者那边查不到成员。

**最常见的原因：登录了错的账号。** GitHub 的邀请是发给**具体账号**的
（本次是 `1750468716qqcom-maker`）。如果浏览器里登录的是另一个账号，
那个账号看不到这条邀请，也点不了 Accept —— 页面会显示"没有待处理的邀请"。

按顺序排查：

| # | 查什么 | 怎么查 | 对了是什么样 |
|---|---|---|---|
| 1 | **当前登录的是哪个账号** | 右上角头像 → 菜单里显示的是账号名 | 必须是 `1750468716qqcom-maker`（**不是** `GALAXYLLIYI`） |
| 2 | 邀请还在不在 | 打开上面的 `/invitations` 链接 | 列表里有 `GALAXYLLIYI/computer-use-gate` 一行，右侧有 Accept 按钮 |
| 3 | 接受后有没有生效 | 打开 https://github.com/GALAXYLLIYI/computer-use-gate ，看顶部有没有蓝色横幅 | 横幅提示你已经是该仓成员 |

**如果第 1 步查出登录错了账号**：

- 右上角头像 → **Sign out** → 用 `1750468716qqcom-maker` 重新登录
- （推荐）用**隐身窗口**打开 `/invitations`，避免两个账号串味
- 登录对之后，那条邀请应该就在列表里，点 Accept 即可

**如果第 2 步发现列表是空的**：说明邀请已经不在待接受列表里了
（可能已接受，也可能已过期被清理）。问维护者重发一封即可。

**如果第 3 步没有横幅**：多半是接受动作落在了别的账号上，或浏览器缓存了旧页面
（按 `Ctrl+` `F5` 强刷）。

### 1.2 ⚠ 只拿到 read 权限？（★ 2026-10-26 实际踩到）

**症状**：对方说"已经接受了"，但推代码时提示没有权限。

**根因**：对方**接受了邀请，但不是接受这条邀请** —— 实际是通过别的路径进的仓
（比如 star、fork、或点了邮件里的其它链接）。GitHub 对这类操作给**默认 read 权限**，
**和邀请里的 write 是两回事**。

**怎么分辨**（维护者侧，权威口径只有一个）：

```powershell
# ★ 这个端点才是权威的 —— 它返回该账号在本仓的【实际】权限
gh api repos/GALAXYLLIYI/computer-use-gate/collaborators/<用户名>/permission --jq '"permission=\(.permission) role_name=\(.role_name)"'
```

| 观察到的 | 含义 |
|---|---|
| `permission=admin` | 仓库所有者 |
| **`permission=push`** | ✅ 邀请被接受了，可以推分支 |
| `permission=read` | ⚠ **只拿到读权限** —— 邀请没被接受，走的是别的路径进来的 |
| `permission=none` | 完全没进仓 |

> ⚠ **`collaborators` 列表会骗人**：它**只列 push 及以上**的成员。
> 一个只拿到 read 的账号**根本不会出现在那个列表里** ——
> 「列表里没有他」≠「他没进来」，得用上面那个 `permission` 端点查。
> 维护者侧看到「协作者列表只有我」就以为对方没接受，是最容易犯的误判。

**解法**：让对方**用正确账号登录后，去 `/invitations` 页面接受那条还挂着的邀请**
（read 权限不会让待接受邀请消失，所以那条一定还在）。接受后重查上面那个端点，
应变成 `permission=push`。

> 💡 也可以让维护者直接**删掉旧邀请重发一条**：
> ```powershell
> gh api -X DELETE repos/GALAXYLLIYI/computer-use-gate/invitations/<邀请id>
> gh api -X PUT repos/GALAXYLLIYI/computer-use-gate/collaborators/<用户名> -f permission=push
> ```
> 删掉重发能顺带把 7 天有效期重置。
> 如果对方说"我点了"，但维护者那边看到的还是"待接受"，
> 那就是**点在了别的账号上** —— 让他用隐身窗口重来一次。

**怎么确认自己已经进来了**（在仓库页面按 `Ctrl+` `9` 或看 Code 按钮旁边）：

- 顶部会多一条蓝色横幅：**"You must be the maintainer of ... to ..."** 反过来 ⇒
  看不到横幅就说明还在邀请状态。
- 或者直接打开 https://github.com/GALAXYLLIYI/computer-use-gate/collaborators 看自己有没有列在里面。

## 二、准备本地环境

### 2.1 硬性要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 10/11 x64** | **不是推荐，是硬要求** —— 控制链路走 UIA / 抓屏 / WinRT OCR / 键鼠注入，Linux/macOS 上这些能力根本不存在 |
| Python | **≥ 3.10**（开发基线 **3.12**） | 低于 3.10 不保证能跑；仓里实测的是 3.12.7 |
| PowerShell | **7+**（`pwsh`） | `install.ps1` / `tools\dev_env.ps1` 按 pwsh 7 语法写的，`powershell`（5.1）不行 |
| 桌面会话 | **要有交互桌面** | 一部分判据只能在你自己的桌面上跑 |

> 无头会话 / 服务 / CI 里跑不动桌面类判据 —— `tests\run_all.py` 的文件头写得很直白：
> 「**别把它当 CI 判据使**」。

### 2.2 一键准备环境

```powershell
git clone https://github.com/GALAXYLLIYI/computer-use-gate.git
cd computer-use-gate
pwsh -File tools\dev_env.ps1
```

这个脚本会：校验平台与 Python 版本 → 建 `.venv` → 装 `requirements.txt` + `pyflakes`
→ 跑**语法 / 静态 / 契约 / 提交前扫描**四道闸门 → 打印下一步。

> `requirements.txt` 里 `winrt-*` 与 `windows-capture` 是 **`vendor/` 里预编译随包分发**的轮子，
> 不走 PyPI ⇒ 离线环境要按 README 的离线安装那条走。

## 三、认证（clone / push 用）

你**不需要**做任何特殊配置就能 clone —— 仓库是公开的，匿名 clone 就行：

```powershell
git clone https://github.com/GALAXYLLIYI/computer-use-gate.git
```

**但 push 需要认证**。两条路，任选一条：

### 路线 A · SSH（推荐，一次配好长期省心）

1. 本机没有密钥就先生成（**Windows 上用 Git Bash 或 WSL**，别用 PowerShell 的 `ssh-keygen`）：

   ```bash
   ssh-keygen -t ed25519 -C "你的邮箱"
   ```

2. 把 `~/.ssh/id_ed25519.pub` 的**整行内容**贴到：
   https://github.com/settings/keys → New SSH key → Title 随便填 → Key 粘贴 → Add

3. 测一下：

   ```powershell
   ssh -T git@github.com
   ```

   看到 `Hi <你的用户名>! You've successfully authenticated` 就成了。

4. clone 用 SSH 地址：

   ```powershell
   git clone git@github.com:GALAXYLLIYI/computer-use-gate.git
   ```

### 路线 B · HTTPS + Personal Access Token

1. 造一个 token：https://github.com/settings/tokens/new
   - **Note** 填 `computer-use-gate`
   - **Expiration** 选个日期（别选永久）
   - **Scopes** 勾 **`repo`**（读写私有/公开仓必需）—— 公开仓只读的话 `public_repo` 也够
2. 复制 token（**只显示一次**）。
3. clone 时用 token 当密码：

   ```powershell
   git clone https://github.com/GALAXYLLIYI/computer-use-gate.git
   # 提示 Username: 填你的 GitHub 用户名
   # 提示 Password: 粘贴 token（不是账号密码！）
   ```

4. 或者用 Git Credential Manager 存起来（**推荐，省得每次输**）：

   ```powershell
   git config --global credential.helper manager
   ```

   第一次 push 时按提示输入用户名 + token，之后就自动了。

> ⚠ **token 等同于密码**，别提交进仓、别贴到聊天里。误贴了立刻去
> https://github.com/settings/tokens 吊销重发。

## 四、干活：分支 → 改 → 提交 → PR

### 4.1 切分支

```powershell
git checkout -b feat/<简述>      # 或 fix/<简述> / docs/<简述>
```

**不要直接改 `main`** —— `main` 有保护规则，直推会被拒。

### 4.2 改完提交前必跑三条

```powershell
git add -A
python -X utf8 tools\presubmit_scan.py     # 手机号/密钥/个人绝对路径
python -X utf8 tools\check_contract.py      # 契约
python -X utf8 tools\lint_gate.py           # 静态
```

> ★ `presubmit_scan.py` 扫的是 **git 索引**，所以**必须先 `git add -A`**。
> 没暂存它就「什么都没扫」却照样报 CLEAN —— 那是个假绿灯。

> ★ 改产品行为的话，还要跑对应的判据，**正跑和 `--inject` 都要跑**。
> `--inject` 必须是红的 —— 那是判据「有牙」的证明。

### 4.3 提交

```powershell
git commit -m "M19P2 同族两处：'没测出来'不再被报成'确认没变' —— 附判据四跑法 0/1/0/0"
```

提交信息用中文，格式是 `<里程碑或主题>：<一句话说清改了什么>`，
**带上判据结果**（像「判据四跑法 0/1/0/0」这种），让人一眼看出红绿。

### 4.4 推分支 + 开 PR

```powershell
git push -u origin feat/<简述>
```

推完 GitHub 会提示开 PR，点它或手动开：
https://github.com/GALAXYLLIYI/computer-use-gate/compare/main...feat/你的分支

## 五、PR 会被什么卡住（`main` 的三道闸）

`main` 上挂了 ruleset `main-contribution-gate`，PR 必须全部满足才能合：

| # | 闸门 | 说明 |
|---|---|---|
| 1 | **必须走 PR** | 直推 `main` 会被拒 |
| 2 | **1 个批准** | 需要**别人**批准 —— 自己的 PR 别人批，**不能自批自合** |
| 3 | **CI 闸门绿** | `闸门（无桌面依赖）` 必须过 |

外加：**禁 force push、禁删分支、对话必须全部解决**才能合。
合并方式限 `merge` 与 `squash`（**没有 rebase**）。

> 💡 CI 里还有一条 `观察位（已知红 · 不阻塞）` —— 它**故意是红的**且**不阻塞合并**。
> 看到它失败**不是你的问题**，别去修它。

### PR 里要写什么

仓库有 PR 模板（会自动填好结构），关键是填满这几项：

- [ ] `python -X utf8 tools\验收_发版.py` 的**退出码**（0=全绿 / 1=红 / 2=有验不了）
- [ ] 受影响判据的**正跑**与 **`--inject`** 两种结果
- [ ] 复现步骤（别人怎么在你这台机器上复现你的结论）
- [ ] 实测数字（涉及性能/时序的改动：多少轮、什么背景负载、p50 还是 p95）
- [ ] 改了什么、为什么（**尤其是推翻既有结论的改动**）

> ⚠ **「看起来对」不算证据，退出码才算。**
> 如果你的改动让某条判据红了 —— 要么修产品，要么改判据并说明理由；
> **不接受「把断言删弱」**（`tests\_元判据_断言弱化.py` 专门盯这个）。

## 六、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **点了 Accept 但权限没加上** | **登录了别的账号** | 见 §1.1 —— 用隐身窗口 + 确认账号是 `1750468716qqcom-maker` |
| 找不到仓库 / 403 | **邀请还没接受** | 回 §一 点 Accept |
| 提示没有权限 | 同上 | 接受后需要**重新登录**或换用 SSH |
| push 要密码但账号密码不管用 | GitHub 已停用账号密码认证 | 用 **token** 当密码（见 §三 路线 B） |
| `main` 推不动 | 保护规则生效（**预期行为**） | 切分支提 PR |
| PR 卡在「需要批准」 | 不能自批自合 | 找维护者或另一位协作者批 |
| CI 里 `观察位` 那条红了 | **已知红，故意不阻塞** | 不用管 |
| `pip install -r requirements.txt` 装不上 winrt-* | 这些轮子不在 PyPI，在 `vendor/` 里 | 走 README 的离线安装那条 |
| 判据在别人机器上红了、你这儿绿 | 判据把仓根写死了 | `tests\_M_可移植性判据.py` 守的就是这条 |
