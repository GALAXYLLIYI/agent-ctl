# 纠错 · 「OCR 不给 bbox」是**错的**（主控实测，2026-10-22 11:02）

> 触发：主控在做「视觉优化」方向盘点时，回头核对 M2 探针回执里的一句断言。
> 原断言（2026-10-21，M2 输入归因层探针回执，**只在对话里，未落盘**）：
> 「缺什么：……**OCR 不给 bbox**；跨模态接地（文字⇢坐标）——正是 M1 在做的事；OCR 只有中文。」
> ⇒ **这条前提是错的，且它一直在误导决策。**

## 一、实测证据（本机，2026-10-22 11:22，主控亲跑）

### 1.1 我们的代码**早就在取** bbox

`src/agentctl/ocr.py:198-201`：

```python
for wd in line.words:
    rect = wd.bounding_rect
    words.append({"t": str(wd.text), "x": int(rect.x), "y": int(rect.y),
                  "w": int(rect.width), "h": int(rect.height)})
```

`ocr.py` 的 docstring 明写：
> ★ `words[].x/y/w/h` = **客户区相对、客户区物理像素**；`dpi_scale` 就是换算用的因子。

### 1.2 真跑一遍（自开的记事本，hwnd=1185450）


⇒ **Windows.Media.Ocr 逐词给 bounding rect**，坐标口径 = **客户区物理像素**（`dpi_scale=1.5`）。
⇒ **「文字 ⇢ 坐标」的接地能力，本机早就有**，不需要任何视觉模型。

### 1.3 契约里本来就写着

`contract/tools.json` 的 `ctl_screen` 返回结构已明列：
`ocr{…, words[{t,x,y,w,h,conf}], …}` ⇒ **对外已经暴露**。

## 二、真正的缺口是什么（把错误前提换成正确前提）

| 原来说法 | **实际情况** |
|---|---|
| 「OCR 不给 bbox」 | ❌ **给**，逐词给，客户区物理像素 |
| 「缺跨模态接地（文字⇢坐标）」 | ❌ **不缺**，OCR 已给；**缺的是把它变成可点的目标** |
| 「OCR 只有中文」 | ✅ **对**（本机仅 `zh-Hans-CN`），可 `OcrEngine.try_create_from_language()` 指定别的语言 |
| 「非 UIA/非 DOM 的自绘界面全瞎，只能靠像素」 | ✅ **对**（Canvas/游戏画面没有结构树）—— **但像素 + OCR bbox 已经能给出「文字在哪」** |

⇒ **真正的三个缺口**（按代价排序）：

1. **缺「字框 → 词/按钮」的合并**：中文被**逐字**切分（「文」「件」两个框，x=31 与 x=63 首尾相接）
   ⇒ 需要按「同行 + 间距小」把相邻字框合成词框。**纯几何，零依赖，几十行**。
2. **缺「bbox ↔ UIA/DOM 物体」的对齐**：OCR 框是客户区坐标，UIA 物体也是客户区坐标
   ⇒ 可以直接做**重叠度匹配**（IoU / 中心点距离），把「屏幕上这段文字」对到「那个控件」。
   ⇒ 这一步做完，**R3 视觉通道的置信度就能从「只有 conf_bbox」升级成「文字+位置双证据」**。
3. **缺速度**：整客户区 OCR **1120ms**（本机实测）⇒ **不能进动作同步链**。
   ⇒ 但 M6 已经把「变化区 bbox」算出来了（`实测_响应速度三件套_20221022.md:260`：
   「只对**变化区**做 OCR（把 diff 的 bbox 喂给 OCR 的 `rect=` 参数）——**本轮判据已具备 bbox，尚未接 OCR**」），
   裁剪后 OCR 实测 **42~58ms** ⇒ **只对变化区做 OCR 是可行的**。

## 三、这条纠错**改变了什么决策**

1. **UI-TARS 那一票的结论要再收紧一格。**
   当初评估 UI-TARS 时，它唯一的实质增量被写成「**感知 grounding 权重**」
   （本机只有「该不该看图」的判定，缺「截图上直接给出坐标」）。
   ⇒ 现在看：**文字⇢坐标** 这块**本机已经有**（OCR bbox），只剩「字框合并 + 与结构对齐」
   ⇒ UI-TARS 那 7B VLM 的边际价值**进一步下降**（它给的是同样的东西，只是更贵更慢更不准）。
   ⇒ **不引入**的结论**不变且更硬**。
2. **「视觉优化」的下一步不是买模型，是补三步几何。**
   ⇒ 字框合并 → bbox↔物体对齐 → 只对变化区做 OCR（裁剪 42~58ms）。
   ⇒ **全部零新依赖**，且都在本机自己的代码里。
3. **M10（纯图标）降级的理由要复核。**
   M10 的结论是「纯图标 D1 不做」，理由含「UIA 看不见 ⇒ 退回像素/模板匹配」。
   ⇒ 这条**不受影响**（OCR 只认文字，不认图标）⇒ M10 降级**维持**。
