## 一、怎么跑的

```powershell
$env:AGENTCTL_AUTHDIR = "<live 目录>\tools\_auth"          # ★ 必须**先**设（见 §二 坑①）
python -X utf8 "work\_M20_真机验收_20221023\_run_端到端矩阵.py" `
        --authdir $env:AGENTCTL_AUTHDIR --wait-minutes 22
```

- 跑批器**只读**账本的 `expires_at`（**不写、不签、不续**）；证一到位**立刻**开跑，证一过期就**只读轮询等**下一张。
- **每跑完一格立刻把汇总 JSON 落盘一次** ⇒ 进程被杀也留得住已跑完的格子。
- **两臂按格交错**（每格先「开」后「关」）⇒ 万一中途过期，每档仍是一对对齐全的。
- 靶场：**Edge**（`--app=` + 独立 `--user-data-dir`），**不是**原生 tkinter
  （产品的敏感窗终判对「属主是 python.exe」的窗口**永久硬拒** ⇒ 原生靶场根本点不动）。

### 1.1 ★ 命中确认通道：读**页面面板 `#panel` 的文字**（不是标题）

- **为什么不能读标题**：Chromium `--app=` 窗口的**自绘标题栏画在客户区里** ⇒ 改 `document.title`
  就等于改**客户区像素** ⇒ 标题是**污染源**，不能当命中判据。
- **为什么读面板**：面板文字正是**被测对象**（面板写「已响应：slow」/「已响应：never」）⇒
  读它**不碰任何像素** ⇒ 不污染判词；本机也**没有可用 OCR 引擎** ⇒ 走 CDP `Runtime.evaluate` 直读 DOM。
- 靶场页把「标题」与「`never` 档的点击送达标记」都**延后 2500ms** 写
  （测量窗口 ≤1.7s ⇒ 2.5s 必在窗口之外 ⇒ **不污染画面判差**）。
- **这一栏直接判生死**：面板若还写「初始状态：还没点过任何按钮。」⇒ **这一格作废**（点击没送达页面），
  绝不能当成「应用没变」。

## 二、本次跑之前挖出来的真机坑（都修了，否则这张表出不来）

### 坑①：**甲案关臂会读到另一本账** ⇒ 验收脚本直接「拒绝跑」

- **根因**：`prepare_env()` 在 `import agentctl.gate` **之后**才设 `AGENTCTL_AUTHDIR`；
  而甲案关臂的注入动作**先** `import agentctl`（连带 import gate）⇒ gate 在 import 时就把 AUTHDIR 钉死。
- **修法（rig 内，不碰产品码）**：跑批器在 **import 之前**设 `os.environ["AGENTCTL_AUTHDIR"]`。

### 坑②：★ **残留窗口 ⇒ 点到了别人的页面**（最容易把整批数据变成废数据的坑）

- **现象**：每一格面板都写「初始状态：还没点过任何按钮。」⇒ 看着像「点了没反应」，
  其实是**点击没打中自己的靶场**。
- **根因**：Chromium 会把**启动器 pid 转交**给真正的浏览器进程 ⇒ 验收脚本「按 pid 找窗口」常常找不到
  ⇒ 它退回「按标题找任意窗口」⇒ **认错了上一轮残留的同名窗口**（上一位子代理随中断死掉时残留的）。
- **修法（rig 内）**：
  ① 靶场页支持 `?run=<唯一 id>`，**写进标题** ⇒ 窗口唯一 ⇒ 认不错；
  ② 验收脚本找窗口时**强制带 run 标识**，并**删掉**「按标题找任意窗口」的退路；
  ③ 跑批器**每格开跑前清掉**我们自己的残留隔离 Edge（只认 profile 标记，不碰用户自己的 Edge）。

### 坑③：★ **前台锁 ⇒ 跑批器抢不到前台 ⇒ 产品 rc=5 直接拒绝**

- **现象**：部分格子 `code=5`（坐标/快照/前台三类共用），判词「坐标/前台/窗口稳定性拒绝」。
- **根因**：Windows 的**前台锁**：不是当前前台进程、又没收到最近一次输入的进程，
  `SetForegroundWindow` **会被系统忽略** ⇒ 跑批器是**后台独立进程**（`Start-Process` 起的，没焦点）
  ⇒ 产品 act 的「动作前自动置前」也跟着失败 ⇒ **动作被拒、零像素发出**。
- **修法（rig 内）**：验收脚本用 **AttachThreadInput** 把本线程临时挂到前台线程上再置前
  （**测试脚手架**自己的手段，**不改产品代码**；产品 act 仍是温和置前）。
- **诚实记录副作用**：置前会把用户当时在用的窗口（本轮是用户的**授权弹窗**）压到后面一小会儿。

### 坑④：`reset` 定位色块的包围盒被噪声撑大 ⇒ 复位点击打在空白处

- **现象**：抓帧里 `reset`（橙 `#FFA500`）的包围盒是 `[24,78,862,671]`（面积 496934）
  ⇒ 中心算成 `(443,374)` ⇒ 屏幕坐标 `(531,454)`（**在按钮列与面板之间的空白处**）⇒ 复位点不到。
- **处置**：矩阵**每格一个全新窗口** ⇒ 基线天然干净 ⇒ 用 `--no-reset` **不点复位**，
  **每格省 1 次 act 额度**（额度只有 60 次）。落点算法**未改**（按要求）。

### 坑⑤：★ **「延迟带在哪一格」不能靠推理** —— 900/1000/1200 实测都**没被救回**

- 派单给的假设是「甲案专属窗口 ≈ 1100~1400ms」。**实测否掉了它**：
  900ms / 1000ms / 1200ms 三档，**应用确实变了**（面板写「已响应：slow」）
  **但产品都判 code=8** ⇒ 甲案**没救回**这三档。
- ⇒ 甲案的专属窗口在 **900ms 以下** ⇒ 关键档改扫 **800 / 700 / 600 / 500 / 400**。
- 靶场页这轮还加了**毫秒时间戳**（面板写「已响应：slow ｜ 第 1 次 ｜ 17:35:41.123」）
  ⇒ 和产品回执里的点击时刻（`t_wall`，毫秒）相减 ⇒ **实测**「名义 ms → 实际响应时刻」的偏移 δ。
- ★ **实测 δ ≈ +600ms 且有抖动** ⇒ Chromium 对窗口定时器有 ~1s 粒度的钳位
  ⇒ **延迟带必须实测，不能推理**（派单给的 1100~1400 被实测否掉）。
- ⚠ **第一轮（900/1000ms）作废重测**：那两轮跑的时候，**用户的授权弹窗还在屏上**
  ⇒ 它抢前台 ⇒ 页面定时器被节流 ⇒ 应用实际响应比名义晚 ~500ms ⇒ 带口被污染
  ⇒ 弹窗撤掉后**重测**（见 §三 的 900/1000 两行）。

## 四、拿到什么 / 没拿到什么（逐条，不编）

### ✅ 拿到（有数、有原始回执）

1. **端到端矩阵：28 格**（每格都带「面板命中确认」，可逐格核验点击是否送达）。
2. **「真没变不被救成成功」：拿到了** —— 控制档 `never`：
   - 甲案开 code=8 / 1359.0ms（加长观测 做了=True / 306.5ms / 6轮 / 结果=False）｜ 甲案关 code=8 / 1087.8ms；
   - 面板确认：`已响应：never（点击已送达；画面未变）` ⇒ **点击送达了页面，是应用真没变** ⇒ code=8 是**真判词**。
3. **甲案在真机上确实多花了那一眼**：两臂耗时差见 §〇.3（在「没变」的档位上是 +250~350ms 量级，与函数级底座的 315.9ms 同量级）。
4. **「慢应用被甲案救回」的延迟档：400ms、500ms、550ms、650ms、700ms** —— 这些档位上**甲案开臂 code=0 且甲案关臂 code=8**，
   面板逐格写「已响应：slow」⇒ **应用确实变了**，⇒ 不是「没点到」造成的假象。
5. **带口结构实测出来了**：≤600ms 两臂都 code=0（act 自己的快路径，与甲案无关）；
   **500/550/650/700ms 是甲案专属窗口**；≥800ms 两臂都 code=8（观测窗外，救不回）。
6. **「应用实际响应时刻」实测偏晚 ≈ +600ms**（面板毫秒时间戳 vs 回执里的点击时刻）
   ⇒ Chromium 对窗口定时器有 ~1s 粒度的钳位 ⇒ **延迟带必须实测，不能推理**。

### ❌ 没拿到 / 验不了
