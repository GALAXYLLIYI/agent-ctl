## 六 · 关键机制事实（判断"假成功后果"的地基）

### 六·1 · rc=0 在 core 侧被怎么解释（**原文**）

`src\agentctl\core.py:2464-2465`：

```python
    if rc == 0:
        return env(ok=True, code=0, data={"rc": rc, "raw": out.strip()[:3000]})
```

契约 `docs\AGENT接口.md:157`：`| `0` | 成功 | 继续 |`
⇒ **rc=0 ⇒ 信封 ok=True、code=0 ⇒ agent 按"成功，继续"处理**，不重试。

### 六·2 · ★ 但 core 对写动作**自己有一把尺子**（假成功被**大部分**兜住）

- `core.py:3416`（普通路）/ `core.py:3479`（带 frame_id 路）：
  `r = _picture_verdict(r, _df, …)`
- `core.py:2883-2916` `_picture_verdict` 的三态：
  `changed is True` ⇒ 原样返回（成功）；`is False` ⇒ **code=8**（CODE_NO_CHANGE）；
  `None`/退化 ⇒ **code=5**（CODE_UNSTABLE）。
- `core.py:3260-3262`：动作前帧 core **自己现拍**（"现场抓帧"）⇒ 不依赖 act 的证据。
- 走这条路的动作：`t_type`（4690）、`t_fill`（4704）、`t_scroll`（4936）、`t_keys`（4988）⇒
  **keys / scroll / type / fill 全部被 core 重新判过**。

⇒ **所以 F3/F4 的"假成功"在 agent 契约面上大部分被 core 兜住**（0 会被降级成 8/5）。
**残余的洞**：
① core 的尺子是**像素级**：按键/滚动**常常不改像素**（Ctrl+A 选中、方向键、无重绘控件）
   ⇒ core 可能判 8（保守，可接受）；反向地「画面变了」也可能是**世界自己在动**
   （act.py:3102-3105 自己就写了这条）⇒ **仍可能假成功**；
② **CLI 直调面完全裸奔**：`python -X utf8 act.py keys --hwnd N` 返回 0 就是成功，**零核验**；
③ act 自己那把尺子被丢掉 ⇒ 一旦 core 抓不到帧，act 这一路的信号**全丢**。

### 六·3 · ★★ 硬约束：act 若自己改成 rc=5/8，会**掐死 core 的尺子**

`core.py:2895-2896`（`_picture_verdict` 第一行）：

```python
    if not (r or {}).get("ok"):
        return r
```

⇒ **act 报非 0 ⇒ `ok=False` ⇒ core 的画面结论、M20 甲案的加长观测（`_act_extend_observe`）全部被跳过。**

⇒ **"把 F3/F4 直接改成 rc=5「没测出来」"这个看似显然的选项，代价是**：
core 本来能判"画面其实变了 ⇒ 成功"的场景，被 act 的像素误判掐成失败 ⇒ **把成功打成没测出来**，
agent 会反复重试 ⇒ **比假成功更糟**。这正是本仓 M12 阶段三 A 既定口径（act.py:2916-2922）：

> 「act 的 rc 只表示『输入送没送到』…… 画面结论由 **core** 判」。

## 八 · 结论一句话

**该改两条、可直接改、不用等用户**：**F5**（读不到⇒5、未授权⇒9、读到空⇒0）与 **F7**（按 `how` 分码 9/4/5/5）——

**该做零风险诚实化、不改 rc**：**F3**（日志/数据层说清"未核验"，中期把三态交 core 统一判）——

**F4** 拆两半：**UIA 路径补 `scroll_pct()` 真核验**（现成、零依赖、立刻能做），
**鼠标/后台路径**（无像素语义）**等用户拍板口径**："没核验"该说 rc=5（会被重试）还是 rc=0 + blind_spots（不重试但要人核）？

## 九 · 需要用户拍板的问题（可直接勾）

1. **【按键】** "键发出去了"算不算成功？
   - (a) 算 ⇒ act 维持 rc=0 正确（与 M12「输入送没送到」口径一致），core 的画面结论才是权威；
   - (b) 不算 ⇒ 必须有**按键专用**的核验证据（读回控件值 / 焦点态 / UIA 属性）——
     像素对按键不可靠（Ctrl+A、方向键、无重绘控件都不改像素）⇒ 这是一项新工程，不是改一个码。
2. **【滚动】** "没有像素语义"的动作，"没核验"该怎么表达？
   - (a) rc=5（CODE_UNSTABLE）⇒ agent 会重试 ⇒ 可能反复重试同一件无效的事；
   - (b) rc=0 + `blind_spots` 明写"未核验"⇒ 不重试，但 agent/用户必须自己核对。
   （现状 core 已给 scroll 挂了 (b) 型 blind_spots，core.py:4948-4951。）
3. **【要不要为可核验性引入新证据】** 例如：滚动读 `scroll_pct`（已存在、零成本）；按键读焦点/选区（要新做）。
   —— 这条决定 F3/F4 是"改个码"还是"做一项工程"。
