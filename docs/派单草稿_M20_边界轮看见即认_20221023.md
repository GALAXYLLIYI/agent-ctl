## 一、为什么是这一刀（实测依据，非推断）

### 1.1 现象

`_wait_effect` 每轮 = 抓帧(24ms) + diff(12.2ms) + 间隔(50ms) = **86.2ms**（实测）。
450ms 预算 ⇒ 只够 **5.2 轮**。而 `POLL_HYSTERESIS=2` 要求**变化后再来一帧**才能确认。

### 1.2 ★ 直接证据（主控 n=6/格 ＋ MiniMax n=20/格，两把尺子一致）

预算 450ms：

| 起变轮次 | 检出率 | **看见过变化** | **连看都没看见** |
|---|---|---|---|
| 4 | 100% | 6/6 | 0/6 |
| **5** | **100%**（MiniMax 测到 70%） | 6/6 | 0/6 |
| **6** | **0%** | **6/6（MiniMax 17/20）** | 0/6（MiniMax 3/20） |
| 7+ | 0% | 0/6 | 6/6 |

⇒ ★★ **第 6 轮的失败 ＝「看见了变化，但只有 1 帧证据，need=2 凑不够」** —— 不是「没看见」。

### 1.3 ★ 改这一刀能拿回多少（主控实测的四种组合账）

| 方案 | 可靠检出到第几轮 | **有效覆盖时间** | 边界轮救回？ | 代价 |
|---|---|---|---|---|
| **现状**（间隔 50ms） | 第 5 轮 | 5×86.2 = **431ms** | — | — |
| **B 单独**（间隔 35ms） | 第 6 轮 | 6×71.2 = **427ms** | ❌ 否 | 抓帧↑40%、CPU↑ |
| **★ 本单（M20 单独）** | **第 6 轮** | **6×86.2 = 517ms（+86ms / +20%）** | ✅ **是** | **零时间成本** |
| M20 ＋ B | 第 7 轮 | 7×71.2 = 498ms | ✅ 是 | 抓帧↑ CPU↑ |

⇒ ★ **本单是四者里唯一「零代价大幅提升」的**：431ms → 517ms，只改判定、不改等待、不多抓一帧。

## 二、改什么（**只有一处判定**）

**落点**：`legacy_tools\_src\act.py:1377-1381`（`_wait_effect` 的预算耗尽分支）

```
if _t.perf_counter() >= deadline:
    return {"生效": False, "轮次": rounds,
            "耗时ms": ..., "图": last,
            "退化": _is_degraded(last), "首变图": first_img,
            "口径": _frame_scope(last or base_img)}
```

**改法**（**只改这一处，不动别的**）：

```
if _t.perf_counter() >= deadline:
    # ★ 本刀：预算耗尽时，若这一轮**已经看到过变化**（streak≥1 ⇒ first_img 非空），
    #   不再判「确认没变」，而是判 True（变化确实发生了，只是没攒够 need=2 来确认）。
    _saw = (streak >= 1) or (first_img is not None)
    return {"生效": True if _saw else False, ...}
```

⚠ **注意两个前置**：

1. `streak` 与 `first_img` 都在本函数作用域内（`act.py:1345-1348` 定义、`1368-1369` 写入）⇒ **不需要新变量**。
2. `first_img` 在 `streak>=1` 时写入 ⇒ 它是「看见过变化」的可靠信号（MiniMax 已用它做过判别）。

## 三、★ 这一刀的**真实代价与取舍**（必须诚实写进报告）

### 3.1 它削弱了 `need=2` 的抗假阳性保护

`need=2`（连续 2 帧都判变）存在的原因是：**压假阳性** —— 防止「刚变又变回去」的闪烁/加载态/光标闪烁被误判成功。

⇒ ★ **本刀在「预算耗尽的那一轮」放宽了这个保护**：只要看见**一帧**变化就算生效。

⇒ ★★ **所以本刀必须配一条判据**：

> **「闪烁」场景（画面变一帧又变回去）仍然必须判「没变」/「没测出来」，不许判成功。**

⇒ ⚠ **这条能保住吗？** 主控的分析：`act.py:1364-1371` 的逻辑是
「本轮 changed ⇒ streak+1；否则 streak=0」⇒ 闪烁（第 k 轮变、第 k+1 轮变回）⇒
**第 k+1 轮 streak 被清零** ⇒ 若预算恰好在第 k+1 轮耗尽，**`streak` 已经是 0** ⇒ **判 False** ✅
⇒ ⇒ **闪烁保护在预算耗尽分支里仍然成立**（因为 streak 每轮都可能被清零）。
⇒ ★ 但**这必须由判据实测证明**，不能只靠推理 —— 这是本单判据的核心用例。

### 3.2 它会让「本该报 code=8」的场景报 code=0

若最后一轮的变化是**噪声**（如压缩视频的解码抖动、屏幕刷新、动画残影），本刀会判成功。

⇒ ★ **这正是 `need=2` 要防的东西** ⇒ ⇒ **本刀应当与 M19（语义修复）配套**：
M19 让「没测出来」变可重试；M20 让「边界轮看见即认」。两者叠加后的风险敞口需要实测。

### 3.3 不受影响的部分（明确边界）

| 分支 | 改前 | 改后 | 说明 |
|---|---|---|---|
| **预算耗尽且 streak≥1** | False | **True** | ★ 本刀唯一改动点 |
| 预算耗尽且 streak=0 | False | False | **不动**（含闪烁情形，见 §3.1） |
| 连续 N 帧判变 | True | True | 不动（`act.py:1372-1376`） |
| 图取不到 / 退化 | None | None | 不动（`act.py:1343/1360`） |
| 轮询到底也没变 | False | False | 不动（`act.py:1377` 之前的分支） |

## 五、验收口径（写死，不许事后放宽）

- **有效覆盖时间**：可靠检出到第几轮 × 单轮成本（86.2ms）⇒ **目标 431ms → 517ms（+86ms / +20%）**。
- **不得扩大边界**：第 7 轮及以后**仍然检不到**（不许顺手把「连看都没看见」也算成功）。
- **闪烁不许判成功**（用例 5）。
- 行尾全 LF；改前备份 + MD5 + 字节级 diff 落 `work\_M20_边界轮_20221023\`。
- **靶场用完即关**（按名字杀）；回执带「靶场记事本残留：跑前 X → 跑后 Y」；**桌面零产物**。
- 三处 act.py 全等（用 `tools\gen_legacy.py` 同步，收尾核对 MD5）。

## 六、★ 为什么这一刀排在「砍预算」前面（给用户看的一句话）

> **砍预算不会让边界轮少浪费一轮**（它砍的是已经被「差一轮」吃掉的那部分），
> **只会让边界更早到来** ⇒ 慢应用被误判的比例只升不降。
> **而本刀零代价把可靠覆盖从 431ms 推到 517ms** ⇒ **先把能白拿的拿完，再谈要不要加预算。**
