## 三、我独立复核的项

### 3.1 行为断言（我逐条复跑）

| 检查 | 期望 | 对应铁律 |
|---|---|---|
| 界面**已稳定** | **不得等满固定 sleep**（断言耗时上限） | 提速目标 |
| 界面**未稳定**（注入持续动画源） | **不得提前发动作** | TOCTOU（arXiv:2604.18860：观测→动作间隙 6.51s） |
| 光标闪烁 | **不得判变** | caret <8px 窄边滤除 |
| 真变化 | **必须判变** | 不漏 |
| 轮询超时 | 返回**三值 None**（「没测出来」），**且不得当成功** | 铁律 11⑨：unknown 永不当成功 |
| 动画区 | 判「没测出来」而非「没变」 | 同上（与 M6 判据 A6 同口径） |

### 3.2 数字（我自己重测，不抄它的）

| 指标 | 怎么测 | 底线 |
|---|---|---|
| 单动作总耗时 | 同一目标、同一动作，**≥5 次取中位数** | 改前基线 **1,050–1,111 ms**（M6 实测） |
| settle 扫描曲线 | 自己扫 `AGENTCTL_SETTLE_MS` | 曲线要**1:1 线性**（它已测到 580ms@0 → 1929ms@450） |
| 误判率 | 「点了没反应」/「重复点」的次数 | 必须比 settle=450 **不更差**；若更差 ⇒ 提速不成立 |

### 3.3 与 M6 的接口

| 检查 | 期望 |
|---|---|
| 阈值常量**单源化** | core.py 侧（`framecache.py`）与 act.py 侧用**同一份常量**，不许两套阈值 |
| 落盘策略 | 轮询期不落盘；只在最终判变后落 1 张（与 M6 一致） |
| 两者不打架 | 不许出现「core.py 说没变、act.py 说变了」 |
