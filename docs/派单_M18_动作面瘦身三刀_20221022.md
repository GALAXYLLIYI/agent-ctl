## 二、刀1（ZCode）· core 侧 eid 复核：从「全树 walk」改「按 eid 精确定位」

| 项 | 内容 |
|---|---|
| 落点 | `core.py:3598` `nodes, trunc = uia_tree.walk(hwnd, roles=roles, ...)`（带 eid 的动作，**注入前扫全树**） |
| 依据 | B 实测：`uia_tree.tree()` **129.9ms**（纯遍历 64.2 + 属性/模式读 ~66）；`FindFirst(TrueCond)` **3.04ms**；`FindAll` 36.7ms；`ElementFromHandle` 1.09ms；**`FindAllBuildCache` 91.3ms ＝负优化**（比 FindAll 慢 2.5×）⇒ **第一刀不是 CacheRequest** |
| 改法方向 | `ElementFromHandle` + 按 eid/控件特征精确定位，替代全树 walk；**结论语义不许变弱** |
| 预计省 | ~100~125ms（带 eid 的动作） |
| ★ 判词风险 | 全树 walk 能顺带发现「同名多元素」；精确定位可能漏 ⇒ 判据必须覆盖：**同名多元素**、**元素已消失**、**元素已换代（窗口代际闸 code=12）** 三种情形；**⛔ 不许把「查不到」写成「没变」** |
| 判据 | 先红后绿：新写 `tests\_P3_M18_eid复核_判据.py`（至少覆盖上面三种情形 + 一条「省了多少」）；**判词三档（变了/没变/未知）必须与改前逐例一致** |
