## 2. 本单要做的四件事

### A. ★ 判定权补齐（**核心**）

- **普通 `ctl_click` 的 `code` 必须由 core 给出**，不许由 act 的 rc 给出。
  ⇒ 形状（采纳 窗口B 的建议，也是 M12 原裁决的本意）：
  - **act 的 rc 只表示「输入送没送到」**（成功注入 / 注入失败 / 被前置拒绝），
    **不再承载「画面变了没」**；
  - 画面结论由 **core** 用**自己的尺子**给出（`framecache.diff_images`），
    三态：变了 ⇒ `code=0`；**确认没变** ⇒ `code=8`；**没测出来/退化** ⇒ `code=5`。
- ★ **不许**为了让普通 click 走 core 判定，就去放宽任何口径；
  「没测出来」与「没变」必须**分开**（这是铁律：unknown 永不当成功，也不当「没变」）。
- ⚠ **回归风险**：`ctl_click` 的 `retry` 逻辑在 act 侧用了 `changed`（`act.py:2771`）
  ⇒ 你要保证**重试判定**仍然拿得到「变了没」这个信息（窗口B 建议：保留在 act 内部用，
  但**不进退出码**）。自己权衡，**写进文档**。

### B. ★ 基线时机（**必须先于注入**）

- core 把 **baseline 下发给 act**：**帧路径 + `(w,h)` + `origin` + `dpi_scale` + 判据版本号**；
- act 只做「**对着这个 baseline 采样**」，回传**首变帧 + 每轮时刻 + 轮次**；
- **不许**再用「注入后现抓一帧」当基线（那会把首变吞掉）。
- ★ **帧口径必须随帧回传**；core 侧若发现口径不一致 ⇒ **回落 `wait_change`（fail-closed）**，
  **不许**「现取 origin」补救（窗口会动）。

### C. 删重复（**窗口B 的第一刀**，按性价比）

一次点击现在**拍 5~7 张整窗、写 6~7 张 PNG**。本单至少做到：

1. `act.py:2599` 无条件拍的 `before` 与 `2622` 又拍的 `before` —— **只拍一次**；
2. act 的 `after` 整窗只为了算 md5 —— **判据归 core 后就不需要了**（审计图留一张即可）；
3. `_wait_ready` 的基线（`act.py:2690` 的 `_poll_base`）—— **复用已有的 before**；
4. **交接/落盘格式**：PNG save **29.9ms/张** ⇒ 内部交接改 **raw 或 BMP**（save **1.9ms / 5.3ms**）
   ⇒ **每动作 6~7 次 ⇒ 省 ~27ms/次**；**证据图仍保留 PNG**（要能给人看）。

### D. 每轮的两笔纯税（顺手做，零风险）

- `is_blank` 每轮跑（**5.7ms/轮**）—— 退化只是**打标** ⇒ **最后一帧打一次就够**；
- `_poll_gray` 每轮跑（**6.3ms/轮**）—— 只为判「图够不够大」⇒ **用 `img.size` 就够**。
