## 5. 第二部分：`_read_tail()` 每事件全量重读 → 尾部倒读

### 5.1 根因（改前）

`append()` 在锁内调 `_read_tail()`（现 `store.py:620-622`），而改前的 `_read_tail()`：

1. `sorted(self._jsonl_files())` —— 每次 `listdir` 整个 timeline 目录；
2. 对最后一份文件**逐行读全文**；
3. **每行都 `json.loads`**；
4. 只为了拿最后一条的 `(seq, hash)`。

⇒ 写 N 条事件 = 把当天 JSONL 读 N 遍 ⇒ **O(N²)**（今天 6.02 MB，377 ms 全在这里；
sqlite 只 0.8 ms —— 原假设「sqlite 连接复用是元凶」被实测否掉）。

### 5.2 改法（`store.py:462-562`）

| 位置 | 内容 |
|---|---|
| `store.py:464` | `_TAIL_CHUNK = 64 * 1024`（首块 64 KB；找不到就翻倍，直到全文） |
| `store.py:467-486` | `_last_record_fullscan()`：**老实现的逐行全读，回退路径**（M8 正确性保证，不许删） |
| `store.py:489-539` | `_last_record_in_file()`：`getsize` → `seek(size-limit)` → 读尾块 → `split(b"\n")` → **逆序**解析；首段是半行就丢掉；预览到完整行即返回 |
| `store.py:541-562` | `_read_tail()`：按 `reversed(sorted(files))` 逐文件取最后一条；非 dict / `seq` 转不了 int ⇒ 找更早的文件；全无 ⇒ `(0, GENESIS)` |

**完整性检查与回退**（派单 §9.4 的硬约束，逐条对上）：

| 约束 | 落地 |
|---|---|
| 末尾半行必须做完整性检查 | 半行 `json.loads` 失败 ⇒ **跳过**，落到上一条完整记录；绝不把半行当完整行 |
| 不许只读最后一行了事 | 逆序逐行解析；最后一行坏就继续往前，直到找到能解析的 |
| 回退路径必须保留 | ① 尾块没有 ⇒ 块大小翻倍直到覆盖全文；② 读完仍无 ⇒ `_last_record_fullscan()` 全量逐行；③ 半行带非法 UTF-8 ⇒ 同样走全量（与老实现一样会抛错，不静默吞掉） |
| 不许用 sqlite `max(seq)` 代替 | 全程只读 jsonl，**不碰 sqlite**（M8 修掉的 bug 不回退） |
| 锁语义不变 | 调用点仍是 `store.py:620-622`（append）、`:662-664`（append_frame）、`:982-988`（migrate），都在 `_xlock` + `_lock` 内；`_load_head()` 仍只在构造时读一次 |
| 不砍 fsync / 不改事件语义 | `_append_jsonl` 与索引写入**零改动**（见 §2） |

> 「跨多个文件回退」也保住了：若最新文件只有坏行/空行，`_read_tail()` 会继续找更早的文件
> （判据 H 的「跨 3 文件（最新文件全坏）」就是钉这个）。
