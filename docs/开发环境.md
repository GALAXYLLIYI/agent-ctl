# 开发环境（贡献者指南）

> 面向要**改这个仓**的人。想用这个工具但不想改代码的，看 [README](../README.md) 的「装之前先看三句」。
>
> 适用版本：0.1.x ｜ 最后更新：2026-10-24

---

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 10/11 x64** | 不是「推荐」，是**硬要求**：控制链路走 UIA / 抓屏 / WinRT OCR / 键鼠注入，Linux/macOS 上这些能力根本不存在 |
| Python | **≥ 3.10**（开发基线 **3.12**） | 低于 3.10 不保证能跑；仓库里实测的是 3.12.7 |
| git | 任意近期版本 | 安装脚本会用到 |
| PowerShell | **7+**（`pwsh`） | `install.ps1` / `tools\dev_env.ps1` 按 pwsh 7 的语法写 |
| 桌面会话 | **要有交互桌面** | 见下面「判据分层」——一部分判据**只能**在你自己的桌面上跑 |

> ⚠ **无头会话 / 服务 / CI 里跑不动桌面类判据。**
> `tests\run_all.py` 的文件头写得很直白：「**别把它当 CI 判据使**」。

## 二、一键准备

```powershell
# 建 .venv、装依赖、跑一遍无桌面依赖的闸门
pwsh -File tools\dev_env.ps1

# 只跑闸门，不装东西（CI 里也是这一套）
pwsh -File tools\dev_env.ps1 -GateOnly

# 用当前解释器，不建 venv
pwsh -File tools\dev_env.ps1 -NoVenv
```

脚本做的事：校验平台与 Python 版本 → 建 `.venv` → 装 `requirements.txt` + `pyflakes`
→ 跑**语法 / 静态 / 契约 / 提交前扫描**四道闸门 → 打印下一步。

> `requirements.txt` 里 `winrt-*` 与 `windows-capture` 是 **vendor/ 里预编译随包分发**的轮子，
> 不走 PyPI ⇒ 离线环境要按 README 的离线安装那条走（`tools\pack_dist.py` 打 zip）。

## 三、判据分层

这是这份文档里**最该先看的一节**。判据不是一坨，分两层：

### A 层 · 无桌面依赖（CI 能跑）

| 闸门 | 命令 | 管什么 |
|---|---|---|
| 语法 | `python -X utf8 -m compileall -q src/agentctl` | 全部模块能编译 |
| 静态 | `python -X utf8 tools/lint_gate.py` | pyflakes 结果里的**致命项**为零（存量 unused import 只提醒不拦） |
| 契约 | `python -X utf8 tools/check_contract.py` | `contract/tools.json` 可读、**全层级无重复键**、字段齐、工具名唯一 |
| 提交前扫描 | `git add -A` 后 `python -X utf8 tools/presubmit_scan.py` | 暂存区里没有手机号 / 密钥字面量 / 个人绝对路径 / 本地 agent 凭据引用 |

这四道已经进 `.github\workflows\ci.yml`（`gates` job），每次 push 与 PR 都跑。

> **契约那道为什么单独存在**：`json.load` 遇到重复键会**后者覆盖前者**、不报错。
> 契约是 agent 直接读的 API 说明，静默少一条工具比直接报错更坏。

### B 层 · 要交互桌面（只能在自己的机器上手工跑）

| 判据 | 为什么必须要桌面 |
|---|---|
| `tests\_T1_W2_判据.py` | 要真画边框窗口、真抓屏、真断言前台窗口不变 |
| `tests\_T1_窗3_自证.py` | 同上 |
| `tests\_急停弹窗判据.py` | 要真弹一个置顶窗口出来；还会起 5 个真 daemon、逐个抢一次全局热键 —— **约占 2 分钟桌面** |
| 若干判据 | 要 UIA 能枚举控件树（自绘 / Canvas / 游戏界面除外） |

跑全部：

```powershell
python -X utf8 tests\run_all.py
```

`run_all.py` 是 **fail-closed**：判据文件不见了、崩了、超时了，一律算红。
「少一条判据」绝不会被读成「全绿」。

> ⚠ 赶时间的时候别跑急停弹窗那条 —— 它要独占桌面约 2 分钟。

### C 层 · 已知红（观察位，不阻塞 CI）

2026-10-24 实测，这三条**在开发机上现在就是红的**：

| 判据 | 现状 |
|---|---|
| `legacy_tools\selftest.py` | 报「act.py 无静默动作 → 找不到『无变化就返回非 0』的判据」 |
| `tests\_M_可移植性判据.py` | 报「副本里跑不起来 `_T1_W2_判据.py` / `_T1_窗3_自证.py`」 |
| `tools\selfcheck_minrepo.py` | 报「清单条数 52 ≠ len(CRITERIA) 53」。⚠ 这个脚本**不在仓**（`.gitignore` 白名单刻意没放行它）⇒ 只能在开发机上跑，CI 跑不了 |

CI 里它们挂在 `known-red` job（`continue-on-error: true`），**故意不阻塞**：
闸门长期红着会训练所有人无视它，等修绿了再挪进 `gates`。

> `_M_可移植性判据.py` 那条尤其值得修 —— 它守的是
> 「**每条判据必须验它自己所在的那份仓**」。仓根写死在本机路径上的判据，
> 换台机器会给出一份**与入库物无关的绿灯**。闸门会撒谎，这比没有闸门更坏。

## 四、环境变量

### 4.1 公开可调（.env.example 里也列了）

| 变量 | 默认 | 作用 |
|---|---|---|
| `AGENTCTL_APP_DIR` | `%LOCALAPPDATA%\AgentCtl` | 应用根：授权状态、通行证、急停标志、边框日志都在这儿 |
| `AGENTCTL_AUTHDIR` | `<APP_DIR>\_auth` | 账本目录（闸门唯一规则见 `src/agentctl/authdir.py`） |
| `AGENTCTL_TIMELINE` | `<仓>\work\timeline` | 时间线落盘目录 |
| `AGENTCTL_BRAKE_FLAG` | `<APP_DIR>\_急停.flag` | 急停标志路径；**改了它，闸门读的也不是原来那个真源** |
| `AGENTCTL_ACTOR` | `cli` | 动作归因里的 actor 名（谁在动） |
| `AGENTCTL_SETTLE_MS` | 生产值 450 | 等生效预算（点击后等多久算生效） |
| `AGENTCTL_REQUIRE_LEASE` | —— | 是否强制「必须持租约才准动」 |
| `AGENTCTL_MCP_PORT` / `AGENTCTL_PORT` / `AGENTCTL_TEST_PORT` | 8761 等 | MCP HTTP / 本地服务 / 测试端口 |
| `AGENTCTL_NO_TRAY` | —— | 不装托盘图标（无头 / 自动化跑） |
| `AGENTCTL_BORDER` | —— | 控制期的屏幕边框总开关 |
| `AGENTCTL_MCP_DEBUG` | —— | MCP 调试日志 |
| `AGENTCTL_SHOTS_DIR` / `AGENTCTL_SNAP_DIR` / `AGENTCTL_CACHE_DIR` | —— | 截图 / 快照 / 缓存落盘位置 |
| `AGENTCTL_WORKSPACE` / `AGENTCTL_ROOT` | —— | 工作区与仓根（判据用它定位自己那份仓） |

### 4.2 排障用的内部变量

`src/agentctl/` 里还有 30+ 个 `AGENTCTL_*`（`ACT_EXT_OBSERVE_MS` / `EID_STRICT` /
`POPUP_TEST_*` / `KB_DB` / `LEGACY_HOME` …）。它们**不属于公开接口**，随时可能变，
只在排障时临时用 ⇒ 不要写进文档或脚本承诺。

改任何 `AGENTCTL_APP_DIR` / `AGENTCTL_AUTHDIR` 之前，先想清楚一件事：
**它们改的是闸门读状态的位置。** 改错地方，闸门就会去读一份「与入库物无关」的状态 ——
判据会因此变绿，但那个绿是假的。

## 五、目录速查

```
src/agentctl/        产品代码（core.py 是主战场）
contract/tools.json  契约：26 个工具的 JSON 描述（agent 直接读它）
legacy_tools/        随包分发的执行层产物（由 tools\gen_legacy.py 生成，**不要手改**）
tools/               开发/构建/校验脚本
tests/               判据（分 A/B/C 三层，见上）
docs/                文档（含实测记录，历史文档保留本机路径，公开前需脱敏）
work/                本机证据落盘（已 gitignore；**别提交**）
vendor/              预编译轮子（winrt-* 等）
```

> ★ `legacy_tools/` 是**生成物**。改逻辑要改 `src/agentctl/`，
> 然后跑 `python -X utf8 tools\gen_legacy.py` 重新生成，
> 再用 `python -X utf8 tools\check_live_sync.py` 核产物与真源一致。
> 手改生成物 ⇒ 下一个跑生成脚本的人会把它覆盖掉，且 diff 里看不出原因。

## 六、提交前

```powershell
git add -A
python -X utf8 tools\presubmit_scan.py     # 手机号/密钥/绝对路径（只用标准库 + git）
python -X utf8 tools\check_contract.py      # 契约
python -X utf8 tools\lint_gate.py           # 静态
```

三条全绿再提交。PR 模板（`.github/PULL_REQUEST_TEMPLATE.md`）要求写清
**判据退出码 + 复现步骤** —— 这不是形式：闸门的价值全在退出码上。

> ★ `tools\presubmit_scan.py` 扫的是 **git 索引**，所以必须先 `git add -A`。
> 没暂存它就「什么都没扫」却照样报 CLEAN —— 那是个假绿灯。
>
> ★ `tools\scan_repo.py` 在本机还有一份，但它**刻意不在仓**（`.gitignore` 白名单的核对结论：
> 与 presubmit_scan 是「什么算泄露」的两份真源）。**别在脚本里引用它**，干净克隆上会崩。
> 泄露扫描由 `presubmit_scan` 独家负责。

## 七、常见坑

| 现象 | 多半是 |
|---|---|
| 判据在别人机器上红了、你这儿绿 | 判据把仓根写死了 —— `tests\_M_可移植性判据.py` 守的就是这条 |
| 面板显示「未启用」 | 通行证过期/没签发。**装完默认关闭是设计**，不是 bug |
| 急停按了没反应 | 热键被别的程序占了（面板表头会显示「热键被占」）。关面板 ≠ 解除急停 |
| `pip install -r requirements.txt` 装不上 winrt-* | 这些轮子不在 PyPI，在 `vendor/` 里 ⇒ 走离线安装那条 |
| CI 红了但本地绿的 | 多半是 A 层闸门（CI 跑的就是 A 层）；B 层判据 CI 根本不跑 |
| 急停弹窗判据跑了 2 分钟 | 正常：它要起 5 个真 daemon、逐个抢全局热键 |
