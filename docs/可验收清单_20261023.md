① 窗口 c 的 act.py 改动尚未重新生成产物（⇒ 三处 act.py 现在**不等**，D1/D2/D3 因此红）

**能不能自己装、自己用？** 能。装完**默认什么都不通**——这是设计，不是坏了（§二·2）。

**怎么验？** 一行命令（§三）：

```powershell

```

**它给什么？** 一张 12 行的总表（项 / 期望 / 实测 / 判定）＋ 一句话结论 ＋ 一个退出码：

| 退出码 | 含义 | 能不能当"过了" |
|---|---|---|
| **0** | 全绿 | ✅ 可以 |
| **1** | 有红项 | ❌ 不行，去看红的那几行 |
| **2** | 无红项，但有**验不了 / 待通知**项 | ❌ **不是绿**（"没结论"≠"结论为绿"） |

> ⚠ **为什么要刻意分三档**：出包前必然落在 2（`verify_dist` 没包可验、`pack_dist` 等通知）。
> 如果把"没跑"折进 0，那这张表就只是在说"我没查出来"却让你以为"我查过了且没问题"——
> 这正是本项目 M19′ 踩过的坑（**空刀**：改的东西没人读，行为等于没变）。
> 所以验收器的铁律是：**红不解释成绿，没跑不算绿。**

**当前这一跑的真实结果（2026-10-23 15:08 实测）**：**绿 7 / 红 2 / 验不了 3，退出码 1**。
两条红的根因见 §三·3——**都是窗口 c 正在改 act.py 真源、还没重新生成产物**造成的**在途态**，

## 二、装完是什么样：**默认关闭**（这是设计，不是没装好）

### 2.1 默认状态下会发生什么

- **默认无通行证 ⇒ 一切写动作一律被拒**。装完、开机、重启之后都是这样，**装完不会替你签任何证**。
- 急停 flag 一票否决，压过一切授权。
- 想要授权：调 `ctl_authorize`（或跑 `python -X utf8 tools\申请授权.py`）→ **屏幕上弹窗，由人点「允许」** →
  现场签发密钥（默认 **30 分钟 / 60 次**）。**弹窗不可被 agent 代点**；密钥明文不落盘、不回显（只存加盐 SHA-256）。
- 自验：`python -X utf8 tests\_默认关闭_判据.py`（默认全拒 → 显式放行后才通 → 急停压过一切）。

### 2.2 三道急停（任选其一，**关面板 ≠ 解除急停**）

| 通道 | 怎么用 |
|---|---|
| 面板 ⏹ | 面板上的急停按钮 |
| 全局热键 | `Ctrl+Alt+Home` |
| 删急停标志 | 直接删急停标志文件 |

急停一拉下，**所有自动控制当场停**，并联动吊销当前租约。

### 2.3 每个动作要过的五道闸（顺序固定）

```
人类签发（弹窗一次给 ABCD，30 分钟/60 次） → 租约（任务→窗口，只追加不覆盖，子随父亡）
→ 帧凭据（旧帧点新画面 = 拒绝） → 敏感窗服务端终判（--xy 直点也拦）
→ 急停一票否决（文件级，拉下即全灭） ⇒ 证据链（前后差分 / hit_test 归属 / 决策日志）
```

### 3.2 每项**验的是哪件事**（人话版，不只是文件名）

| 项 | 人话：这一项过了，说明…… |
|---|---|
| **m19** | AI 点完之后，"**它到底变了没有**"这件事不再被含糊掉。"没测出来"（环境不稳、读不到）不再被谎报成"确认没变"——前者会**重试**，后者会**停下**，混了就会静默卡住流程。 |
| **m19p2** | 上一条在**另外两个入口**（打字读回、拖拽选区）也成立，且真源 / 产物 / live **三份 act.py 是一份**（不一致直接报红）。 |
| **m20core** | AI 点了之后画面没动，**平台不会立刻判死刑**：它会用自己的尺子**再看 300ms**。慢应用（点了 0.3 秒才响应）因此能被救回来；同时"真的没变"仍然照实报、闪烁仍然不会被误判成功。 |
| **m20act** | **演练就是演练**：`--dry-run` 不会真的把字打进你的窗口、不会挪你的鼠标、不会发滚轮、不会偷抓屏。非演练路径的行为一个字都没被改坏。 |
| **m19s** | 本机**真在跑的那份**程序与仓内产物**逐字节一致**——没人偷偷改过线上那份（这条是防"改了仓、忘了上线"）。 |
| **m19ps2** | 通行证（授权账本）存在**一个确定的地方**，签发方和新老两套闸门都指向它；平台**读不到东西时拒绝写回**，不会拿半截数据覆盖你的授权。 |
| **zhukong** | 一份**独立的人写的复核**（不采信施工者自检）确认：改动只动该动的、没碰预算常量、没混进 CRLF、"生效"出口清单对得上。 |
| **lint** | 产品代码里没有"**跑到那一行才崩**"的错误（未定义的名字、写错的语法）。 |
| **livesync** | 线上那份与仓内产物**逐字节一致**（"发版前最后一道闸"）。 |
| **verifydist** | **第二个裁判**独立把 zip 解开重算一遍：里面没有敏感文件、没有本机运行数据、该有的件都在（不采信打包脚本自己的说法）。 |
| **presubmit** | **已经进暂存区**的内容里没有手机号、密钥、密码、个人绝对路径（要提交给公开仓的东西，扫的是索引不是工作区）。 |
| **packdist** | 真的打得出一个可发布的 zip。 |

### 3.3 当前两条红的**根因**（在途态，不是已定型的缺陷）

| 红项 | 根因 | 谁解 |
|---|---|---|
| **m20act** | act.py **三处已经不等**了：真源 `0B3842ED…`（210516 B，在途改动）≠ 产物/live `8D2075A3…`（207104 B）。判据的 6 个失败**全落在真源那一份**上，产物与 live 两份 100% 全绿。 | 主控统一重生成产物 + 刷新 live |
| **zhukong** | 同一根因的下游：`真源 == 产物` / `真源 == live` 两组 FAIL，加上新改动的代码行还没进复核账本白名单（78 行 vs 账本 55 行）。**⑦ 判据四种跑法这一组是全 PASS 的**。 | 同上（账本补段由窗口 b 派） |

> ⚠ **顺带一提**：`livesync` 这一项在 15:08 那一跑是**绿的**（live 与产物一致），但真源与产物已经不等了
> ⇒ **live 一致 ≠ 三处一致**，D1 要的是**三处全等**（真源/产物/live）。所以主控那一步必须是
> "**改真源 → 重新生成产物 → 刷 live**"三步一起做，只做一步会把 D1 从红变绿再变红。

## 四、产品边界与已知限制（**未核到的必须写"未核到"**）

### 4.1 等生效：有效预算比名义预算少一整轮

- 生产点击路径的等生效预算 = **450ms**（`act.py` 的 `do_click` 三处传 `budget_ms=int(_settle(450)*1000)`，`AGENTCTL_SETTLE_MS` 可调）。
  ⛔ `act.py` 里的 `POLL_BUDGET_MS = 800` **只是函数默认值、不是生产值**——拿 800 去定性能曲线会系统性偏一倍。
- 实测：名义 450ms **只覆盖约 431ms** 的响应延迟。差的那一整轮不是应用慢，而是 `need=2` 迟滞要求"多一帧确认"，
  在预算边界上把"看见了但来不及确认"判成了"没变"。
- 实测检测率（预算 450ms）：响应 **0ms / 100ms / 200ms 检出率 100%**，**300ms 及以上整段掉到 0%**
  ⇒ **切线在 200ms，不在 450ms**。
- 填字路径的总预算 = **1500ms**（`POLL_BUDGET_MS_FILL`），与点击不是同一个数。
- core 侧另有一层 **300ms** 的回落预算（`framecache.WAIT_BUDGET_MS`）；M20 甲案在判"确认没变"**之前**用 core 自己的尺子再看 ≤300ms。

### 4.2 慢应用：离线已证，**真机数字未核到**

- **离线（假时钟）已证**：M20 甲案 12 条断言全绿——末帧≠基线⇒零额外等待；末帧==基线且窗口内变化⇒改判成功；
  一直不变/闪烁/退化/采样失败⇒判词一个字不动；加长观测不超预算。
- ⛔ **真机（200~500ms 延迟的靶场）数字：未核到** —— 需一张**有效通行证**才能跑真机。
  ⇒ **D8 至今是"未核到"，不是"通过"。**

### 4.3 判词是三态，不是两态

| 判词 | 出口码 | 含义 |
|---|---|---|
| 生效 | `code=0` | 画面确实变了 |
| 确认没变 | `code=8` | 动作发出去了、画面没变 —— **不是成功** |
| 没测出来 | `code=5` | 没测到 / 读回失败 / 环境不稳 —— **可重试**，不许当成功 |

### 4.4 其余已知限制

- **桌面相关判据必须在有交互桌面会话的 Windows 上跑**（无头 / 服务 / CI 跑不了）；`tests\run_all.py` 文件头的原话是"**别把它当 CI 判据使**"。
- 部分窗口不支持 `PrintWindow`（部分 WinUI/DWM、DRM/游戏类画面）⇒ 取不到帧时**如实报"取不到"**，不猜。
- UIA 控件树对自绘 / Canvas / 游戏 / PDF 视图只能拿到窗口壳 ⇒ 要退到"截图 + 编号标注"路线。
- OCR 走系统自带 WinRT OCR（**不额外下模型**）；首扫有暖机成本：真页 **0.5s 只拿到 18 节点外壳，3s 稳定到 49 节点**。
- `must_vlm` 通道**未接线**——如实报"不可用原因"，不做假承诺。
- 平台：**Windows 10/11 x64**（WinRT OCR 需 Win10 1903+）；Python 3.10+。
  ⛔ **不承诺特定 Windows 版本矩阵**，也不承诺与未来版本兼容。
- **证据只落本机 `work\` 目录**（时间线 jsonl、前后帧指纹、决策日志）——⚠ 证据里**含前后屏幕截图**，属**敏感本地数据**，**不要提交到版本库**。
- **无遥测、不上传任何数据**；服务只监听 `127.0.0.1`。

### 4.5 它明确**不做**什么

- ❌ 不做通用 CUA（点得准是别人的战场）
- ❌ 不做多 agent 调度平台
- ❌ 不承诺 VLM 升级
- ❌ 不做绕过风控 / 验证码 / 权限边界的事
- ❌ 不适合无人值守批量点击、需要 SLA 的生产环境、需要稳定兼容性的集成

### 7.1 回滚

```powershell
.\uninstall.ps1                 # 卸载（**保留数据**：授权/通行证/急停状态/事件流/截图）
.\uninstall.ps1 -Purge          # 连数据一起删（授权、通行证、日志、截图全没，不可恢复）

.\uninstall.ps1 -KeepShortcut   # 保留桌面快捷方式（默认会删）
```

- 因为这个平台**没有注册表项、没有服务、不写系统目录** ⇒ 卸载就是"删掉 `%LOCALAPPDATA%\AgentCtl` + 桌面快捷方式"。

- **代码侧回滚**：`git log` 找到上一个好提交 ⇒ `git revert <sha>`（⚠ 只回滚**仓内代码**；
  **已装到本机的那份**要用 `install.ps1` 重装，别指望 git 管到 `%LOCALAPPDATA%`）。
- ⚠ **回滚后通行证要重签**：证 ≤30 分钟，且 S2 生效后三方统一到 `_auth` 目录，旧路径下的授权不再被认。
