# 派单 MiniMax Code M10：纯图标（D1）—— 从「估坐标」到「认出是哪个图标」

> 开单：Codex（2026-10-22 01:20，7 小时任务）｜接单方：MiniMax Code
> 接在 **M9 之后**。裁决依据：`docs/意见/裁决_20221022.md`（A5）、`docs/意见/意见_DSH_20221022.md`（Q3）、`docs/意见/意见_ZCode_20221022.md`（Q3）

## 0. 一句话目标（≤40 字）

> 让「只有图标、没有文字」的按钮能被认出是哪个按钮，而不是靠估坐标乱点。

## 1. 为什么这件事排在最后（三方一致）

「纯图标没文字只能估坐标」是真痛点，但**它是最不该先动的一类**：
本机已有 UIA 树（191ms/85 节点）、OCR（裁剪 42–58ms）、CDP DOM 通道，
**大部分「无字按钮」在可访问性层面是有名字的** —— 先问对问题，比先上模型便宜得多。

## 2. 三条路，按成本从低到高（**必须按顺序评估，不许跳级**）

### ① 先问可访问性（零像素、零模型）— DSH 与 ZCode 一致同意先走这条

- UIA 节点 `Name` 为空时，还有 `HelpText` / `AutomationId` / `ClassName`
- Chromium/Electron 走 `aria-label`（`src/agentctl/uia_tree.py` 已在抓节点名，先核字段覆盖度）
- ZCode 补的一条：**Chromium 系加 `--force-renderer-accessibility` 后图标按钮的 AutomationName 大多存在**
  （本机 QQ 树薄是另一码事，不因此否掉这条路）——本单可给一个最小验证。
- 交付口径：**给出一张表**：本机常见应用（计算器 / 资源管理器 / 记事本 / Edge / 微信 / QQ）
  的「视觉无字按钮」里，**可访问性有名字的比例**是多少。比例高 ⇒ 这条路就够，②③ 可降级为备选。

### ② hover 取 tooltip（B 级，一次 hover + 150–300ms）

- Windows 原生控件与 tiptap 类编辑器几乎都给 tooltip，**比渲染字体稳得多**。
- 与本机三闸的关系：hover 是 B 级动作（不改变系统状态），但**会移动鼠标** ⇒ 归因层要能区分（这是 M9 的用武之地）。

### ③ 模板匹配（零模型、零 GPU，但成本最高，放最后）

- ZCode：**系统图标资源库同管线** —— `imageres.dll` / `shell32.dll` / 应用自身资源的图标渲染成 bitmap 集，
  把「Segoe 码点集」扩成「通用图标集」，**边际成本近零**。
- DSH：**自监督** —— 成功点中一次后裁下图标存 NCC 模板，**不用码点、天然匹配真机渲染（含 150% DPI）**，越用越准。
- ZCode 备选：**ORB/AKAZE 特征匹配**（OpenCV，无模型）比 NCC 抗缩放旋转；**焦点遍历**（Tab + 读焦点元素 rect）算第四条。
- ⚠️ **DSH 的一条硬要求（原 M6 派单漏了）**：若走**字体渲染**（Segoe Fluent Icons / Segoe MDL2 Assets 码点），
  **必须按目标窗口 DPI 渲染并关 ClearType**，否则本机 150% 缩放下 NCC 必掉分。

## 5. 边界

- **不许引新依赖**：OpenCV 若本机没有 ⇒ 不许装（ZCode 的 ORB/AKAZE 方案需先核 `cv2` 在不在；
  M6 侦察已发现 **cv2 缺失** ⇒ 该路线本单默认不走，除非有 vendored 方案）。
- 不许动 `contract/tools.json`。
- 改了真源 ⇒ 备份 + MD5 → 判据先红后绿 → 字节级 diff 落盘。
- 不许起常驻进程；不许读含密钥文件。
- **不许把「认出图标」当成「可以跳过授权」**：认得出 ≠ 许点，闸门照旧（三闸铁律）。
