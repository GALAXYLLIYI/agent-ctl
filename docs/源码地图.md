# 源码地图（agent-ctl · 2026-10-24）

> 给要读源码的人：**先看哪里、每个文件管什么、改一个需求该动哪**。
> 数字由脚本从仓内实读（`src/agentctl` 30 个模块，共 ~21,500 行）。

---

## 一、一句话结构

```
工具面（26 个 ctl_*）──┐
  MCP stdio  mcp.py     │
  MCP HTTP   mcp_http.py├─→ core.py（唯一调度核心：三态同源的"同源"）
  CLI        cli.py     │        ├─ 安全内核 gate.py / authstate.py / authdir.py / action_guard.py
  面板       widget.py  │        ├─ 感知与动作 uia_tree.py / eye.py / ocr.py / framecache.py / digest.py
  本地HTTP   server.py  ┘        ├─ 记录 store.py / recorder.py / tasks*.py
                                 └─ 业务通道 quiz.py / clip.py / iconfont.py …
```

**唯一的"同源"点**：`core.py`。MCP/CLI/面板三面都调它，所以判据只要盯住它，就同时盯住了三个入口。

## 二、模块清单（按职责分）

### 1. 入口 / 传输层（薄壳，只做协议）

| 文件 | 行数 | 干什么 |
|---|---|---|
| `mcp.py` | 157 | MCP stdio（JSON-RPC over stdin/stdout）—— 窗口D/本地 agent 拉起的就是它 |
| `mcp_http.py` | 319 | MCP **Streamable HTTP** `POST /mcp`（8761 端口，靠 `AGENTCTL_MCP_TOKEN` 鉴权） |

| `widget.py` | 1001 | 悬浮面板（只读挂件 + 急停/授权入口；**关面板 ≠ 解急停**） |

### 2. 调度核心（最大、最该先读的一份）

| 文件 | 行数 | 干什么 |
|---|---|---|
| **`core.py`** | **7687** | **唯一调度核心**：26 个 `ctl_*` 的实现、三态判词（成功/没测出来/确认没变）、动作前绑证据、加长观测 |

阅读建议（不要从头读）：先 `grep -n "^def dispatch" core.py` 看动作出口 → 再读 `t_click / t_type / t_find / t_shot` 各 20~40 行 → 最后读 `_act_extend_observe`（慢应用救回 900ms 就在这）。

## 三、"我要改 X"→ 该看哪

| 需求 | 去这里 |
|---|---|
| 新增/改一个工具（`ctl_*`） | `core.py` 里对应 `t_xxx()` + 工具契约 `contract/tools.json` |
| 改判词/错误码语义 | `core.py` 的 `env()/verdict_canonical` + `gate.py` 的 `CODE_*` 码表 |
| 改慢应用"等多久" | `core.py: ACT_EXT_OBSERVE_MS`（默认 900，可用 `AGENTCTL_ACT_EXT_OBSERVE_MS` 覆盖） |
| 改急停阈值/误触发 | `action_guard.py` + `action_guard_policy.json`（`fail_counted_classes` / `same_target_counted_classes`） |
| 改授权/通行证 | `gate.py` + `authstate.py` + `authdir.py`（三处必须一致） |
| 改识别通道 | `uia_tree.py`（结构）/ `eye.py`+`ocr.py`（像素/文字）/ `framecache.py`（抓帧） |
| 改时间线 | `store.py`（真源）+ `recorder.py` |
| 改安装/打包 | `install.ps1`、`tools/pack_dist.py`、`tools/verify_dist.py`、`build/*.spec` |

## 四、三份"同一逻辑的多处副本"（改之前必读）

| 名字 | 真源 | 产物 | 注意 |
|---|---|---|---|
| `act.py` 等 37 个老脚本 | `legacy_tools/_src/act.py` | `legacy_tools/`（gen_legacy 生成）＋ 本机 live（`dsh-viewer-plugin/tools`） | **只改真源**，再 `python -X utf8 tools/gen_legacy.py --out <仓根>/legacy_tools`；live 由 `check_live_sync.py` 守 |
| 闸门 `gate.py` | `src/agentctl/gate.py`（新线）＋ `legacy_tools/_src/gate.py`（老线） | 两份实现 | 常量/码表改动**两边都要看**（复核脚本会比对） |
| 判据 | `tests/_*.py` | `tests/run_all.py` 的 CRITERIA 登记 | 新增判据要登记并把文档条数改一致，否则"元判据"会红 |

**铁律：不许在 `tools/` 造第二真源。** 放行清单在 `.gitignore` 里有逐条理由。

## 六、读源码时最容易踩的三个坑

1. **`core.py` 是"大文件但线性"**：别通读，按 `def t_*` 跳读；每个工具大多 30~60 行，注释比代码长（刻意留的疤痕）。
2. **"动作发出去了"≠"事情发生了"**：一切确认都落在三态判词（`code=0/5/8`）与 `verdict_canonical`，不要用"命令没报错"当成功。
3. **live 不是仓**：本机在跑的那份在 `dsh-viewer-plugin/tools`（live），与仓内产物必须逐字节一致；不一致时先跑 `gen_legacy` + 重启进程，别在 live 上手改。
