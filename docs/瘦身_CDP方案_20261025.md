## 2 迁移顺序（先无状态，后全局）

**接缝规则（决定成败）**：新模块 `src/agentctl/cdp_browser.py` 只放实现，跨层依赖（`_legacy`/`env`/`gate`/`_pid_alive`/`_cdp_version`…）一律**参数注入**；core 保留同名**薄壳**，并在调用点解析 core 全局。这样 `core._cdp_http = fake` 仍能穿透，判据一行不用改。若把实现直接搬走、模块内部自调，S8 必**假绿**。

1. **传输（无状态）**：`_cdp_http` → `_cdp_json` → `_cdp_version`/`_cdp_pages` → `_cdp_eval`。壳示例：`_cdp_eval(...)` 内调 `cdp_browser.eval_js(..., legacy=_legacy)`；`_cdp_json` 的 `http=_cdp_http` 在调用时取。
2. **进程叶子（无状态）**：`_cdp_browser_exe`（`cands=CDP_BROWSER_CANDIDATES` 传入）→ `_cdp_spawn` → `_cdp_kill_tree` → `_pid_alive`。
3. **全局/进程表**：`_CDP_PROC` 与 `_cdp_launch` + `_cdp_close` **同一次提交**；表移入模块，core 用 `_CDP_PROC = cdp_browser.PROC` 指同一对象（测试 `.clear()` 仍生效）；launch/close 以 `proc=`/`version=`/`spawn=`/`pid_alive=` 注入。
4. **探针/DOM 段**：`_cdp_probe` → `_screen_dom` → `SCREEN_DOM_*`；`_screen_query_hit`/`_screen_norm_text`/`SCREEN_SOURCE_CONF` 以参数注入，不把 screen 整族带走。
5. **工具面壳**：`t_browser` 最后；只保留 gate→dispatch 转发，`ctl_browser` 契约零改动。

每步单独提交、可回滚；1~5 混在一起，判据红了分不清是哪层。

## 4 风险清单（按疼度）

1. **`_CDP_PROC` 是全局状态**：launch 写、close 删、测试直接 `.clear()`。必须与两函数同批搬；只允许一个对象，core 别名不得被重新赋值（否则两份表分叉）。
2. **判据靠 `core.<名字>` 猴补丁**：`tests\_语义屏判据.py` 直接换 `_cdp_http/_cdp_eval/_cdp_spawn/_cdp_kill_tree/_pid_alive/CDP_BROWSER_CANDIDATES`，并 `_CDP_PROC.clear()`。薄壳必须**调用时**解析 core 全局，否则补丁只改壳、模块仍用自己那份 ⇒ S8 假绿。
3. **`--inject` 影子仓只复制 core.py**：`build_injected()` 只把 core.py 抄进临时包；新模块必须用**绝对 import**（`from agentctl import cdp_browser`，与 core 现有风格一致），相对 import 会因影子 core 按路径加载而炸。注入段只改 core 尾部同名 def ⇒ 壳不能省；若直接搬实现，就必须同提交把新模块拷进影子包并挪相关注入锚点（`cdp_cap`/`cdp_steal`/`eval_port`）。
4. **外部调用方**：`src\agentctl\quiz.py` 用 `core._cdp_eval/_cdp_pages`；需保留 core 薄壳或同提交改 import。`sync.py` 只在注释提 `_CDP_PROC`，不是调用。
5. **双真源**：`legacy_tools\cdp.py` 仍是 DOM/WebSocket 真源，本刀不重写协议；新模块只包 HTTP/进程。
6. **行号漂移**：工单 7045 vs 实盘 7721；按实盘切，别复用旧行号。
