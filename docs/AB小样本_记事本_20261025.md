## ★ 必须直说的缺陷：T3 **误报 3/3**

T3 的预期是“目标窗已消失 ⇒ 回放必须报失败”。实际是：

```
verdict=完成   replay_ok=True   3/3
```

也就是说，**技能引擎在“目标已经不存在”的情况下仍然报成功**。原因链（已定位）：
1. `locate` 用的是 `ctl_find`，窗口进程刚被杀时有时间窗，仍能返回节点；
2. 我们的 executor 把 `ctl_click` 的 **code=8** 当 `ok=True`（为聚焦点击放行）；
3. `ctl_type` 只要 `ok=True` 就过，**没有要求 `verdict=met`**；
4. 步骤 `expect` 为 None ⇒ 引擎没有别的证据可用。

**这就是 ZCode 警告的“误报率”真实样本：3/3。** 在我们补上“动作前后窗口存活校验 + 判词必须 met”之前，任何“技能回放成功率高”的说法都不成立。

## 修法（下一步，按优先级）

1. `skills.replay` 增加**窗口存活校验**：每步前后由 executor 提供 `alive()`（或 `fingerprint()`），失败即停；
2. executor 的 `ctl_type` 必须要求 `after.verdict == "met"`，**不能只看 ok**；
3. 聚焦点击的 `ok` 允许 code=8，但必须带“这只是焦点变化”的备注，不能当“动作生效”；
4. 修好后重跑 T3，**误报必须为 0** 才算过。

## 修复后复测（同日 12:4x–12:5x）

- 结论：**引擎的 `alive()` 守卫还没有一次有效的端到端验证**；要验证必须换一个**能真正关闭**的目标（WinForms 窗体或独立进程的靶窗）。
