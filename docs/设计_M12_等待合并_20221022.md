## 0. 一句话

core 侧 `framecache.wait_change`（`src/agentctl/framecache.py:653`）与 act 侧 `_wait_effect`（`legacy_tools/_src/act.py:1280`）

| # | 通道 | 方向 | 载体 | 既有约定（行号） |
|---|---|---|---|---|

## 3. 合并点在哪一层：两个候选接口形状

### 候选 A（**推荐**）：**act 判据 + stdout 回传（走 C2）**

- **谁判据**：**act 侧**（`_wait_effect` 已经在判「画面变了没」，且它离注入最近、拿到的是**第一次变化**那一帧）。
- **回传什么**：act 在 stdout 末尾多打**一行 JSON**（沿用 `act.py:3467` 的既有格式），形如
  `{"__effect__": {"changed": true|false|null, "轮次": N, "耗时ms": X, "帧": "<路径>"}}`
  —— `帧` = act 探测时**最后一张客户区图**（`act.py:1094 _poll_sample` 已经在拿这张图，把它存下来即可）。
- **core 侧怎么用**：`core.py:2874` 收 `out` 后，`core.py:2629 _act_after` **改成**：
  若 `out` 里带 `__effect__` ⇒ **不再调用 `wait_change`**，直接用 act 回传的那一帧当「动作后帧」；
  若 act 判定 `changed=False` ⇒ **直接落 `code=8`**（与今天 `wait_change` 返回 `changed=False` 的路径一致）。
- **失败口径怎么保**：
  - 画面没变（act 说 `changed=False`）⇒ **仍落 code=8**，不因「省了等待」而放松；
  - act 说 `changed=null`（没测出来）⇒ core **不许**当成功 ⇒ 落 `code=5/8`（沿用今天 `wait_change` 返 `changed=None` 的处理，`framecache.py:653` 文档串明写「changed=None ⇒ 没测出来，不等于没变」）；
  - 预算**一秒不减**：`POLL_BUDGET_MS=800`（act）与 `WAIT_BUDGET_MS=300`（core）都保留；合并后**等多久由 act 那一遍说了算**（取 800ms 预算），core 不再额外加 300ms。

### 候选 B：**act 判据 + 帧走 SNAP_DIR（走 C3/C4）**

- **谁判据**：同候选 A（act 判）。
- **回传什么**：act 把「最后一帧」写成 `AGENTCTL_SNAP_DIR/<tag>.png`，并把 `<tag>.json` 里补 `changed/轮次/耗时`；
  core 通过 **C4** 把 `AGENTCTL_SNAP_DIR` 传给子进程（`core.py:483 _legacy_env` 加一个键），再按同一目录读回。
- **core 侧怎么用**：同候选 A，只是取帧路径变成「读目录」而不是「读 stdout」。
- **失败口径**：同候选 A。
- **代价**：多一次磁盘往返（PNG 写 + 读，量级 ~1~5ms），且要处理「目录不存在/文件过期」（`act.py:295 _snap_dirs()` 已只保留**真实存在**的目录 ⇒ 不存在时 act 要**明确报「没拍到」**，core 据此回落到今天的 `wait_change` 路径）。

### 两候选对比（给主控选）

| | 候选 A（stdout JSON） | 候选 B（SNAP_DIR） |
|---|---|---|
| 新造通道？ | ❌ 不新造（沿用 C2 + 既有 `print(json.dumps())` 约定） | ❌ 不新造（沿用 C3/C4） |
| 改动面 | act 侧 ~15 行 + core 侧 ~25 行 | act 侧 ~20 行 + core 侧 ~30 行（多一个 env 键） |
| 失败模式 | stdout 被截断/多行 ⇒ core 解析不到 ⇒ **必须回落到今天的 `wait_change`**（多等 300ms，但**不误判**） | 目录不存在 ⇒ 同回落 |
| 帧的时效 | 随 stdout 一起回来，**一定是本次动作的帧** | 靠 tag + mtime（`act.py:310 _read_snap` 按 mtime 倒序取最近）⇒ **同名 tag 复用时可能取到上一轮的帧** ⇒ **必须带本次 nonce** |
| 推荐 | ★ **推荐**（无跨进程文件系统依赖、失败面最小） | 备选（若 stdout 太长不宜塞二进制路径以外的负载） |

## 4. 合并后的预期节省（**算法**，不是拍脑袋）

**要省掉的正是 core 那一遍**：`core.py:2645` 的 `wait_change` 整段（M11 实测 **321~343ms**，大窗 414ms）。

```
省ms/次 = core 侧 wait_change 实际耗时            （M11 实测 321~343ms；大窗 414ms）
        = max(0, 端到端_after − 端到端_before)
```

- **画面会变时**：act 在**第一次探测到变化**就停（M11 直测 337.1ms / 3 轮）⇒ core 那一遍**本来也是白等**（它会立刻命中 changed=True）⇒ 省 ≈ core 那一遍的**大部分**（M11 直测 core 侧 193.7~283.2ms）。
- **画面不变时**：act 已盯满 800ms 预算仍判「没变」⇒ core 再等 300ms **必然还是没变** ⇒ 省 = core 那一遍**全额**（321~343ms）。
- **在什么窗口尺寸下成立**：**与窗口尺寸无关**（省的是 core 那一遍的**轮询**时间）。
  ⚠ 注意：**「每轮抓帧」的成本是窗口尺寸相关的**（M11：大窗 47.68ms/轮、小窗 12.5~40.96ms/轮）⇒
  合并后**留在 act 那一遍里的抓帧成本不变** ⇒ 小窗下合并收益**就是** core 那一遍的 321~343ms；大窗下 core 那一遍更贵（414ms）⇒ 收益更大。
- **端到端预期**：1,682~1,718ms → **约 1,340~1,400ms**（省 18~20%）。

## 5. 风险清单（触发条件 → 后果 → 兜底）

| # | 风险 | 触发条件 | 后果 | 兜底 |
|---|---|---|---|---|
| **R1** | ★ **「观测帧被误当动作后帧」** | 合并时 core 直接拿「动作前那张观测帧」当「动作后帧」⇒ diff 恒为 0 ⇒ **动作永远判「没变」** ⇒ 每次动作都落 `code=8` ⇒ **agent 永远收不到成功** | 最严重：**把成功判成失败**，且因 `code=8` 是「合法失败」而**不会炸**，只会一直失败 | **动作后帧必须来自 act 探测循环里的那一张**（`act.py:1094 _poll_sample` 的返回值），**不许**拿 core 的 `before` 图顶替；core 侧加断言：回传帧的 `mtime` 必须 **晚于**动作注入时刻（core 记录 `t_inject`）⇒ 不满足就**回落**到今天的 `wait_change` |
| **R2** | **act 的结论被 core 误读** | core 解析 stdout 失败/截断 ⇒ 拿不到 `__effect__` | core 无判据 ⇒ 可能把「不知道」当「没变」 | core 侧：**解析不到 ⇒ 一律回落** `wait_change`（`framecache.py:653`），**绝不许**把解析失败当 `changed=False`；`changed=null` ⇒ 落 `code=5`（没测出来 ≠ 没变） |
| **R3** | **回传帧与本次动作不同源**（同名 tag 复用） | 候选 B 用固定 tag 写目录 ⇒ 上一轮的帧被当本轮 | diff 拿错帧 ⇒ 误判变/不变 | 候选 B 的 tag 必须带**本次 nonce**（core 在 `core.py:3808` 组 argv 时一并生成，传给 act）⇒ 帧与动作**一一对应** |
| **R4** | **两侧口径不同导致结论打架** | act 用 `_poll_sample` 的**灰度图/指纹**判，core 用 `framecache` 的**指纹 + 降采样判差** | act 说「变了」、core 说「没变」 | 合并后**只有一个判据**（act 的）⇒ core 不再自己判；core 只做「回读/落盘」与「按 act 的结论落 code」；**判据唯一性**是本仓纪律 |
| **R5** | **注入其实没生效，但画面碰巧变了**（别的窗口/动画） | 合并后 core 采信 act 的「变了」 | 假成功 | 沿用现状口径：core 的落盘 diff 仍要给出**变化区域**（`core.py:2662`），**证据照样留**；`code=0` 的成立依据仍写进信封的 `after.diff` |
| **R6** | **急停/闸门在等的过程中被拉下** | 等待中 `brake.engaged` 变 true | 等满预算才返回 | 与现状一致（M11 已见 `code=11`）⇒ 合并**不新增**这类延迟；阶段二要保证「等的过程中急停被拉 ⇒ 立即返回」**不是**新引入的回归点（现状 core 侧也没这条） |

## 8. 原型（**实测**「只等一次」省多少 ms）

`tests\_M12_合并原型.py`（**不改 src/**，只在测试进程里 import/monkeypatch，跑完即退）：
同一次实验里把两侧的「等变化」**各跑一遍**，再算「只等 act 那一遍」的合并版。

**实测输出**（`work\_M12_原型输出.txt` / `.json`，2026-10-22 10:40:44，目标 = 脚本自己开的记事本）：

| 步 | 实测 | 说明 |
