# 实测：UIA 路径（2026-10-25 11:0x–11:2x，桌面实跑）

> 目的：验证「UIA 定位 + 点击 + 打字 + 外部读回」能不能作为默认主路。
> 环境：Windows 11、agentctl 通行证 A/B/C（60 分钟 80 次）、记事本（原生控件）与 tkinter 靶场（对照）。

## 一、结论

**能，但有两条必须写进设计的坑**：
1. **点击“只是把焦点移进编辑器”时，画面零变化 ⇒ code=8（no_effect）**。它不是失败，但会让技能回放的 `expect` 误判；
2. **tkinter 控件对 UIA 失明**：`ctl_find` 只拿到无名 `PaneControl`，按名字定位不可用 ⇒ 靶场必须换 WinForms/原生控件。

## 二、数字

| 动作 | 结果 |
|---|---|
| `ctl_find` 记事本（49 节点） | **128ms**，命中 `DocumentControl · 文本编辑器` |
| `ctl_find` tkinter 靶场（20 节点） | **82ms**，全部无名 Pane |
| `ctl_click --eid`（窗口被遮时） | **code=12**：落点归属 `Chrome_RenderWidgetHostHWND`，拒绝发送 |
| `ctl_click --eid`（已聚焦编辑器） | **code=8**：零像素变化（见坑 1） |
| `ctl_type`（空文档） | **code=0**，verdict=`met` |
| 外部读回（uiautomation ValuePattern） | 与写入串**逐字一致** |
| 技能回放 2 轮（含开窗 1.8s） | **2/2 成功**，单轮 **3.43s / 3.36s** |

## 三、护栏实战（不是 bug）

往**已有 1851 字符的真实文件**打字 ⇒ **rc=7** 拒绝：

```
目标文档里已有 1851 个字符，且不是训练靶
这道护栏防的是「把字打进用户的真实文件里」，不要绕
```

两条合规通路：清空后重打（read → Ctrl+A → Backspace ×N），或换空文档。本轮按第二条做。

## 四、参数坑（我的错，不是 bug）

`ctl_keys` 的参数是 **`keys`**（不是 `key`），Ctrl 是**独立布尔 `ctrl`**，且组合白名单只有 `{A,C,V,X,Z}`。
我传 `{"key":"ctrl+n"}` ⇒ code=4（键名不合法）；正确写法是 `{"keys":"v","ctrl":true}`。

## 五、对技能库（`skills.py`）的直接影响

- 回放步骤里 **click 的 `expect` 不能要求 `met`**：聚焦型点击天然 no_effect ⇒ 需要 `expect: "any"` 或改用 UIA `SetFocus`；
- **定位失败即停**已由引擎保证（本轮 find 命中才继续）；
- 靶场选型：WinForms/原生控件优先，tkinter 只作“坐标兜底”用例。
