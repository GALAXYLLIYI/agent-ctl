## 二、改了什么

### 2.1 病根（行号可查）

`legacy_tools/_src/auth_popup.py` 的 `merge_pass()`：`base["scopes"] = new["scopes"]`（**覆盖**）
⇒ 一张「只要 A」的小请求签出后，**你原来那张 B+C 的证就没了**。

### 2.2 改动清单

**真源 `legacy_tools/_src/auth_popup.py`（五处）**

| # | 位置 | 改动 |
|---|---|---|
| ① | `_initial_scope_states(items, no_d, existing_scopes=None)` | 本次范围 = **现有范围 ∪ 本次要的**（`existing_scopes` 形参）。并集**不是放宽**：每一项要么你早已批过，要么你此刻正在批。 |
| ② | `_existing_valid_scopes()`（新增） | 并集的来源 = **有效**旧证的范围（未消费、未过期）。**废证不进并集**（不能凭一张废证把权限恢复回来）。 |
| ③ | `issue_pass(...)`（新增，从 tkinter 闭包 `submit` 里抽出） | 「算范围 → 合并 → 落盘」变成模块级函数 ⇒ **判据能在用户不在场时打这条真签发路径**（改前它长在闭包里，弹窗要真桌面 + 真密钥才走得到）。★ 顺带修一个洞：空白范围项**不算一个范围**（见 §二.4）。 |
| ④ | `main()` | **先判 `window_ack`**（那条路只动窗口、范围一律不碰 ⇒ **不并集**），再取 `existing_scopes`，最后算 `states`。 |
| ⑤ | `_carried_letters()` + `_clamp_acts()`（新增） | **动作次数上限按并集夹紧**（见 §二.3，这是本轮挖出的真问题）。 |

**新线 `src/agentctl/core.py`（一处：注释订正）**
`core.py` 的 `ctl_authorize` 里有一段注释说「申请到的 == 授予的，所以不存在缺口」——
**并集之后这句不成立了**（并集让授予的 ⊋ 申请的）⇒ 注释已订正，并写明缺口由**弹窗侧**夹紧、
为什么在弹窗侧夹（只有它知道最终授予集；在新线算就得把并集逻辑写第二遍 ⇒ 两边漂移）。

### 2.3 ★★ 本轮挖出的真问题：并集会顺带**放宽动作次数上限**

**症状**：调用方算 `acts`（一张证能做几次动作）时，看的是**它申请的那几个范围**；
并集**带进来**的范围（D，上限 10）不在那个计算里 ⇒ 一张含 D 的并集证可能带着 20 的额度
⇒ **比 D 自己的上限宽松**。

**为什么必须修**：这等于「并集」顺手替你放宽了额度，而且是**静默**的。

**修法**（弹窗侧，因为它在锁里读旧证、才知道最终授予集）：
- `_carried_letters()`：算出「并集里**从旧证带进来**的那些字母」（本次没要、旧证里有）。
- `_clamp_acts()`：`acts = min(acts, 带进来范围自己的上限)`，口径与新线 `gate.effective_act_limit` 一致
  （**已授予档位里最紧的一档**，A 不参与取最小，因为 A 零副作用、不计数）。
- ★ `acts ≤ 0`（用户 2026-10-19 定的「不封顶」）**不夹** —— 并集不许破掉那条决定。
- ★ **没有并集 ⇒ 原样**（默认行为不变）。

**⚠️ 这里踩了一个「静默不生效」的坑（判据逼出来的）**：
旧线的 `gate.ACT_LIMIT` 的键是**全名**（`{"A级 只读感知":200, …}`）而不是字母 ——
我第一版按字母查 ⇒ 一个都查不到 ⇒ **夹紧静默失效**（acts 仍是 20，判据 A9 变红）。
⇒ 修法：经 `SCOPE_FULL` 翻译；并且**额度表认不出时按固定兜底上限（10）保守夹**，
**不许「静默不夹」**（那才是事故）。判据 A9e 专门盯这一条。

### 2.4 顺带修的一个洞（判据逼出来的）

`issue_pass` 原来直接用 `scope_extra`；若里面有**空白项**，就会签出 `scopes=[""]` 的废证。
⇒ 现在**空白项不算一个范围**（fail-closed）。
★ 诚实边界：实流程走不到这个洞（`_split_scope` 已经滤掉空串），是**纵深防御**，但判据把它钉住了。

### 2.5 `merge_pass` **不用改**（与派单写的不一样，如实说明）

派单 §1 单 B ② 写「拍板后才许动代码：`_initial_scope_states` / **`merge_pass` 两处**」。
实际**一处就够**：并集在上游算出来 ⇒ 传给 `merge_pass` 的 `new["scopes"]` 已经是并集
⇒ 它那句 `base["scopes"] = new["scopes"]` 存进去的就是并集 ✔。
（`merge_pass` 的语义「批准集 = 证的范围」一个字没改，改它反而会把并集做两遍。）

### 2.6 ★ 运行时同步（这一步不做 = 测试绿但线上没生效）

**运行时读的不是仓内 `legacy_tools`，而是上游那份**
（`ctl_status` 的 `legacy_home` = `<文档目录>/dsh-viewer-plugin/tools`；旧线的 `_auth`
也在**它自己所在目录**）。

⇒ 改完仓内真源、跑 `gen_legacy` 重生成产物后，**还必须把产物同步到上游那份**，
否则弹窗行为不变。已同步并核过**逐字节一致**（`E7CF2B00…`）。
★ 同步时踩到：上游那份是**只读**的（上次生成的收尾动作带过去的）⇒ 直接覆盖 `Access denied`，
要**先清只读、复制、再恢复只读**（已恢复原状）。
