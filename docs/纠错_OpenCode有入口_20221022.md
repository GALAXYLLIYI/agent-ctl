### 两条可用通道（**实测走通**）

1. **CLI（推荐）**：`opencode-cli.exe run --auto -m <model> -f <附件> "<短指令>"`
   ⇒ 直接跑一轮问答，**不需要抢前台、不需要像素点击**。本轮征询就是用它跑的。
2. **GUI**：窗口 hwnd 可用（`ctl_windows` 能拿到 rect），但——
   - **UIA 树只有 3 个节点**（`Chrome Legacy Window`，禁用）⇒ **可访问性全瞎**（与 ChatGPT 3 节点、QQ 13 节点同族）；
   - 输入框能靠坐标 + `SendInput` 打字**打进去**（1139 字全文落地 ✔），
     但 **回车与「↑」按钮都点不动**（`ctl_click` 报 ok、`ctl_keys Enter` 报 ok，**画面无变化**）⇒ 该通道**只到「打字」为止，发不出去**。
   ⇒ **结论：OpenCode 走 CLI，不走 GUI。**

## 二、附带记下一条**本产品**的实测坑（不是 OpenCode 的问题）

`ctl_type`（`mode=focus`）把 **1139 个中文字符**打进 OpenCode 时返回 **rc=124（超时）**，
但**字符其实全部打进去了**（截图逐字核对过）。

⇒ ★ **rc=124 ≠ 没打进去**。老脚本 `act.py` 逐字符 `SendInput` 的耗时超过了 core 的等待上限，
于是**超时被报成失败，动作其实已完成**。
⇒ 这是**「动作发出去了但没验成功」**的另一种形态（与 code=8「画面没变化」同族，但更隐蔽）。
⇒ **建议**（留账，本轮不改）：`ctl_type` 对长文本应**分段**或**放宽超时**，
并在返回里区分「超时但已发出」与「超时且未发出」。**本轮登记为待办，不动产品代码。**
