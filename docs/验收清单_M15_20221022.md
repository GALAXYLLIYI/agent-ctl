## 4. ★ 本单实测揪出的、A 批初版自己没发现的洞（如实登记）

| 项 | 内容 |
|---|---|
| 现象 | `client_rect_screen` 无条件 `width = raw × dpi_scale`；而 `GetClientRect` 给的是**物理**还是**逻辑**像素，取决于**进程**的 DPI 感知级别（实测 unaware=1695×1013 / aware=2543×1520） |
| 受害面 | **服务进程**（`legacy_tools/coord.py` 导入即 `SetProcessDpiAwareness(2)` ⇒ 服务用过 `ctl_screen` 就是感知进程）⇒ 客户区被报成 **3814×2280**（真值 2543×1520）⇒ ① ImageGrab 退路按 3814 抓（抓到窗口外的别的东西）② 两条路径词框不在同一套坐标 ③ core 的 usable 边界虚高 1.5 倍 |
| 为什么初版判据没抓到 | **判据进程恰好是 DPI-unaware** ⇒ 双乘没触发（unaware 下 `raw×k` 恰好等于物理值）⇒ **判据绿了，产品是错的** |
| 修正 | `client_rect_screen` 按**当场查到的感知级别**算：aware ⇒ raw 即物理（**不再乘 k**）；unaware ⇒ `raw×k` 且**原点口径标为不可靠**。并新增 `dpi_aware` / `口径可靠` 字段 |
| 交叉核对 | 判据 A④：修后 `ocr 客户区 == uia_tree 客户区`（2543×1520@(9,0)），**尺寸与原点都一致** |
| 词框数值有没有变 | **没变**。改前(unaware) / A批初版(aware) / 修正版(aware) 同一个窗口上「文」都是 x=21（详见实测 §2.4）。本轮改的是**客户区尺寸**、**ImageGrab 退路 bbox**、**原点物理性**，不是词框数值 |
