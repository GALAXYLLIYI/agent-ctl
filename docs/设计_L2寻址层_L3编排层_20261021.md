### 1.2 缺口（单 C 要解决的五个）

- **G1 寻址不可复用**：五步（观测 → 定位 → 点 → 核验）每次**手搓**。
  `ctl_find` / `ctl_tree` / `ctl_screen` 三种观测各自签各自的 `capture_id`，
  **没有一个「目标对象」把 `(hwnd, uid, eid, capture_id, gen, screen_version)` 捆在一起**；
  凭据一旦过了 15 秒 TTL（`gate.py` 的 `CAPTURE_TTL`）整条作废 ⇒ agent 只能从头重做。
- **G2 失效语义没成文**：`uid_state` 有三档，但「**什么时候必须重新解析、什么时候可以沿用**」没有规则 ⇒ 每个 agent 各发明一套。
- **G3 重试没有幂等语义**：`postcondition` 已经是结构化判词（四态），但没人拿它当**幂等键**
  ⇒ 「点了没看见效果」就重试点 ⇒ 可能**点两遍**。
- **G4 状态住在进程里**：`ctl_task` 的事件流是真相源（哈希链、只追加），
  但「这个步骤做没做过」现在只存在于**调用方的记忆**里 ⇒ 崩一次／重启一次就失忆，且无法自证。
- **G5 两个时间尺度没桥**：凭据是**秒级**（15s），编排是**分钟级**（任务推进），
  中间没有「凭据过期了，但整条任务不用重做」的中间态。

## 二、L2 寻址层：目标解析对象（Target）

### 2.1 数据结构（字段级）

| 字段 | 来源 | 语义 | 失效条件 |
|---|---|---|---|
| `hwnd` | `ctl_windows` | 目标窗口 | 窗口没了 |
| `window_gen` | `ctl_windows` 的 `gen` | 窗口代际（服务端签发） | `ctl_click` 回执 gen 不符 ⇒ 重新 `ctl_windows` |
| `uid` | `ctl_screen` 的 `objects[].uid` | `struct_key@text_key`，**对象身份** | `uid_state=STALE`（结构变了 ⇒ 不是同一对象） |
| `eid` | `ctl_find` / `ctl_tree` | 那次快照的取件钥匙 | 窗口内容变化 ⇒ 回执 `STALE_SCREEN` ⇒ 重扫 |
| `capture_id` | `ctl_find` / `ctl_tree` / `ctl_shot` | 观测凭据（**15 秒**） | 过期 ⇒ `code=12`「capture_id 已过期」 |
| `screen_version` | `ctl_screen` | 屏幕版本（服务端签发） | 版本不匹配 ⇒ 重新观测 |
| `expect_uid` | 由 `uid` 派生 | 点前身份确认用（点前重算，不匹配就零像素拒） | 同 `uid` |
| `rect` | `ctl_screen` / `ctl_find` | 目标矩形（屏幕物理像素，**唯一一套坐标**） | 窗口动了 ⇒ 重新观测 |
| `target_id` | **本地派生** = sha256(规范化(上述绑定字段)) | 指称与幂等用；**不含时间** | 任一绑定字段变 ⇒ 变 |

★ `target_id` **不含时间戳**：同一目标解析两次必须得到同一个 `target_id`
（这是 J2 判据的核心断言）；时间不入键，才谈得上「幂等」。

### 2.2 解析流水线（只用现有工具，**不加新工具**）

```
ctl_windows                                  → 窗口清单 + gen（免授权，A 级）
   └─ ctl_screen(hwnd, top, include_offscreen, query?)
        → objects[]（id/uid/label/role/rect/interactive/source_confidence/…）
        → screen_version；给了 since 还有 uid_state
   └─ 选定对象 → 记 (uid, rect)
        └─ 要点它 → ctl_find(hwnd, query) 或 ctl_tree(hwnd) → capture_id（15s）
             └─ ctl_click(hwnd, xy, from_capture, expect_uid, window_gen,
                          verify_expect=…, expect_region=…)
                  → 回执：verdict（因果四态）＋ after.uid_state ＋ 归属事实
```

★ **网页场景另走 CDP**（`ctl_browser`），一帧像素都不碰 —— 已在
`docs/浏览器CDP接线图.md` 立规矩，本层不重复发明。

### 2.3 失效语义表（本层的**核心产物**）

| 现象 | 从哪看出来的 | 必须做什么 | 不许做什么 |
|---|---|---|---|
| `capture_id` 过期 | 闸门回执 `code=12`「capture_id 已过期」 | **重新观测**那一步 | 拿旧凭据硬点 |
| `uid_state = STALE`（struct 变） | `ctl_screen(since)` | **重新定位**（寻址拒绝，不许沿用） | 当成同一对象继续 |
| `uid_state = TEXT_CHANGED`（文变了，结构没变） | 同上 | **可以点**（同一对象），但核验期待要改成 `after.uid_state` 比对 | 报「目标不见了」 |
| `uid_state = OK` | 同上 | 沿用 | — |
| `window_gen` 不匹配 | `ctl_click` 回执 | 重新 `ctl_windows` | 点 |
| eid 路径回 `STALE_SCREEN` | `ctl_click` 回执 | 重扫（`ctl_find` / `ctl_tree`） | 复用旧 eid |
| 内容摘要变了（单 A 核心） | 摘要比对 | 重新观测 | — |
| 窗口 rect 变了 | 闸门 `code=12`「窗口位置/大小变了」 | 重新观测 | 换算坐标硬点 |

★ 这张表是**成文口径**，不是某个 agent 的经验 —— 落地时它进 `docs/AGENT接口.md` 一小节（指针式，不复述全套）。

### 2.4 ★ 边界：**L2 不新增任何 MCP 工具**

`input_schema` 键集/type/required 冻结**，**A1 把 desc+schema 卡在 27000 字符**
（当前 26851，余量 149）⇒

| 想要的做法 | 会撞哪条 | 结论 |

## 三、L3 编排层：步骤、幂等键、状态重建

### 3.1 Step 模型

```
Step = { step_id, intent, target(Target), precondition, action, postcondition }
```

- `precondition`：进入这一步前必须成立的事实（如「窗口在」「租约在」「证没过期」）。
- `action`：一次**既有工具调用**（⇒ 闸门、归属、零像素那一套全部照旧，编排层不新增放行口）。
- `postcondition`：**复用已有的结构化判词**，不新造词表：
  - 因果四态 `verdict`：`met` / `no_effect_in_region` / `changed_outside_target` / `unknown`
  - 内容三档 `uid_state`：`OK` / `TEXT_CHANGED` / `STALE`
  - 可选：`after.uid_state`、`screen_version`、命中框

### 3.2 postcondition 即幂等键

**键的规范化**（写歪了就会重做，得死抠）：

```
key = sha256( step_id ‖ intent ‖ canonical(target_id) ‖ canonical(postcondition 谓词) )
```

规范化规则（逐条都要有判据）：
- 字段名排序固定；空白折叠；数字取整（坐标取到像素、分数取两位）；
- **时间不入键**（否则同一件事永远不幂等）；
- 谓词取**语义字段**（`uid` / `expect_uid` / `verdict` / `expect_region`），**不取**回执里的自由文本。

**判重规则**（拿到已有事件后怎么办）：

| timeline 里同键的历史 | 含义 | 编排层的动作 |
|---|---|---|
| 有 `met` | 这件事**成过** | **跳过**（幂等命中），回执写明「命中既有事件，不重做」 |
| 有 `no_effect_in_region` | 确认**没成** | **重做**（这是「没成」而不是「成过」） |
| 有 `changed_outside_target` | 动了但不在判定区 | 重做，但要**先重解析**（世界变了） |
| 有 `unknown` | **观测失败**，不是「没成」 | ⛔ **不许自动重做**（重做可能双击）⇒ 要人/agent 明确要求 |
| 有 `STALE` | 对象已不是那个对象 | **重做**（且必须重解析） |

★ `unknown` 那一行是**安全关键**：把「没测出来」当成「没做成」去重做，就是**双击**的来源。
（与既有纪律一致：unknown 永不当成功，也永不当「没发生」。）

**冲突**：同键但结论不同（例如先 `met` 后 `STALE`）⇒ 以**时间线上最后一条**为准，
但事件流**只追加不修改** ⇒ 冲突本身**要留痕**（追加一条 `task_progress`，写明两次结论与各自证据）。

### 3.3 状态从 timeline 重建（不靠进程内缓存）

- **真相源**：`timeline.db`（哈希链、只追加）＋ `ctl_task` 的事件
  （`task_created` / `task_progress` / `task_delivered` / `task_verified`）。
- **重建算法**：扫事件 ⇒ fold 出「每个 step 的最新状态」＋「每个幂等键的最新结论」。
- **进程内缓存只是加速器**，不是真相源：缓存清空后**必须**能从 timeline 重建出**同样的结论**（J4 判据的核心断言）。
- **崩溃恢复**：重启后编排层从 timeline 重建 ⇒ 知道做到哪一步、哪些键已命中。
- ★ `ctl_task` 的三态口径**照旧**：`task_verified` **只能由用户触发**，agent 无权宣布完成。

### 3.4 桥：秒级凭据 ↔ 分钟级编排（补 G5）

| 层 | 时间尺度 | 载体 | 过期怎么办 |
|---|---|---|---|
| 单步观测 | **15 秒** | `capture_id` | 只**重做那一步的观测**（不回退整条任务） |
| 单步身份 | 分钟级 | `uid` / `uid_state` / `expect_uid` | 重新定位（§2.3 表） |
| 任务推进 | 十分钟级 | `ctl_task` 事件流 | 从 timeline 重建（G4） |

⇒ **凭据过期不回退整条任务** —— 这就是两层之间缺的那座桥。

## 七、风险与止损

| 风险 | 后果 | 止损 |
|---|---|---|
| 幂等键规范化写歪 | 同一件事被判成两件 ⇒ **重复执行**（点两遍） | 键里只放**已存在**的结构化字段；J3 必须覆盖「同义不同形」 |
| 把 `unknown` 当「没成」 | 重做 ⇒ **双击** | J3 把这一条单列为断言；编排层默认**不自动重做** |
| 状态重建与在线缓存漂移 | 两套真相 ⇒ 结论不可信 | J4：清缓存后必须重建出**同样**结论 |
| 事件流被写爆（每步一条、每帧一条） | `timeline.db` 膨胀、哈希链变慢 | 只给**里程碑**写事件（step 开始/结束/幂等命中）；不要每帧写 |
| 客户端库被 agent 当权威、绕过闸门 | 安全退�� | 库里**只做编排**，动作仍走既有工具 ⇒ 闸门照旧 |
| 一期把「编排层」做成「新工具」 | A2/A3 红 ⇒ 契约面被动 | 本设计的 §2.4 边界就是防这个；真要做 ⇒ 走拍板流程 |

## 八、需要用户拍板的（≤2 条）

1. **L2/L3 放在哪一层**：客户端层（本设计建议，**零契约变更**、零判据口径变更）
   vs 服务端原生（要加工具 ⇒ 撞 A2/A3 ⇒ 必须像「单 A②」那样单独拍板一轮）。

   （幂等命中是「我判断这件事做过」的重要痕迹），但只写里程碑。
