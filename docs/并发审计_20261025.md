# 并发审计（2026-10-25）· 静态清单 + 三个真问题

> 方法：只读审计（读锁的使用、共享状态清单、线程模型），不改代码；每个结论标注证据行。
> 结论先行：**跨进程的并发做得对（文件锁+原子替换），进程内的线程并发有真缺口。**

## 一、线程模型（先说清谁在并发）

- `mcp_http.py` 用 **`ThreadingHTTPServer`**（每个请求一个线程）；
- 同一个进程里还有看护线程（daemon-watchdog）；
- 于是：**同一进程内，多个 MCP 请求会真正并行**，共享模块级状态必须自己加锁。

## 三、三个真问题

### F1（高）`action_guard._state` 没有锁

`observe()` 里对 `_state["same"] / ["fail"] / ["rate"] / ["hits"]` 做 **读-改-写**：

```python
n = ((rec.get("n") or 0) + 1) if rec else 1      # action_guard.py:335
_state["same"][key] = {"n": n, "last": now}
...
fail_n = ((rec.get("n") or 0) + 1) ...          # :353
_state["fail"][actor] = {"n": fail_n, "last": now}
```

`ThreadingHTTPServer` 下两个并发请求可能同时读到同一个 `n`，**后写覆盖先写** ⇒
计数器少计（漏：该拉闸没拉）或多计（误：不该拉闸拉下）。
两级刹车（先 warn、连续两次才 brake）对计数精度是敏感的，**这不是理论风险**。

### F2（低-中）core 的模块级缓存无锁

`_SCREEN_SEEN` / `_SCREEN_FRAME_RESULT` / `_CDP_PROC` / `_INTEGRITY_CACHE` 都是普通 dict：
单次 `d[k]=v` 在 CPython 下原子，但 **“读出来→判断→再写回”不是原子的**。
影响：screen 评分可能用旧帧结果、CDP 端口表可能短暂重复启动；不会破坏安全性，但会产生“偶发不一致”。

### F3（中）租约只防跨 actor，不防同一 actor 的并发调用

`acquire_lease` 的判据是 `holder != actor` ⇒ **同一个 actor 可以并发 N 路**。
`capture_id` 的五项校验能拦住“旧帧点新画面”，但**同一窗口两个并发动作仍可能交错**
（例如同时 click 与 type），表现为偶发“动作没生效”。

## 四、已经做对的（不是空夸，有代码位置）

1. 通行证读改写**同一把锁**、写盘用 `os.replace`（gate.py:655-712）；
2. 租约的 acquire/renew/release/revoke **全在 `_exclusive()` 内**（gate.py:979/994/1013）；
3. 急停旗子 tmp + 替换，且带 pid + 有界重试（gate.py:780-800）；
4. **“这次调用是人发起的吗”用 thread-local**，不会被别的线程串味（core.py:242+）；
5. 有 40 进程并发发证测试（注释里记录）。
