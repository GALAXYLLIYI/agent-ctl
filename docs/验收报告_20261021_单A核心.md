## 一、做成什么

### ① 统一哈希来源（病根与改法）

**病根（行号可查）**：签发侧与校验侧取的是**两个不同来源**的画面哈希。

| 侧 | 改前位置 | 改前取的是什么 |
|---|---|---|
| 签发 | `core.py:888`（旧行号） | legacy 帧文件（PrintWindow 落盘 PNG）的**文件字节** sha256 |
| 校验 | `core.py:2190`（旧行号） | **mss 实时抓屏**的 RGB 缓冲 sha256 |
| 比对 | `gate.py:1179` | 两侧都非空才比；不等 ⇒ 抛 `GateDenied(code=12)`「画面哈希变了」 |

⇒ 文件字节 vs 实时抓屏，**画面一模一样也必然不等** ⇒ 一开就是**假拦**。
而且 `verify_image` 从来没进过契约（`contract/tools.json` 里 grep 不到），
`core.py:2183` 那个分支**一次都没走到过** ⇒ 「凭据内容寻址」这个能力事实上**不存在**。

**改法**：新增 `src/agentctl/digest.py` —— 窗口画面摘要的**唯一来源**，
签发与校验**都调它**（`digest.window_digest`）。

**口径（四条，都有实测支撑）**：

| 口径 | 内容 | 为什么 |
|---|---|---|
| ① 只取**客户区** | `PrintWindow` + `PW_CLIENTONLY｜PW_RENDERFULLCONTENT`（flag=3） | 整窗（flag=2）实测**不稳定**：同一窗口连抓 3 次，三个 sha256 全不同；逐像素比对 2634 个像素不同（3.43%），**最大通道差只有 ±1**，差异 bbox = `x[197..319] y[0..30]` ⇒ 那是**标题栏**（DWM 文字渲染的亚像素噪声）。客户区：三次抓取**逐像素 0 差异**。 |
| ② 对**像素**取 sha256 | 不是 PNG 文件字节 | PNG 有编码器版本差异，同一画面换个编码器就换哈希。 |
| ③ 拿不到就**空串** | 调用方据此跳过比对（`gate.py:1179` 既有语义） | **不许假装有摘要**；空串时仍比 rect／前台／TTL。 |
| ④ **绝不退回屏幕抓取** | 无 ImageGrab 退路 | 那是**另一个来源**，而且窗口被盖住时抓到的是压在上面那个窗口。 |

**默认行为不变**：不传 `verify_image` 时，行为与改前**逐字一致**（今天＝不做图像比对）。判据 D 条钉住这条。

## 七、顺手发现（只报不改）

1. **整窗摘要不可用**（标题栏 DWM 亚像素噪声，±1 级差异就让 sha256 变）。
   本轮口径已避开（只取客户区）；但若将来有人做「整窗摘要」/「帧指纹」，会直接踩这条。
2. **客户区近纯色 ⇒ 摘要为空 ⇒ 不比较**（能力有缺口，不是 bug）：
   窗口空白/最小化/单色界面时，内容寻址会**静默退化成旧行为**（只比 rect/前台/TTL）。
   这条退路是「不误拒」的取舍，写在 `digest.py` 与 §3-bis-ter 里了。
3. **`ctl_shot` 热路径 +4~60 ms**（按窗口面积），当前是**白付**的（契约没暴露，功能还用不上）。
   拍板项 1 一起解决。
4. **窗口D 执行通道当前不可用**：MiniMax M Plan 端点 `api.minimax.cn`
   —— `/v1/responses` 返 **HTTP 500**、`/v1/chat/completions` 返 **HTTP 429**；
   `codex exec` 连打 3 次全部 `turn.failed`（`codex_error_info: internal_server_error`，
   被 CLI 翻译成「high demand」）。认证没问题（`sk-cp-` 令牌写在 `~/.codex/config.toml` 里，
   `codex login status` 的 Not logged in 指的是 ChatGPT 登录，与 minimax provider 无关）；
  本地 Ollama 未起（127.0.0.1:11434 连接被拒）。
   ⇒ 本轮由主控接手实现；**窗口D 恢复后应回来做异构审核**（现在只有主控自审，独立性弱一档）。
