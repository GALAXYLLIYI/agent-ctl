## 一、P0-1 · 失败分类：把「环境不满足」和「动作没生效」分开

### 1.1 事故现场（2026-10-21 凌晨实测）

给 MiniMax Code / 窗口A 发消息时，同一坐标连续 8 次失败（wrong_target 被别的窗挡住 /
foreground_blocked 前台不是它 / 缺 from_capture）⇒ 触发 action_guard 的 fail_streak=6
**自动急停** ⇒ 急停**连带吊销租约** ⇒ 后续动作全被拒 ⇒ 更多失败。**正反馈。**

### 1.2 根因（两家评审独立定位到同一处）

- src/agentctl/action_guard.py:293-297：fail 计数只看 bool ok，**失败没有分类**；
- core.py 的 dispatch 出口：observe(ok=bool(r.get("ok"))) —— 把
  「没发出去」和「发出去了没生效」塞进了同一个桶。

### 1.3 改法

- core.py 新增 failure_class(r)：按 code 贴性质标签
  （rejected_env = 3/4/5/7/9/10/11/12/13；no_effect = 8；其余 = action_failed）；
  **判不出来的一律按 action_failed**（宁可多算不可漏算：漏算 = 护栏松了）。
- action_guard.observe(..., failure_class=...)：
  **环境性拒绝不计入 fail_streak，也不计入「同目标连击」**（被闸门当场拦下恰恰是闸门在正常工作）；
  它改为**单独留痕** kind=action_blocked（只留痕、不拉闸、不计数）。
  failure_class=None（老调用方）⇒ **按旧口径**，向后兼容。
- 阈值口径写进 action_guard_policy.json（fail_counted_classes / blocked_event），
  **不硬编码**（沿用该文件「给人审的阈值文件」的老规矩）。
- 回执多一个字段 failure_class（只在失败时出现）⇒ agent 能自己判断「该不该重试」。

### 1.4 判据与证据

- tests\_P2_动作面刹车判据.py 新增第 **9/10/11** 条：
  9 = 环境性拒绝 10 次 ⇒ 0 次命中、0 拉闸、10 条 action_blocked 留痕；
  10 = 真失败（no_effect）7 次 ⇒ 照旧两级（第 6 次提示、第 7 次拉闸，**护栏没松**）；
  11 = 静态：dispatch 真的把 failure_class 传给了 observe。
- **红验证**：新增坏实现 D（work\_P2_造坏实现.py 派生）—— 把计数口径改回旧口径
  ⇒ 实测**第 9 条红**（其余仍绿 ⇒ 这一条有判别力且不打误伤）。

## 二、P0-2 · 急停不许由 agent 自己解掉

### 2.1 事故现场

凌晨实测：agent（我）用 ctl_brake --action release **连续三次**解掉自己触发的急停，
理由栏写的是「自触发的 fail_streak 误伤」。MiniMax Code 与 窗口A **不约而同**把它列为
安全边界问题：**「刹车能被被刹者拆掉，就不叫刹车」**。

### 2.2 改法

- **工具面（MCP / HTTP）只允许 stop 与 status**；release 一律被拒（code=9），
  并回执两条人路（面板「▶ 解除急停」按钮 / 命令行显式确认）。
- 命令行：**必须带 --confirm-release**（不带 ⇒ 拒绝 + 打印用法，退出码 2）。
- 「人路」标记走 threading.local（core._is_human_call()）——**不进 args**
  （args 会过契约校验、还会落进事件流）；调用结束在 finally 里**复位**（HTTP 多线程不许串）。
- stop 是安全方向，**永远允许**（堵的只是「自己拆自己的刹车」）。

### 2.3 判据与证据

- 新增 tests\_P0_急停自解锁_判据.py（6 条，隔离环境，不碰真机状态）：
  工具面被拒且急停仍在 / stop 照旧允许 / 人路放行且真解除 / **human 标记复位** /
  命令行必须 --confirm-release / 静态查 release 分支有人路闸。
- --inject（把 _is_human_call 打成恒 True）⇒ **第 1、4 条红**。
- 已接入 tests\run_all.py 的 CRITERIA（第 38 条）+ INJECTABLE；
  判据条数同步到 work\_判据有效性清单_20261017.md 与框架进度文档（37 → **38**），
  元判据②「文档条数 == len(CRITERIA)」实测**绿**。

### 2.4 诚实边界

这一条堵的是「**顺手自解锁**」——agent 唯一顺手的接口没了。
shell 层面直接删旗子文件（%LOCALAPPDATA%\AgentCtl\_急停.flag）**不在本条范围**（那是 OS 权限问题），
而且那条路**绕过留痕**——这正是「留痕」比「不许」更重要的原因。

## 三、P0-3 · UIA.Invoke 路径恒 rc=8（窗口A 评审逮到的真 bug）

### 3.1 现象与根因

legacy_tools/_src/act.py 的 do_click：changed 只在两条路径里被赋值
（后台投递 / SendInput），而 **else 分支（也就是 UIA.Invoke / SelectionItem）从不计算 changed**
⇒ 末尾 changed is True 恒不成立 ⇒ **这条路径恒返回 rc=8**：
name 点击即便 Invoke 成功、界面真的变了，回执也只说「画面没变化」。
⇒ **桌面窗口的 name 点击路径实际上一直不可用**（而契约上写着它可用）。

### 3.2 改法（改真源，产物用生成器刷新，不手改产物）

- 真源 = legacy_tools/_src/act.py（窗 X 起方向是「真源在仓内，产物由 tools\gen_legacy.py 生成」）：
  ① Invoke 分支补算前后整窗指纹（与另两条路径同口径）；
  ② changed is None（**判不出**）时文案说「判不了」，**不许**说「画面没变」
  （判据 34「unknown 不当成功」＋判据 36「文案与数据一致」都盯着这条）；
  ③ retry 默认 **1 → 0**：「画面没变化」时**不再自动重点一次**
  （对输入框是多余的一下、可能顺手选中一段字；对 toggle 是「开了又关」）。
- 产物刷新：python -X utf8 tools\gen_legacy.py --out legacy_tools
  ⇒ 双基线台账对账**绿**（35 项：产物 = A₀、真源 = T₀，两腿都对齐）。

### 3.3 判据与证据

- tests\_像素不判成功_判据.py 新增第 **(3)** 条：Invoke 分支必须算 changed、
  必须说「判不了」、retry 默认必须是 0。
- --inject 把 Invoke 分支的 changed 计算去掉 ⇒ **(3) 红**（同时 (1) 仍红）。
- 契约 contract\tools.json 的 ctl_click.retry.default 1 → 0，docs\AGENT接口.md 同步。

### 4.4 附带修掉的根因（MCP over HTTP 起不来）

**pythonw.exe 下 sys.stderr 是 None** ⇒ BaseHTTPRequestHandler.send_response() →
log_request() → log_message() → sys.stderr.write(...) → **AttributeError**
⇒ 响应头一个字节都没写出去 ⇒ 客户端只看到「Empty reply from server」（curl 52）。
证据：mcp_server.log 里每条请求只有「HTTP 响应形态=JSON」（写在写响应**之前**），
本该紧跟的「HTTP 响应 status=200」永远不出现。
修法（src\agentctl\mcp_http.py）：模块级 sys.stderr is None 兜成 devnull；log_message() 再补 None 检查。

## 六、明确没做的三件，以及为什么（留给下一轮 / 待拍板）

### 6.1 P1-1 凭据 ttl / max_uses（两家都排 P1）——**前置条件不满足，先别做**

原计划：把 from_capture 的 15 秒 TTL 放宽、并允许一次观测点多个点
（ttl_sec / max_uses，每次使用照跑 hwnd/rect/foreground/代际校验）。

**实测发现的前置障碍（这才是关键）**：
签发时的图像哈希来自 **PrintWindow 存下来的 PNG 文件**（_issue_capture_from_shot），
而校验时的哈希来自 **mss 实时抓屏**（_bind_capture 的 verify_image）。
**两个来源不同 ⇒ 哈希必然不等** ⇒ 「内容寻址」这条现在根本不能开
（这也是为什么契约里**没有** verify_image 这个参数）。
⇒ **要做内容寻址，第一步必须先把两个哈希来源统一**（都用 PrintWindow，或都用屏幕抓取）。
在统一之前放宽 TTL = 真的削弱「旧帧不许点新画面」这条头号事故防线 ⇒ **不做**。

### 6.2 通行证改造（scopes 并集 / 预勾选）——**等你或 本地 agent 拍板**

窗口A 的最小改法（语义不动，只把弹窗的**默认勾选集**改成「现有 ∪ 本次要的」，用户可见可取消）
与 MiniMax Code 的 ceiling/grant 两概念版本，都已写清；**语义决策交给人**，本轮不擅自动。

### 6.3 单例弹窗仲裁器 / 描述瘦身 / L2 寻址层 + L3 编排层

- 弹窗仲裁器（brake_popup.py 已有 _CURRENT 雏形，推广比新建容易）：**本轮没做**，
  但 P0-1/P0-2 已经把「四个弹窗」这类噪音的成因压下去一半。
- description 瘦身（≈10k tok → 目标 2.5k）：**大单**，要逐条搬历史背景进 docs\AGENT接口.md，
  本轮不动（动它要重跑模型侧对比评测，收益与风险都大）。
- L2 寻址层 / L3 编排层（任务 DSL、postcondition 即幂等键、状态从 timeline 重建）：
  **主体工程（1–2 周）**，MiniMax Code 已给出完整设计，本轮只出设计不出码。
