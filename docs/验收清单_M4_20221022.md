## 0. M4 要解决的问题（一句话）

输入归因（谁在操控这台电脑：agent / 真人 / 远程他程序）目前只能靠
「LLMHF_INJECTED 注入位 + ±2 s 内对上 timeline 动作」这条**时间邻近**的软判据，
误判率高。M4 给 agentctl 自己的 `SendInput` 注入打一个**专属魔数**
（`dwExtraInfo`），让「这是 agent 干的」变成**一票确定**，砍掉一整类时间邻近误判。

## 1. 改前基准（主控已独立实测，2026-10-22 05:47）

### 6.1 ★ 唯一未闭合项：M6 回归红 3（**环境所致，已用两条独立证据排除 M4 责任**）

B2（画面变了必须重扫）/ B2b（screen_version 必须进位）/ B3c（动作本身真的跑成）。

**根因不是 M4**：

1. 判据回执明写 `ctl_click：1633.6 ms code=5 … warning='坐标/前台/窗口稳定性拒绝'`
   ⇒ act.py 的 ensure_foreground 失败（act.py:3090「置前台失败的语义是『前台/窗口不稳定』… 返回 5」），
   动作**在注入之前**就被拒 ⇒ 画面当然没变 ⇒ 上面三条连锁变红。
2. 主控独立实测**前台锁死**：对记事本调 SetForegroundWindow 返回 **False**、前台**纹丝不动**
   （前台是 GameInputSvc 的无标题窗口）；再用 AttachThreadInput 绕，仍失败。
   ⇒ 判据的 focus_only() 在本时刻**必然失败** —— 与 M4 无关。
3. **逻辑闭合**：M4 的改动全部落在**注入时刻**的 dwExtraInfo 实参上；本次动作**根本没走到注入**，
   ⇒ M4 的代码路径**本次根本未被执行**。

⇒ **裁决：M4 本体通过**（R1–R8、R10、R12、R13 全绿，R3/R4 主控亲跑复现）。
