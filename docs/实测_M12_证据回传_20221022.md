## 2. 形状（对照裁决 §一 / §五）

```
core.t_click (core.py:3621)
 ├─ 前置闸门 (core.py:3693) ─ 租约/通行证/凭据
 ├─ ★ 建本次动作专属目录 work 的临时目录 + t_spawn=time.time()
 ├─ ── 进程边界 ──  core._legacy → act.py click
 │    act: _wait_ready (act.py:2617)      ← 动作【前】就绪等待（250ms 预算，不动）
 │    act: find_control (act.py:1923)      ← UIA 查找
 │    act: send_mouse (act.py:2089)        ← 注入
 │    act: _wait_effect (act.py:2675)      ← 动作【后】生效等待（800ms 预算，不动）
 │         ├─ 每轮 framecache.is_blank() ⇒ 退化**只打标**
 │         ├─ 每轮 framecache.diff_images() ⇒ 用**唯一那把尺子**
 │         └─ 第一次变化 ⇒ 存 first.png + stdout 一行 {"effect":{...}}
 ├─ core._parse_effect(out)   ← ★ 解析失败 ⇒ None ⇒ **回落**
 ├─ core._act_after(hwnd, before, effect, t_spawn)
 │     ├─ 回传帧存在 ∧ mtime ≥ t_spawn ⇒ **用它**（判定仍由 core 的 diff_images 下）
 │     └─ 否则 ⇒ **回落** framecache.wait_change（老路，300ms 预算）
 └─ degraded=true ⇒ **code=5**（unknown，永不当成功）
```

**判定权唯一性**：act **不传结论**（只传帧 + rounds + 退化标 + 耗时）⇒
「act 判、core 信」的分裂在**结构上不可能发生**（阶段一候选 A 被否决的那点，已消除）。

## 3. 失败口径矩阵（主控要逐条核的那张）

| 情形 | act 回传 | core 的动作 | 结果 code | 当成功吗 |
|---|---|---|---|---|
| 画面**变了** | `frame_ref` 存在、mtime ≥ t_spawn | 用回传帧 + **core 自己的** `diff_images` ⇒ changed=True | **0** | ✔ 成功 |
| 画面**没变** | 无 frame_ref（或无可用帧） | **回落** `wait_change` ⇒ core 判 changed=False | **8** | ⛔ 不当成功 |
| **退化**（空白/纯色） | `degraded=true` | 直接判 unknown | **5** | ⛔ 不当成功、**也不当「没变」** |
| **回传解析失败** | 解析不到 | **一律回落** `wait_change` | 由 core 自己判（8 或 0） | 绝**不**把解析失败当 changed=False |
| **帧不新**（mtime < t_spawn） | 有 frame_ref 但不新 | **回落** | 同上 | ⛔ 杜绝 R1（观测帧被误当动作后帧） |

## 4. 改前/改后端到端对照

| | 端到端 | core 侧 wait_change | 备注 |
|---|---|---|---|
| M11 基线（改前） | **1,682~1,718ms** | **321~343ms** | 两遍等同一件事 |
| **M12 阶段二（改后，实测 2 轮）** | **1,486.7 / 1,524.1ms** | **16.0 / 25.8ms** | ★ **core 不再等第二遍**；**净省 ≈184~195ms** |

★ **一个关键发现**（决定了合并到底省不省）：act 回传的帧**不只**是「第一次变化的那一帧」——
**画面没变时，回传「最后采到的那一帧」** ⇒ core 用**自己的尺子**判那张帧：
变了 ⇒ 成功；没变 ⇒ **code=8**（**不用再等第二遍**）。
⇒ **「画面没变」这一路（最常见）也省掉了 core 的 300ms**；若只回传「变化帧」，
画面没变时 act 没有帧可回传 ⇒ core 只能回落 `wait_change` ⇒ **一点都省不下**（这正是本单调试中踩到并修掉的坑）。

★ 判据终态（实测，原始输出 `_out_判据_正跑.txt` / `_out_判据_inject.txt`）：

| 模式 | 结果 | 说明 |
|---|---|---|
| **正跑** | **绿 7 / 红 0 ⇒ EXIT=0（绿）** | ② 合并已发生（core 侧 wait_change 16.0ms）＋ ⑥ 双实现已消除 ＋ ⑦ 退化检测 ＋ ⑧ 退化⇒code=5 ＋ ④ 没变⇒code=8 ＋ ⑤ unknown 不当成功 |
| **`--inject`** | **绿 7 / 红 1 ⇒ EXIT=1（红）** | ③ 假账被抓出：伪造「core 不再等第二遍」，但端到端并没有真的降到基线以下 |

⚠ 调试过程中被环境挡过两次（租约被占 ⇒ `code=10`；前台被锁）⇒ 判据按设计报「**环境受阻·验不了**」，
**绝不报绿**；租约已在判据收尾时**释放**（不占着主控的会话）。

## 5. 判据新增的三条断言（阶段二）

| 断言 | 判法 | 为什么这样判 |
|---|---|---|
| ⑥ **双实现已消除** | **行为级**：同一对帧喂 `act._img_diff` 与 `framecache.diff_images` ⇒ `changed` 必须一致；且 act 源码必须 `from agentctl import framecache` | ZCode 提的「同一对帧喂两个实现必须判同一结论」；**不许**判成一句注释 |
| ⑦ **退化检测存在且有效** | `framecache.is_blank(全黑图)` 必须 True | act 侧改前 grep `degrad/退化/BLANK` **0 命中** ⇒ 原来根本没有退化检测 |
| ⑧ **退化 ⇒ code=5** | 让 core 收到 `degraded=true` 的回传 ⇒ 结果 code 必须是 **5**（不是 0、不是 8） | 「退化 = 没测出来」≠「没变」≠「成功」 |

## 6. 未验项 / 已知限制（如实登记）

- ~~端到端数字未拿到~~ ⇒ **已拿到**（1,486.7 / 1,524.1ms，净省 ≈184~195ms；判据 exit=0）。
- act 侧现在用**全尺寸帧**做判差（`framecache.diff_images`）⇒ **每轮判差更贵**（M11 实测全尺寸 40.96ms/轮 vs 降采样判差 0.74ms）
  ⇒ act 侧轮询成本**上升**；端到端净收益**待实测**（省 321~343ms 的 core 那一遍，但要减去 act 判差变贵的部分）。

- 冻结态（`AgentCtl.exe`）下子进程可能**取不到 `agentctl.framecache`** ⇒ act 只采样不判 ⇒ core 回落 `wait_change`
  （**多等 300ms，但不误判**）—— 这是**有意的失败安全**，不是 bug。
- `AGENTCTL_SNAP_DIR` 指向**临时目录**，core 收摊后**未删**（留给判据/取证用）⇒ 下次进程启动会清（`tempfile` 目录在 `%TEMP%`），
  但**本轮没做收摊清理** ⇒ 登记为待办（阶段二收尾时删）。
