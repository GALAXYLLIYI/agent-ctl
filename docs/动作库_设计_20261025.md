# 动作库设计（2026-10-25 · M2 骨架）

> **动作库 = 手脚的记忆**：一个技能是一段**可回放的记忆** —— 在某应用、某窗口上按顺序做几步，
> 每步都要「找得到」且「做完符合预期」。本层只管**形状**与**回放纪律**；
> 真正的手脚（点/敲/读）由**注入进来的 executor** 做。
> 边界：**不接真 UIA**（不 import core/gate，不发输入、不截图）、**零 IO**、**只用标准库**。
> 代码：`src/agentctl/skills.py`｜判据：`tests/_P3_技能库_判据.py`

## 一、结构（纯数据 dict，JSON 友好；字段顺序 = 序列化顺序）

```
skill = {name, app, window_fingerprint, steps:[...], stats:{runs, ok, avg_ms}, version}
step  = {action, selector:{name, type}, expect:{属性: 期望值}}
```
- `make_skill(...)` 是**唯一合法入口**（内部过 `validate`）；`validate(skill)` 校验**外来**数据：
  缺字段 / 未知字段 / 未知 action / selector 空 / `expect` 类型不对 ⇒ `ValueError`（中文、带字段名）。
- 已知动作词表 `KNOWN_ACTIONS` = `ctl_click/ctl_type/ctl_fill/ctl_focus/ctl_browser`
  （与 `action_guard_policy.json` 的 `action_tools` 对齐；**刻意不读那个 JSON** ⇒ 离线可测、代价靠人同步）。
- `stats.ok` = **成功跑过几次**（≤ `runs`），**不是**「记了几步」；步数看 `len(steps)`。

## 二、回放必验（`replay(skill, executor, guard=None)`）

每步**按序**过四道，**任一不过就停**（停了就不再往下走）：
1. **定位先于执行**：`executor.locate(selector)` ⇒ 失败 ⇒ **立即停**（找不着还往下走 = 在乱点）。
2. **执行**：`executor.perform(action, element)` ⇒ 失败 ⇒ 停。
3. **期望**：`expect` 是纯数据，由本模块做字典比较（不接 UIA ⇒ 只做比较）⇒ 不满足 ⇒ 停。
4. **「没测出来」≠ 成功**：属性**取不到** ⇒ 判词「没测出来」；取到但对不上 ⇒ 「期望不满足」；两种都 `ok=False` —— **绝不把「没测出来」当成功**。

结果字段：`ok` / `verdict` / `reason` / `step`（**0 基**索引）/ `step_no`（1 基）/ `steps_done` / `total_ms` / `steps[]`。

## 三、过闸（两道，都在动手之前）

- **`guard(skill, step)`**（可选回调，模拟真实闸门）：**在定位之前**调用 ⇒ 返回 False ⇒ **一步都不做**就停
  （判词「闸门拒绝」）。guard 抛异常也按拒绝处理（宁停不错）。
- **窗口指纹核对**（可选）：executor 若提供 `fingerprint()`，必须与 `window_fingerprint` 一致，否则停
  （判词「窗口指纹不匹配」）—— **记忆得用在对的地方**。

## 四、版本指纹

- `version` = **结构版本**（改结构就 +1）：回放结果原样回显 `name/app/window_fingerprint/version`，
  便于对账「这轮跑的是哪一版记忆」。
- `window_fingerprint` = **场景指纹**：把「在哪个窗口上做过」钉死；配 executor 的 `fingerprint()` 才能真正核。

## 五、失败模式（判词全集 `VERDICTS`）

| 判词 | 何时 | `ok` | 停在哪 |
|---|---|---|---|
| 完成 | 全部步骤过 | True | — |
| 定位失败 | `locate` 返回 ok=False | False | 该步（`steps_done` = 已完成步数） |
| 动作失败 | `perform` 返回 ok=False | False | 该步 |
| 期望不满足 | 属性取到了但对不上 | False | 该步 |
| 没测出来 | 属性**取不到** | False | 该步 |
| 闸门拒绝 | `guard` 返回 False / 抛异常 | False | 该步（一步都没做） |
| 窗口指纹不匹配 | 现场指纹 ≠ 技能指纹 | False | 开始前 |

**共同点**：失败一律 `ok=False` + 给出**中文原因** + 指出**停在哪一步**；「没测出来」与「不满足」**分开**
（不混成一个「失败」），更不许折成成功。

## 六、提炼与存盘

- `record_from(steps_log, name, app, fingerprint)`：从动作日志提炼技能 —— **只留成功动作**、保持顺序、
  统计耗时；日志里有未知 action ⇒ 直接报错（不许攒出跑不起来的技能）。
- `save_skill(skill, path)` / `load_skill(path)`：**路径由调用方给**（不猜路径、不读仓内布局）；写前/读后都过 `validate`。

## 七、本层**没有**做的事（留给下一层）

不接真 UIA（不定位真实控件）、不定义「怎么找元素」的算法、不做技能检索/择优、不碰权限/闸门本体（只留 `guard` 钩子）、不落盘到仓外路径（路径由调用方给）。
