# msvcp140.dll 再分发 · 决策材料 · 2026-10-23

> **一句话**：**这件事不需要用户拍板了** —— 找到了解法 **C-0**：
> **不随包分发 `msvcp140.dll`，改用目标机系统自带的那份**（本机实测**删掉后 OCR 照常跑通**）。
> winrt 本身是 **MIT**（明确允许 modify / distribute）⇒ 删掉 wheel 里那个 DLL **许可上允许**；
> 一个微软专有二进制都不发 ⇒ 微软那条 "limited to licensed Visual Studio users" **不触发**。
> ⚠ 连带要做两件事：① `install.ps1` 检测目标机有没有 VC++ 运行库，缺就**指引去微软官网装官方 vcredist**
> （我们**不分发**它，只指路）；② **cp312 硬伤要单独一刀**（§五 —— 它比许可问题更致命）。

---

## 一、事实（逐条可核）

### 1.1 微软条款原文（仓内逐字存着：`vendor\winrt\msvcp140-LICENCE`）

- Microsoft Learn《redistributing-visual-cpp-files》：
  > "Distribution of the Visual C++ Runtime Redistributable package, merge modules, and
  > **individual binaries** is **limited to licensed Visual Studio users** and is subject to
  > Microsoft Software License Terms."

- VS2019 REDIST 清单：
  > "Subject to the License Terms for the software, you may copy and distribute with your program
  > any of the files within the following folder and its subfolders except as noted below.
  > **You may not modify these files.**"
  > 对应目录 `[VisualStudioFolder]\VC\redist`（`msvcp140.dll` 就在里面）。

- VC++ V14 REDISTRIBUTABLE and RUNTIME（EULA ID: `Cpp_v14_ENU.1033`）：
  `INSTALLATION AND USE RIGHTS` 允许 "install and use any number of copies of the software"；
  `SCOPE OF LICENSE` 里有禁止 "distribute the software" 的表述，但被 `TERMS FOR SPECIFIC COMPONENTS`
  与上面那份 REDIST 清单给出了例外。

> ⚠ **关键读法**（子代理核出来的，**推翻了我原先的直觉**）：
> **"Redistributable package" 与 "individual binaries" 是并列的**，**同在** "limited to licensed
> Visual Studio users" 之下 ⇒ ⇒ **换成微软官方 vcredist 里那一份，一样要拍板**。

### 1.2 我们这份 DLL 的现状

| 项 | 值 |
|---|---|
| 路径 | `vendor\winrt\msvcp140.dll` |
| 大小 / 版本 | 567,352 B / `14.29.30157.0` |
| SHA-256 | `75872c426555ac8af55b5a7f6d4aea8831af74353b22612850a2bfc40e3b67e1` |
| 是否修改过 | **否** —— 与 `winrt_runtime-3.2.1.dist-info/RECORD` 登记的 sha256 完全一致 |
| 来源 | **PyPI 官方 wheel `winrt-runtime 3.2.1`** |
| 为什么必须在包里 | 它是那个 wheel 的组成部分，且 `vendor\winrt\*.pyd` 直接依赖它 |

### 1.3 winrt 的许可是 MIT ⇒ 删掉 wheel 里那个 DLL 许可允许

`vendor\winrt_runtime-3.2.1.dist-info\licenses\LICENCE`：
> "Permission is hereby granted, free of charge, to any person obtaining a copy of this software …
> to deal in the Software **without restriction, including without limitation the rights to use, copy,
> modify, merge, publish, distribute, sublicense, and/or sell** copies … The above copyright notice and
> this permission notice **shall be included in all copies or substantial portions** of the Software."

⇒ 允许**修改 + 再分发**（保留 MIT 声明即可）⇒ ⇒ **从 `vendor\winrt\` 里删掉 `msvcp140.dll` 不违反 MIT**
（那个 DLL 本来就不在 MIT 覆盖范围内 —— 它是微软专有件）。

### 1.4 产品真的依赖 winrt ⇒ "干脆不发 winrt"不可行

| 模块 | 对 winrt 的依赖 | 证据 |
|---|---|---|
| `src\agentctl\ocr.py` | **winrt-only，无兜底** | 它是**产品主 OCR 链路**（`core.py:5331` 调它） |
| `src\agentctl\eye.py` | **winrt-only，无兜底** | 同上 |
| `src\agentctl\clock.py` | 双路（winrt 首选 / PowerShell 兜底） | 实测 winrt **10.70ms** vs PowerShell **480.81ms**（n=20，自造 PNG）⇒ **≈45.7 倍**；且 **PowerShell 路径不输出 `bounding_rect`** ⇒ 词框口径补不上 |
| `src\agentctl\_bundled_deps.py` | 探测 5 个 winrt 子模块 | — |

⇒ ⇒ **去 winrt = 主 OCR 整体失效**（不是"变慢"）⇒ **D 方案不可行**。

## 二、方案对比

| 方案 | 做法 | 许可 | 功能 | 可移植性 | 工作量 | 判定 |
|---|---|---|---|---|---|---|
| **B** | 保留 vendor 那份，分发者**自持有效 VS 许可** | **需用户拍板 / 自证** | 无损 | cp312 硬伤仍在 | 0 | ❌ 把决策甩回给用户 |
| **C** | 换成微软官方 vcredist 里那一份 | **仍需拍板**（package 与 individual binaries 并列） | 无损 | 不解 | 中（RECORD / 哈希 / 许可正文全要重算） | ❌ 不划算 |
| **C-0** | **不发 `msvcp140.dll`，用目标机系统自带那份**；`install.ps1` 检测缺失 ⇒ **指引**微软官网装官方 vcredist | **不触发**（一个微软专有二进制都不发） | **无损**（本机实测删掉后 OCR 照常跑通，走 `System32\msvcp140.dll` 14.51） | 不解 | **小**（删 1 个文件 + install.ps1 加检测 + NOTICE 更新 + 配判据） | ✅ **推荐** |
| **D** | 去 winrt 依赖，只留 PowerShell 兜底 | 不触发 | **主 OCR 失效**、OCR 慢 45.7 倍、PS 不出词框 | 解 cp312 | 大 | ❌ 不可行 |

## 三、C-0 的落地清单

1. `vendor\winrt\` 去掉 `msvcp140.dll`；同步更新 `vendor\NOTICE.md` 与 `THIRD_PARTY_NOTICES.md`
   （写清"我们分发的 winrt 不含那个微软件"）。
2. `install.ps1`：安装时检测 `%SystemRoot%\System32\msvcp140.dll`；
   缺 ⇒ **提示用户从微软官网下载官方 VC++ Redistributable**（**我们不分发它，只指路** ⇒ 不触发再分发条款）。
3. **出包后核验** `dist\agentctl.zip` 里**没有** `msvcp140.dll`（PyInstaller 不许从 `System32` 又收进去）——
   ⚠ **正在核**（见 §六）。
4. 配判据（① 包里没有该 DLL；② install.ps1 有检测与指引；③ 注入必红）。

## 四、对用户的影响

- ✅ **不需要你拍板了** ⇒ 唯一卡着"能不能对外发包"的这一项**解除**（前提是 §三 落地并复核）。
- ⚠ **仍需你知道一件事**：**cp312 硬伤**（下一节）—— 它比许可问题更致命。

## 五、★ cp312 硬伤（比许可更致命，建议单独一刀）

| 事实 | 值 |
|---|---|
| vendor 里 7 个 wheel 的标签 | 全是 **`cp312-cp312-win_amd64`**（**非 abi3**） |
| 实测加载 | **Python 3.12 OK / 3.14 `DLL load failed`**（cp312 ABI 硬绑定） |
| `install.ps1` 的 Python 下限 | **3.10**，候选含 `py -3` ⇒ 本机 `py -3` 解析到 **3.14** |
| 额外坑 | vendor **抢占 `sys.path[0]`** ⇒ 即使 3.13 上 pip 装好了 winrt，也被 cp312 那份抢占 |
| 额外坑 | `typing_extensions` 是 winrt 的**运行期依赖但 `requirements.txt` 漏列** |

⇒ **影响面**：许可问题只卡"对外发包"；**cp312 卡所有用户**（现在默认发 3.14）。
⇒ **建议**：`install.ps1` **钉 Python 3.12**（找不到就**明确报错**，不要静默用 3.14）；
后续再考虑 vendor 多版本（工程量大，另开一单）。

---

## 六、诚实的边界（不许把"待核"说成"已核"）

- **微软条款的独立判读没做成**（官方页正文抓取被截断）⇒ 本文的全部引用**来自仓内逐字存着的官方原文**。
- ⚠ **C-0 的"打包链不会从 `System32` 又收进去"正在核**（子代理在查 `build\*.spec` 并实跑出包）⇒ **核完才能落地 §三**。
- **干净机（完全没装 VC++ 运行库）的行为未实测** ⇒ §三.2 的检测与指引就是为这条兜底。
- **冻结 exe 是否被 PyInstaller 重新收进 `msvcp140.dll`** 未出包验证。
- `ocr.py` / `eye.py` 的硬软依赖按"函数体 + 调用方"两处合看，**未追完所有调用方**。
