## 三、改动清单（**只改真源**，产物一律由 gen_legacy 生成）

### 3.1 新建：`src\agentctl\authdir.py`（唯一规则定义处）

```
ENV_KEY = "AGENTCTL_AUTHDIR"
resolve() -> str
  1) AGENTCTL_AUTHDIR 非空 ⇒ 用它（expanduser + abspath 绝对化）
  2) 否则默认 %LOCALAPPDATA%\AgentCtl\_auth（= _APP_DIR/_auth，与 BRAKE_FLAG 同家；_APP_DIR 认 AGENTCTL_APP_DIR 覆盖）
读取侧**不创建**目录（只如实返回路径）；写入侧由各调用方惰性创建。
```

- 只定义规则，**不含**任何闸门逻辑、不含 I/O 副作用。
- 放 `agentctl` 包内（新线自己 import 它），老线**不能**依赖它（随包执行层不能反过来依赖 `src\`）⇒ 老线那侧内联同规则（见 3.3）。

### 3.2 改：`src\agentctl\gate.py`（新线闸门）

| 处 | 改前 | 改后 |
|---|---|---|
| `AUTHDIR`（现 L395） | `os.path.join(HOME, "_auth") if HOME else None` | `authdir.resolve()`（**恒为绝对路径**） |
| `PASSFILE/LOCKFILE/LEASE_DB/CAPTURE_DB/LOG` | `... if AUTHDIR else None` | 恒有值（`AUTHDIR` 不再可能为 None） |
| 文件头「⚠ 已知分歧（未修，待 DSH 裁）」段 | 说「两份 AUTHDIR 解析方式不同，要修不能各改一半」 | **删掉**（§7.2.2 明确要求「删掉新线『已知分歧（未修）』注释」） |
| `BRAKELOG` 处的 `AUTHDIR or _APP_DIR` 兜底 | 注释说「AUTHDIR 为 None ⇒ 整模块 import 拉崩」 | 保留表达式（不改行为），**补注释**说明 AUTHDIR 现在恒有值 ⇒ 该兜底不再可能触发 |

- `HOME` / `_resolve_home()` **一个字不动** —— 它管的是「老脚本在哪」，不是「账本在哪」（两件事，别混）。
- 不改档位常量、错误码、计数语义、租约/急停/敏感窗逻辑（属 S3）。

### 3.3 改：`legacy_tools\_src\gate.py`（老线闸门真源）

- 新增一个**内联同规则**的解析函数（与 3.1 逐条对应），`AUTHDIR` 改为走它。
- 顶部「★ 已知分歧（待 DSH 裁）——两本账」注释改写：说明三方现在同源，并指向 `src\agentctl\authdir.py`。
- 老线那侧为什么是「内联」而不是 import：老线是**随包执行层**，不能反过来依赖 `src\`（S3 之前的老约束）。
  ⇒ 但它**不是手抄一份了事**：它在 `legacy_tools\_src\gate.py` 里，**由 gen_legacy 纳入生成 + 台账对账**
  （`_md5台账.md` 里 `gate.py` 条目的 md5 会随之变化 ⇒ P8 的机器盯防照样生效），
  两边等价性由 **J1 判据**守着。

## 四、判据计划（J1–J3 登记进 `run_all.CRITERIA`，45 → 48）

| 编号 | 文件 | 判什么 | 退出码口径 |

| **J2** | `tests\_authdir注入必红_判据.py` | **J1 的注入必红**：把 auth_popup 的解析**在临时副本里**改回写死 `BASE/_auth`（= 当前病灶）⇒ J1 必须判红并点名；恢复后（现役树）必须绿 | 正跑 0（自证成立=绿） |
| **J3** | `tests\_空读不写回_判据.py` | **原 S1 的判据保留**：沙箱 AUTHDIR 里构造**半截/损坏**的 `auth_pass.json` ⇒ 两侧 `gate.require()` 必须 `GateDenied` 且**该文件字节不变（md5 前后相等）**；另加**瞬时读失败**子例（第二次读失败）—— 那是老线 D18·R2 守卫真正保护的那一格 | 正跑 0 |

- **J1 的注入口径**：J1 自带 `--inject`（注入到 `%TEMP%` 副本，现役一个字节不动）⇒ `run_all --inject` 里它是「如期变红」，即**判据是活的**。
- **J2 的注入口径**：J2 的正跑**本身就是注入自证**（注入=它的动作，断言=「必须红」）⇒ 输出 `NO_INJECT:` 声明，不进 INJECTABLE 栏。
- **J3 的注入口径**：`--inject` = 在**临时副本**里**摘掉老线 D18·R2 守卫** ⇒ 瞬时读失败那一格必须变红（证被打残、文件被改写）⇒ 证明这条判据有牙。
- **沙箱纪律**：三条判据一律 `AGENTCTL_AUTHDIR=%TEMP%\…`，**不碰用户正在用的 `_auth`**；不重启任何进程；不碰 QQ 窗口。
- **先红后绿**：实现顺序 = 先落判据（对着**改前**的代码跑 ⇒ J1 必红，因为三方现在两本账）→ 再改代码 ⇒ 转绿。**红的那一跑留档在交卷里。**

   ⇒ 在那之前，live 跑的仍是老口径（两本账照旧）。
