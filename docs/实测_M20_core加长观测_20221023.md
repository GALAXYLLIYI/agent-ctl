## 三、「确认没变」语义怎么保住的（为什么不会变成一律 code=5）

四道闸，全部在**产品代码**里，判据逐条钉住：

1. **触发条件收窄到一格**（`core.py:2990-2992`）：`if (df or {}).get("changed") is not False: return` ⇒ 只有 `changed is False` 那一格进得来。成功格（True）、退化格、没测出来格（None）**根本进不了函数体**。
2. **升级要过三道底座**（`core.py:3027-3050`）：
   - ① `framecache.wait_change` 报 `changed is True`（自带 `HYSTERESIS=2` **连续 2 帧**滞回 ⇒ 闪烁不误判）；
   - ② **复核判差** `_act_diff_of(before, _img, win_off, ignore)` 再次确认 `changed is True`；
   - ③ **口径守卫** `before.size == _img.size`（因 `framecache.diff_images` 在尺寸不同时**直接判 changed=True**，`framecache.py:515-519` ⇒ 不守卫就是假成功）。
3. **观测失败 ⇒ 判词不动**（决策 D2）：抓不到帧 / 抛异常 / 复核不通过 / 尺寸不同 ⇒ **原样返回** `_out`，`_df` **不被替换** ⇒ 仍 code=8。**不降级成 None、不降级成 code=5**。
4. **`_picture_verdict` 一字未动**：签名 `(r, df, degraded=False, what="动作")` 与三态语义（True→原样/0、False→code=8、None→code=5）完全保留（自检 2：仍 3 处；判据 A3/A4/A7/A8 直接按位置参数调它）。

**注入自证（判据 `--inject` = 1）**：I1「一律升级」⇒ A3 红；I2「一律观测」⇒ A1 红；I3「一律 code=5（乙案误接线）」⇒ A3 红。⇒ **判据有牙**：把甲案改坏或改回原样，它当场就红。

### 4.2 真实预算口径

- **预算值**：传给 `framecache.wait_change` 的 `budget_ms = ACT_EXT_OBSERVE_MS = framecache.WAIT_BUDGET_MS = 300`（**直接引用既有常量，源码可核；全仓没有一个新数字**）。
- **最坏等待**：预算 300ms + 最后一轮超支（抓帧 24 + 判差 12.2）⇒ **≈ 331ms**（判据 A10 上界 336.2ms）。
- **提前检出（慢应用被救回）**：变化在窗口内出现 ⇒ 命中即停，实测 **≈ 282ms**（第 4 帧）；若变化出现在窗口一开始 ⇒ `50 + 2×36.2 + 25 ≈ 147ms` 检出（施工图 §三 A2 口径）。
- **相对量**：现状「画面不变」的生产 `ctl_click` 端到端实测 1,686.4 / 1,765.1 / 1,791.2 ms ⇒ **+330ms ≈ +19~20%**。
- **最坏路径**：act 回传不可用时 core 已回落等过 300ms，甲案再加 ~331ms ⇒ 该路径总等待 **≈ 630ms**（罕见路径，未改 `_act_after`）。
- ⚠ **诚实点（R1b）**：M12 合并曾在「画面不变」这条路上省掉 core 的第二遍等待（实测 321~343ms）⇒ **甲案在同一条路上把这 ~330ms 又还了回去**。这不是免费的，是一次明确取舍（主控核稿 §七 已列为「要用户点头」的那一条）。

### 4.3 快路径零成本证明（三层）

1. **结构层**：`_act_extend_observe` 的第一个分支就是 `if (df or {}).get("changed") is not False: return _out` ⇒ **在调用 `wait_change` 之前**就返回 ⇒ 成功路**连 `capture_client` 都不碰**。
