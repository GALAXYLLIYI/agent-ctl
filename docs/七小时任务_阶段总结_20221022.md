## 四、★ 本轮挖出的三个真缺陷（比性能数字更值钱）

### 4.1 锁嵌套死锁（M8 首次交付自带，主控复跑抓到）

真源 `append` 内部加跨进程锁，而 M3 判据自带的参考实现 `RefStore` **继承真源**、外层又套一把 `FileLock`
⇒ 同进程对同一锁文件套两把锁，`msvcrt.locking` 按文件句柄/字节区间计 ⇒ **第二把永远拿不到**。

**修法**：锁必须**可重入**（模块级持有计数，只由第一个进入者真正加锁）+ **拿不到锁必须超时抛错**（不许无限等）。
⇒ 修完判据能跑完，参考实现三条契约全立。

**教训（比缺陷本身重要）**：**尺子与被测物耦合**——参考实现继承真源，真源一改，尺子的行为就跟着变。
凡是「继承真源的测试替身」，真源改动必须连带复跑，否则会死锁给你看。

### 4.2 跨日轮转 seq 起点撞号（M8 附带查出的下一个缺陷）

`timeline-20261021.jsonl` seq = 3072..3402，而 `timeline-20261022.jsonl` seq = **3337..3896**
⇒ 两文件在 **3337..3402 撞号 66 条**。

**连带纠正了判据的一条错误假设**：
判据 ⑨ 断言「jsonl 行数 − sqlite 行数 == 重复 seq 条数」，本轮实测 **4216−3974 = 242 ≠ 320**
⇒ **等式不成立 ≠ 还有别的丢失机制** ⇒ 差额 242 才是真正被 `INSERT OR REPLACE` 覆盖丢掉的，
而 320 里混着轮转重号。**这条断言在有跨文件重号时不成立**（下一个单要修判据口径）。

### 4.3 长驻进程持旧代码（**本轮最隐蔽的一个**）

Python 进程**启动时**就把 `store.py` 加载进内存 ⇒ 改了 `src` 对已在跑的进程**无效**。
现场写 timeline 的是：`agentctl.mcp`（stdio 型，窗口D 拉起）、`agentctl.mcp_http`（看门狗拉起）、
`brake_daemon` ×2。

⇒ **主控已执行重启**（mcp_http 22244→41904，brake_daemon 25148/25192→30068；
`agentctl.mcp` 是 stdio 型，下次会话自动生效）⇒ 重启后新写入的 seq 严格递增无重号。

**教训**：M7 已经发现过一次同类问题（live 的 act.py 比仓内旧 2 天、仓内 10-21 的改动从没进过 live）。
**「改了仓库」≠「用户环境生效」** —— 部署链必须进交付清单，不能当隐形步骤。

### 8.1 ★ 新查到的一条最对口的：**「正确但迟到」是决策关键路径问题**（arXiv:2607.28399）

**AAPT（Adaptive Anticipatory Policy Trees）**，2026-07-31：

- **问题定义**：GUI agent 在瞬态事件上「动作是对的，但等它想完，窗口已经关了」。
  作者把原因定位为 **决策时间关键路径上的自回归解码延迟**，并用**受控操纵**证明：
  不是「没预见到」，而是「**预见对了但算得太慢**」。
- **做法**：屏幕安静时让同一个冻结模型**预编译**一棵小策略树（可观察 guard + 预授权动作 + 每分支 deadline），
  树的大小按模型自己的解码延迟来定；事件到来时，一个**轻量观察者**（严格 token 预算，路由调用约 **325ms p50**）
  只做一件事 —— 匹配该走哪个分支并触发**已预授权**的动作；**树外的一切停下来重新规划**。
- **效果**：配对试验（预注册端点 + 精确 McNemar 检验）下，争议窗口内成功率 **0.50 → 0.79**（p=1.8e-3），**无错误动作**；
  在独立多模态模型上 126 次配对试验复现（p=4.9e-13）。
- **边界（作者自己给的）**：预编译树**只在候选动作可以事先枚举时赢**；不可枚举时反应式执行更强。

**⇒ 对 agentctl 的可迁移性（本轮新得的判断）**：

1. 本轮砍的是**执行/感知层**延迟（750ms → ~500ms 量级），**决策层延迟不在 agentctl 里**（在 窗口D / 本地 agent / MiniMax Code 那侧）。
2. 但 AAPT 提示了 agentctl 可以提供的**加速原语**：
   **把「动作决定」提前，用本机已有的逐任务通行证做预授权** ⇒ 事件到来时执行的是**已授权动作**，不必重新问模型。
   这与本机三闸天然兼容：**预授权有边界（逐任务通行证）、树外即停（unknown 永不当成功）**。
3. ⇒ **下一轮的一个具体方向**：给 agentctl 加一层「**预置动作 + guard 路由**」能力
   （例：观察到窗口标题/控件出现 ⇒ 直接执行已授权动作），把「感知→决策→动作」里的决策段移出关键路径。
   ★ 但要注意作者给的边界：**只适合候选动作可枚举的场景**（菜单项、固定工具栏、固定流程），
   不适合开放式任务。
4. 另一条同族文献 **arXiv:2610.14228（潜空间世界模型）**：把未来画面预测从像素重建改到潜空间，
   推理延迟降最多 **98.9%** ⇒ 「预测下一帧」这条路本机**不要走**（要训模型），
   但它反证了「像素级未来预测」是**贵**的 ⇒ 印证本轮「先省重复感知、不建世界模型」的路线。
