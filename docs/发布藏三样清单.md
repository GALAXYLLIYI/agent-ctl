# 发布藏三样清单（对外契约面裁剪 · 2026-10-18 窗Y）

> 原则：**藏 ≠ 删行为**。内部专家与判据还要用这些能力，裁的是"公开契约面"——
> 工具注册表、契约描述、文档示例三处同步收，缺一处就是没藏。
> 实施归属：`contract\tools.json` 的裁剪属后续施工单（本单只给清单，未动契约）。

| # | 藏什么 | 现在暴露在哪 | 建议处置 | 理由 |
|---|---|---|---|---|
| 1 | `ctl_task` 派单面 | 契约工具表含 `ctl_task` | **藏到开关后**：工具注册表按 `AGENTCTL_EXPERT=1` 过滤，公开契约不含此条；文档删示例 | 定位 §六："派单是用户的工作方式，不是产品能力"。对外暴露一个派单工具=邀请别人把内部工作流当 API 用 |
| 2 | `must_vlm` 升级叙事 | 契约 `ctl_screen.description` 的 channels 段、`must_vlm` 字段、docs 叙事 | **删叙事、留行为**：字段保留但描述只写"三条结构化通道都未命中时如实报'必须人看'"；删"将接入/升级"类措辞；R1/R3 未接线照实报 false | 定位 §六："未接线就是假承诺"。对外许诺一个不存在的能力=假承诺 |
| 3a | `ctl_keys` 数值 vk 入口 | `_resolve_vk`（core.py）收十进制/十六进制数值 | **删**：公开面只留键名白名单，vk 数值入口移除（键名表已覆盖导航/编辑/字母需求） | core.py 注释原文：16 位 vk 空间绝大多数是"切窗/截屏/锁屏"，数值入口=把整张表递出去 |
| 3b | `ctl_type mode="focus"` + `allow_foreground` | I0 冻结接口的新能力（P0 输入通道） | **藏到开关后**：公开契约不出现在 `input_schema`（或 `expert: true` 标记 + 注册表过滤）；内部与判据照用 | 无元素直发 + 显式抢前台 = 自由输入面，公开即"能往任何前台窗灌任意字符"；P0 刚修通，能力要留、面要收 |
| 3c | `ctl_browser launch\|close` | 契约工具表 | **藏到开关后**（同 3a 机制）或**删 launch**（只留 follow/close 已开实例） | `launch` = 用任意命令行拉起外部进程的口子；对"动作闸门"定位是面不是功能 |

## 一致性检查（实施时的验收）

1. 公开 `contract\tools.json` 里 grep 不到：`ctl_task` / `must_vlm 升级` / `mode` + `focus` / 数值 vk 示例 / `ctl_browser.*launch`；
2. `AGENTCTL_EXPERT=1` 时五样全数回归（内部判据不降级）；
3. `docs\` 与 README 无三样的使用示例（README 已按本单先行清理）。
