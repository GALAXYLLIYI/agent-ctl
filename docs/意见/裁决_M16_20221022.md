## 一、先认账：**≤900ms 这条验收线是我定错的**

主控 2026-10-22 12:30 定这条线时，假设「把确定性成本都砍掉就能到 900ms」。
实测证明**不成立**：「确认没变」这条路的**物理地板**就在 900ms 上下 ——
**450ms（动作后等变化预算，铁律不许改「等多久」）＋ ~200ms（spawn+import）
＋ ~120ms（抓帧 ×3）＋ ~160ms（core 前置+回读）≈ 930ms**。

⇒ **这条线作废**，改成三档口径（执行者已按此如实报数，做得对）：
- 达标（≤900ms）：需动 450ms 等待预算 ⇒ **本轮不碰**（见 §四）；
- 可达（≤1000ms）：若还能再砍 ~130ms；
- 实际：**逐段账单 + 地板推算**（已交，p50 改前 1572.2 → 改后 1533.1，差 −39.1ms）。

## 二、★ 主控独立核实后的一处口径纠偏（执行者第一版量错了路）

执行者第一版探针走的是 **xy 点击**（无 eid、无 verify_expect），而：
- **A（双 spawn 消除）** 只在**声明了 verify_expect** 的动作上生效；
- **B（动作后 UIA 按需化）** 只在 **ok 且 eid 命中**的点击上生效。

⇒ **那 39ms 基本只是 D（懒加载）的体现，A 与 B 的收益一次都没被量到。**
★ 这与 M12 那一轮主控自己翻的车同源：「**测过的 ≠ 生效的**」。

⇒ **要求补三个测量用例**（每个都给 p50/p95/逐段/守门率）：
① **eid 生产链**（ctl_screen → objects[] → ctl_click --eid --from_capture）—— B 的收益只在这条路上兑现；
② **点击真的生效**（code=0 早停）—— 这是多数真实动作的形状，「没变」是病态最坏情况；
③ 现有 xy 没变组（对照）。
另：改前/改后两次的**置前方式不同**（SetForegroundWindow vs AttachThreadInput）⇒ **未控变量**，请统一后重跑。

## 三、B（动作后 UIA 重扫按需化）的裁决：**不在 M16 上线，但给一个更安全的形状**

执行者登记：定向查询净省上限 ≈130~140ms（够不到派单的 ≥150ms 线）、
对坐标点击场景贡献 0、且**复刻 walk 保口径会让三档判词变弱** ⇒ 登记待裁。
**主控同意这个判断**（不许拿判据强度换 130ms）。但**否决「就此搁置」**，给形状：

**下一单的形状（不是 M16）**：
- **不回读**，而不是「定向查询复刻 walk」：
  没声明 `expect_uid` 时**不做动作后回读**，`after.uid_state` 写
  **unknown** + 明写「**未做动作后回读（未声明 expect_uid）**」；
- ⚠ **绝对不许**把「没测出来」写成「没变」(OK) —— 那是撒谎；
- ⚠ **声明了 `expect_uid` 时回读照做，三档判词必须与改前一致**（要有对照判据）；
- 判据：① **eid 路上**省 ≥150ms（这才是 B 的兑现场景）
  ② `uid_state` 是 unknown + 明写未回读 ③ **不许**出现「没测出来」被写成「没变」
  ④ 有「声明 expect_uid ⇒ 三档判词不变」的对照。

## 四、450ms 等待预算：**主控定：不碰**

- 缩短它会把「确认没变」的判据**变松**（本来就慢的应用——加载、动画、远程桌面——
  更容易被判成「没反应」⇒ agent 以为没点到而重试 ⇒ **可能反而更慢，甚至点错**）；
- 那是拿判据换速度，违反「失败口径零松 / 永不当成功」；
- ⇒ **本轮与下一轮都不动 450ms**；若要动，**须用户拍板**，并同时给出「慢应用误判率」的实测。

## 五、D1（spawn+import 懒加载）的裁决：**改形状，可以做**

执行者登记：28.5ms 全在 **tkinter 探测**（act 自己从不用 tkinter）；
「唯一省法是改『tkinter 缺失 ⇒ act.py 启动即退』这条闸门口径」⇒ 口径变化，登记待裁。

**主控核实了代码，发现「唯一省法」这个前提不成立**（legacy_tools/_src/act.py）：

| 事实 | 位置 |
|---|---|
| `_collect_selftest()` 在**模块加载时**就真 `import tkinter` 探一次 | :105 |
| 探测**必须在** `import win32gui` **之前**跑（否则第一项缺失就 ModuleNotFoundError 打死进程，后面的项没机会报） | :506-509 |
| 「自检没过 ⇒ 立刻拦停」 | :511-513（`_SELFTEST_MISS` 非空 ⇒ rc=11 一次报全） |
| tkinter 其实**只被「授权弹窗」需要** | :96「tkinter（授权弹窗 auth_popup.py 依赖）」 |

⇒ **不必改闸门口径**：把「**真 import 探存在**」换成 **`importlib.util.find_spec("tkinter")`**
（探「**在不在**」，不执行模块）⇒ **缺件清单语义一模一样**，但省 ≈28.5ms/动作。

**判据（可核）**：
1. 普通点击路径跑完，**`sys.modules` 里没有 `tkinter`**（证明没真导入）；
2. **缺 tkinter 的机器上，自检仍报出该项**（用屏蔽 tkinter 的 PYTHONPATH 验）⇒ 清单没少项；
3. 正常机器上**一切不变**（判据全绿 + MD5 口径不变）；
4. ⚠ 若 find_spec 说「有」但真 import 失败（残缺安装）⇒ **由弹窗那条路的真实 import 报错**，
   不在启动闸里假装「有」。
