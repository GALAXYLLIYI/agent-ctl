## 三、主控补的三条**实测**（ZCode 没有的数据）

1. **OCR 整客户区 1120ms**（本机实测，2542 宽客户区，`zh-Hans-CN`）
   ⇒ 裁剪后 42~58ms（M6 实测）⇒ **必须只对变化区/命中区做 OCR**，不能整屏。
2. **`ocr_window(rect=)` 的两条抓图路径口径不一致**（主控实测）：
   `grab_client` 的 PrintWindow 路径返**逻辑尺寸**图、ImageGrab 回退路径按**物理矩形**抓；
   实测两条路径同一窗口的 `words` 坐标差 **~5px**（文 x=31 vs 36）。
   ⇒ **喂 diff bbox 之前必须先统一口径**（ZCode Q3 的 (a) 方案正是为此），否则会差 1.5 倍或 5px。
3. **UIA 侧有个现成机制**：`framecache.py:191 client_origin(hwnd)` +
   `framecache.py:714 STORE.put(token, hwnd, img, origin=…)` ⇒
   **「bbox 与同一帧的 origin 绑定」这件事机制已经在了**，不必新造。

## 四、M15 的判据必须断言什么（写进派单）

1. **字框合并**：造一个已知词条的测试窗（文件/保存全部/确定），
   合并后与 GT 的 **IoU ≥ 0.8**、**召回 100%**；「文 + 件」必须合成一框（gap=0、h 差 6%）。
2. **口径统一**：`ocr_window` 返回值必须带 `coord_space` 声明；
   **同一条 rect 在两条抓图路径下含义必须一致**（判法：两条路径各跑一次，同一区域给的框坐标差 ≤ 1px）。
3. **对齐**：OCR 词框加 origin 后与 UIA 物体求 IoU，**≥ 0.6 判命中**；
   且**必须用同一帧的 origin**，不许现取（窗口会动）。
4. **可点化**：R3 命中后，`ctl_screen` 的 `objects[]` 里必须出现**带 eid** 的该词元素
   ⇒ `ctl_click --eid <eid> --from_capture <cap>` 能点中。
5. **失败口径**：OCR 不可用 / 退化 / 没命中 ⇒ **不许**编一个对象出来。
