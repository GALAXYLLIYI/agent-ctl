## Q1｜K2：不立项（先把口径纠正）
**确定**：191ms 属于 `ctl_screen/_screen_build` 的整树扫描（`core.py:3457`），不属于 `ctl_tree`扫描——后者实测 **51ms**（`docs\七小时任务_阶段总结_20221022.md:36`）；`ctl_screen --since` 命中时已降到 31ms 且**不重扫 UIA**（同文 `:60`）。点击前的 live 复核**已经存在**（`core.py:3846`、`:3887-3899` 重走整树），所以缓存对点击路径没有任何收益，只加速重复“读”。
**待核实**：重复读的频次（先埋点，别先建缓存）。
**风险我认可，而且比你说的更重**：树观测的 `image_sha256` 为空时，`check_capture` 会**跳过图像比对**（`gate.py:1179-1182`）；若缓存节点还能签发 capture，陈旧的 rect 用于点击 xy 坐标就会**真正点错**，eid 复核无法补救。因此，缓存只允许回答“名字/文本”，**永不签 capture、不产坐标**；失效条件 = hwnd + 客户区 rect + 结构指纹 + TTL≤15s（`gate.py:1135`）+ 任何动作即失效。`window_gen` 不够：它只跟窗口清单签名（`core.py:1276-1279`），内容变化不会递增；“遮挡”测不到，别列进条件。上一轮已否过一次（同文 `:414`）。
