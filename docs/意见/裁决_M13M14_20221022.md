## 一、四个问题的裁决

| 问 | ZCode 的结论 | 裁决 |
|---|---|---|
| Q1 事件驱动 | **事件只当唤醒提示，判变仍以帧差为真相**；覆盖：原生表单值变（`EVENT_OBJECT_VALUECHANGE` / UIA `AutomationPropertyChangedEvent`）、网页文本（**只能靠 CDP 的 MutationObserver**）、焦点/前台（`EVENT_SYSTEM_FOREGROUND`）；**不覆盖**：Canvas/WebGL 重绘、未开无障碍的 Electron、自绘控件、动画/视频区 | ✅ **采纳，但本轮不立项**（理由见 §三） |
| Q2 区域抓帧 | 大概率「照样整窗渲染、只省拷贝」；**先用一条探针定生死**：省 <20% ⇒ 判负不立项；省 ≥50% ⇒ 才立项 | ✅ **采纳**（并入 M13 的阶段一探针） |
| Q3 PUSV 落地 | ★ **纠正主控**：PUSV 原文是**动作前的 TOCTOU 安全再验证**，**不是**为省动作后等待设计的；本机正确落法 = 把 L1（落点 masked SSIM）本地化进 `_bind_capture`（现成 `verify_image`），**附带**价值：有 `verify_expect` 谓词时动作后 budget 可折半 | ✅ **采纳（ZCode 纠正得对）**（见 §二） |
| Q4 第四刀 | 不在「抓」也不在「等」，在「**预算的形状**」：①固定 poll_ms 改**前密后疏退避** + 首变早停；②no-change 的整段等待是「证明没变」的必要成本，只能靠谓词折半和区域化收窄 | ✅ **采纳** ⇒ **M13 主刀** |

## 二、★ **修正 ZCode 对 PUSV 的定位**（ZCode 纠正的是我，这里如实记）

我在征询里写「PUSV 能让动作后不必长等」——**这个引申是错的**。

- 论文 `arXiv:2604.18860` 的 PUSV 是**动作前**的 TOCTOU 防御：
  L1 = 点击目标处 masked pixel SSIM；L2a = 全局截图 diff；L2b = X11 快照 diff；
  开销 **<0.1s**，180 次对抗试验 **100% 拦截、0 误报**。
- **它不是**「省动作后等待」的机制 ⇒ **M14 的定位改为「安全」**，
  本轮把它列为**独立价值**的一单（防 TOCTOU），而不是提速的一单。
- 它附带的提速价值只有一条：**有 `verify_expect` 谓词的动作**，动作后 budget 可折半
  （因为「期望」已声明 ⇒ 等待只需确认期望达成，不必确认任意变化）。

## 三、本轮**不立项**的（及理由）

| 候选 | 不立项理由 |
|---|---|
| **事件驱动等待（M13-a）** | ① 覆盖面窄（Canvas/自绘/未开无障碍的 Electron 全不覆盖）；② **架构约束**：钩子必须挂常驻进程（act 子进程只活 1~2 秒，注册成本摊不掉）；③ 正确形状是「事件到达 ⇒ 提前收轮询」，**不是「事件=结论」** ⇒ 仍需帧差兜底 ⇒ 收益被预算上限卡住。**挂账**，等 M5 的首变分布出来再评估。 |
| **spawn 常驻化** | 与「不起常驻进程」红线冲突（且 M11 已证 spawn 只占 95~100ms） |
| **换抓屏 API** | 主控**实测否掉**：BitBlt 比 PrintWindow **慢 3~4 倍**（16.2ms vs 52.4ms） |
| **去掉多余的 `.convert("RGB")`** | 主控**实测否掉**：省 **−0.42ms**（噪声内） |

## 四、★ 主控**排除**掉的一个疑似 bug（ZCode Q4 的怀疑）

ZCode 怀疑：「`_wait_effect` 的 HYSTERESIS 满足后是否真的立即 return？若等满 budget 才出就是白等。」

**主控实读 `legacy_tools/_src/act.py:1300-1356` 确认：早停存在**

```python
if streak >= max(1, int(need)):
    return {"生效": True, ...}     # ← 满足即返回，不等满 budget
```

⇒ **不是 bug，排除**。（这条要记在案：ZCode 的怀疑方向对，但本机实现已经是对的。
⇒ 顺带确认 M12 的设计：**「总有一帧可回传」** —— 画面没变时回传**最后一帧**，
core 用**自己的尺子**判它 ⇒ 这样连「没变」那一路也能省掉 core 的 300ms。**正是裁决要的那条。**）

### M13 的**硬约束**（写进派单，别踩）

1. **退避不许漏首变**：首变若落在稀疏轮次里 ⇒ 发现更晚 ⇒ **端到端反而变慢**。
   ⇒ 判据必须断言「稀疏阶段的发现延迟 ≤ 阈值」，且**端到端不许比 M12 后的基线更慢**。
2. **不许改预算上限**：`POLL_BUDGET_MS=800` 不许动（TOCTOU 铁律：只许改「每轮多贵」「轮询多密」，不许改「等多久」）。
3. **退避参数不许拍脑袋**：先导出**首变分布**（`first_change_ms`，≥100 次采样），再用数据定曲线。
