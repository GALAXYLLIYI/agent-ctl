主控手上有三份**互相打架**的数：

| 项 | 值 | 来源 |

⇒ **不先拆重叠就优化 = 优化不在关键路径上的部分**（白干）。**本单就是拆。**

## 一、本单只做三件事（**不改产品代码**）

### 1.1 import 成本归因（`python -X importtime`）

- 对**动作子进程的真实入口**跑 `python -X importtime -X utf8 -m agentctl.cli <一次只读动作>`，把 stderr 按 cumulative 排序，**取前 20 项**写进报告。
- 要回答：**哪几个模块吃掉了这 1100ms**（推断候选：numpy/cv2/PIL、pywin32、策略 JSON、Defender 首扫 —— **都是推断，必须实测**）。
- 同时量**空壳基线**：解释器冷启动 + 标准库的总时间（`-X importtime` 跑一个**空脚本**），以及**只导包**（`import agentctl`）的增量。
- **不许装任何东西**（不装 py-spy、不装 scalene）。只用标准库。

### 1.2 六点**绝对**时间线（不是分段总和）

在**副本**上打点（`work\_M17_解剖_20221022\` 下放副本，**不许改仓库里的 act.py**），打这 6 个时间点：

| # | 时间点 |
|---|---|
| ① | 参数解析完成 |
| ② | 子进程**真正开始执行**（脚本入口第一行） |
| ③ | 注入/投递完成 |
| ④ | 等生效开始 |
| ⑤ | 等生效结束 |
| ⑥ | 证据落盘完成（返回前） |

- 时间戳用 `time.monotonic()`（同进程内可比）+ `time.perf_counter_ns()` 记绝对值；**同时记父子进程的 `time.process_time()`**，以区分「等 IO」与「算」。
- 交一条**单次动作的完整时间线**（一次典型 + 一次最快 + 一次最慢），以及 n≥20 次的各段**中位数**。

### 1.3 ③/④ 是否重叠的证据

- 用 1.2 的时间戳直接回答：**等生效（④→⑤）与证据落盘（⑥附近）是并行还是串行？** ② 的 spawn 与 import 是重叠还是串行？
- 结论只写三种之一：**全串行 / 部分重叠 / 完全重叠**，并给出支撑的时间戳对照。
