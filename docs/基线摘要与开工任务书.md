## 1. 当前基线（**以此为准**，与设计文档冲突时以本节为准）

### 1.1 范围与红线

- **固定给一个指定 agent 用**，不是多租户（§20）。租约保留，但理由是**防同一个 agent 自己的并发调用**，不是仲裁多方。
- **铁律 11 一个字不改**：每次控制前弹窗授权（密钥不落盘、不回显、不经过 agent）／急停 `Ctrl+Alt+Home` ＋ `%LOCALAPPDATA%\AgentCtl\_急停.flag`（T10 起统一，不再用桌面路径）／档位 A→B→C→D 只升不跳。
- **远程命脉**：绝不碰 `GameViewer*` / `ToDesk*` / `主控模型 Harness.exe`；不断网、不改 IP/DNS/代理、不关机重启睡眠、不改分辨率多屏、不锁屏、不跑全屏独占。自检口诀：**「这一步会不会让我看不见屏幕？」会 → 不做**。

### 1.2 接口（§6 ＋ 契约）

- **三态同源**：MCP（stdio ＋ HTTP）／本地 HTTP JSON／CLI；**只监听 `127.0.0.1:8760`**。
- **20 个工具**，统一返回信封（含 `event_id` / `frame_before` / `frame_after` / `blind_spots`），**10 条信封错误码**（0/3/4/5/7/8/9/10/11/12）＋ **事件级内部码**（契约 `event_codes`，现有 `13` ＝ 录制自保护停录）。⚠️ **动作次数用尽 = `9`**，不是 13。⚠️ **没有 `14`**：服务没跑时压根没有进程、没有信封，真实表现是 TCP 连接被拒；版本对不上就自己拿 `ctl_status` 的 `data.service.schema_version` 比。
- **范围口径只有一套：A / B / C / D**（完整串由服务内部翻译）。
- ★ **坐标动作必须绑定观测**：`ctl_click --xy` / `ctl_drag` / `ctl_fill` 一律要求 `from_capture=<capture_id>`；窗口 rect／前台／图像哈希／TTL 任一变化 → `code=12`，要求重新观测。
- **能用控件名就别用坐标**；按 `name` 点击**不需要** `capture_id`。
- 一个写动作要合法：**通行证（用户签发）＋ 租约（单写者）**，缺一不可；顺序 `status → authorize → lease → act`。

### 1.3 时间与证据（§3 / §4 / §22 / §23）

- **时间源三层**：`perf_counter`（QPC、10 MHz、**不可调**、百万次采样零逆序）排序 ＋ 墙钟锚点对 ＋ **任务栏时钟见证**。
  ⚠️ `time.time()` 是 `adjustable=True`（**系统时钟可被改**）→ 只当"给人读"的锚，不当排序依据。
- **见证通道（已端到端跑通）**：裁屏幕右下角时钟区 → **LANCZOS 放大 4 倍**（**必需，1x 会漏时间行**）→ **Windows 自带 OCR（`zh-Hans-CN`）** → **把全角冒号 `：` 归一化** → 与系统墙钟比对，差 > 2 秒告警；认不出就写"未识别"，**绝不猜**。
- **证据分层**（替代"常录像"）：
  | 层 | 内容 | 频率 | 一天 |
  |---|---|---|---|
  | L0 | 动作事件流 | 每次动作 | 几 MB |
  | L1 | **控件树 gzip ＋ 窗口元数据** | 每 5 秒（变化才存） | 20–80 MB |
  | L2 | 全屏帧 0.25 缩放 | 每 60 秒 | ≈29 MB |
  | L2′ | 动作前后各 1 张 0.5 缩放 | 每次动作 | ≈13 MB |
  | L3 | 片段录像 | 不可逆动作／失败／用户点名 | 按需 |
  | | | **合计** | **≈100 MB/天** |
- **可信性**：jsonl 为真相源（追加式）＋ SQLite 索引 ＋ **哈希链** ＋ **带外锚点** ＋ **独立 verifier**（不在写入进程内）。
  ⛔ **不许说"双写＝防篡改"**——同目录同权限，双写只是抗损坏。⛔ **锚点不离开本机 ＝ 不可抵赖性≈0**。
- **SoM 图不落盘**：只存"干净底图 ＋ 元素表 JSON"，发给模型时现场渲染（实测画框会把 JPEG 撑大 22%–180%）。
- **录入 budget 要入账**：`ctl_verify`／见证 OCR／`capture_id` 校验／帧 sha256 都要记耗时，`ctl_status` 可见（§24.5）。

### 1.4 屏幕识别（§21）

**四档递进，先便宜后贵**：

1. **UIA 剪枝** —— 用 **control view** ＋ `includeOffscreen=false`；**判据看 `patterns`，不看 `enabled`**。
   本机实测：节点削 **26%**、字节省 **48%**（⛔ 不许拿网页的"500→20"来吹）。
   ★ **注意**：旧 `perceive.py` 的字段「可点击」取的是 `IsEnabled`，**34/34 恒为真、别信**。
2. **SoM 编号标注** —— 把元素矩形画上编号，让模型**输出编号而不是坐标**（从根上绕开"模型坐标被缩放 2.53 倍"的老坑）。
   依据：19 个 VLM 严格命中 ≤32%、60–92% 预测落在候选区外，**SoM 标注提升 35–57 个百分点**。
3. **局部放大** —— ⚠️ **只在①②都失败时用**（RegionFocus 实测 66.8% 轨迹开销）。
4. **本地 VLM 兜底** —— `qwen2.5vl:7b` 已在本机；建议再加 `qwen3-vl:4b`（3.3 GB）。**需用户同意才启 ollama**。
- **浏览器场景**：CDP/DOM 优先，**不存像素**，存 DOM 快照（Playwright trace／rrweb 是生产级先例）。
- **采集后端**：推 **`windows-capture`（Windows.Graphics.Capture）**（229 kB／MIT／"变化才出帧"／遮挡也能抓）。**需用户签字**。

- **网页场景（2026-10-14 实机补测）**：`ctl_tree --hwnd 461404` → **147 节点 / 637 ms / 不截图 / 整页 DOM 穿透 / 每元素带 eid＋类名＋rect**
  ⇒ **识别侧是这套系统最扎实的一块**；「网页用无障碍树而不用 OCR」的方向成立。
- **【当前未消的动作侧缺口（2026-10-14 实测 ＋ 读码复核）】** 识别侧已满足；**动作侧**有三个说法要分清：
  - **D1 成立**，但根因不是「eid 会变」，是**三条出口的 `roles` 口径不同**（`ctl_tree` 签发 / `ctl_find` 命中 / `ctl_click --eid` 重解析用了两套 roles）⇒ 同一个号在两张表里指不同节点，**窗口完全静止也点错**；
  - **D2 成立**，但根因是**深度不够**（老路径 `max_depth=10`，页面内容普遍深于 10 层）⇒ `--name` 在网页里**只命中浏览器外壳**；
  - **D3 不成立**（2026-10-14 本地 agent 裁定作废）—— 坐标**只有一套**：屏幕物理像素，`--xy` 原样收，不做任何换算。
  ⇒ **唯一正确的写法**（本目录 `docs\AGENT接口.md` **§3-bis**，全项目唯一定义处）：
  **拉树拿 `capture_id` → 同一快照内定位 → 15 秒内 `--xy ＋ --from_capture` 点**。
  （`capture_id` 的 TTL = **15 秒**，已按 `src/agentctl/gate.py` 的 `CAPTURE_TTL = 15.0` 常量核过，不是派单口径。）
### 1.5 打包（§9 / §18）

- **PyInstaller `onedir`**（onefile 是常驻服务的反模式：被杀时 `_MEI_*` 不清理）。
- ⛔ **MCP stdio 入口绝不能加 `-w`／`--noconsole`**（官方原文：那样 Python 就没有标准输入输出的目标了）。
- 免管理员安装器 → `%LOCALAPPDATA%\AgentCtl`；HKCU 卸载项；**默认不注册开机自启**。
- **构建产物必须放 `C:`**（实测 `F:` 只剩 10.0 GB，`C:` 剩 133.9 GB）。
- 无证书时 SmartScreen 表现 =**不签名与自签名相同**；诚实缓解＝**离线交付 ＋ 公示 SHA256**。

> 用户 2026-10-02 批复：**允许（启 ollama）／装（windows-capture）／开工**，并要求**把两条 OCR 路定下来**。
> 以下是**实测后的决定**，不是拍脑袋。

### 6.1 OCR 两条路：**①进程内优先，②shell 兜底（自动降级）**

| | **路线① `winrt-Windows.Media.Ocr`（进程内）** | **路线② shell 调 PowerShell 脚本** |
|---|---|---|
| 单次耗时 | **6–40 ms**（整块 4x 40 ms；时间行 6 ms） | **396–412 ms** |
| 首次加载 | 244 ms（进程启动一次性） | 已含在上面的 400 ms 里 |
| 读对了吗 | ✅ `21 ： 18 2026 / 9 / 27` | ✅ 同 |
| 依赖体积 | **2,851 KB**（8 个 pywinrt 包） | **0**（系统自带 PS） |
| 冻结后可用性 | ⚠️ **未测**（PyInstaller 要带原生 DLL） | ✅ **已验通，不依赖冻结** |
| 裁定 | **首选** | **兜底** |

**决定**：默认走 ①，**必须实现自动降级到 ②** —— 因为"①在冻结 exe 里能不能加载"尚未验证，
而 ② 已经端到端跑通过。降级要**在时间线上留痕**（`ocr_backend=winrt|powershell`）。

### 6.2 `windows-capture`：装，但**用一个 848 字节的 stub 顶掉 OpenCV**

**发现的坑**：`windows-capture` 的 `METADATA` 把 **`opencv-python` 列为硬依赖**，`__init__.py` 第 7 行就 `import cv2`。
而全库对 cv2 的**唯一用法是 `cv2.imwrite()`（存图）**——**抓屏本身完全不需要它**。

| 方案 | 代价 | 裁定 |
|---|---|---|
| 老老实实装 `opencv-python` | **42.0 MB**（v5.0.0.93；headless 也 41.8 MB，省不了） | ❌ 为一行存图拖 42 MB，不划算 |
| **写一个极简 `cv2` stub** | **848 字节** | ✅ **采用**（实测 `windows_capture` 加载成功） |
| 放弃 WGC 继续用 `mss` | 0，但丢掉"变化才出帧 + 遮挡也能抓" | ⏸ 备选 |

**stub 位置**：`agent-ctl\stubs\cv2.py`（只实现 `imwrite`，转交 PIL）。
⛔ **硬规矩**：**一旦发现别的代码路径也调用 cv2，立刻改成装真的 `opencv-python`** —— 不许让 stub 变成定时炸弹。

### 6.3 依赖落位方式：`vendor\` 目录，**不污染系统 Python**

- 位置：`<仓根>\vendor\`（**实测合计 3,471 KB**：winrt 2,851 KB ＋ windows_capture 552 KB）
- 方式：`pip install --target` 的等价物 —— 但我们**没用 pip**，而是**直连 PyPI 下载 wheel 再解包**。
- **为什么不用 pip**：本机 pip 实测**极慢**（一次 9 分钟无输出；后台再跑 2 分钟仍无输出），
  而 **urllib 直连 PyPI 下载 8 个 wheel 共 43 秒** —— **快约 13 倍以上**。脚本：`tools\fetch_wheels.py`（可复跑）。
- **好处**：可整目录删除、可随安装包一起打包、不碰系统 site-packages。
