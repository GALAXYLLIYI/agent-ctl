## 〇、结论（先行，回答唯一问题）

1. **UIA 能压，且第一刀不是 CacheRequest**。191ms（主控 ctl_screen/_screen_build 口径；本线服务端 elapsed_p50 实测 190ms，**对上了**）里生产 walk 是大头（notepad 110 节点上 tree()=129.9ms：纯遍历 64.2 + 属性/模式读 ~66）。三刀：**①找单目标用 FindFirst+条件（36.7→3.0ms，12×）**；**②`_text_of` 空名回退链（GetValue/GetText/LegacyIAccessible 三连问，uia_tree.py:154-190）收窄为 detail 才问**（-30~40ms，估）；③**FindAllBuildCache 全量带缓存是负优化，否决**（91.3ms vs FindAll 36.7ms，慢 2.5×——L8 的 210× 是「快照复用」即 K2，不是 CacheRequest，两者别混）。命中 K2 时 191→毫秒级（命中率埋点 core.py:1711-1757 已在测）。合计未命中口径 191→**~100-130ms**，判词不弱（判定只吃帧差+谓词 core.py:2873 起；live 复验已在 core.py:3396/3440）。
2. **抓帧 77.6ms 是 mss 整屏退路，不是热路径**。生产热路径 `framecache.capture_client`（framecache.py:154→digest flag=3 客户区）实测 **19.4ms**（900×620；digest 裸 8.4ms——wrapper 多出的 ~10ms **未核到原因**，列观察项交 M5/C）；mss 整屏 2560×1600=33.9ms+frombytes 10.2ms，是热路径的 3~5×，尽量避免触发。热路径剩余可压：**no-change 路径的整帧 after.png 还是 PNG**（core.py:3002/3006）→ 换 BMP 省 ~8ms（9.93→1.75，5.7×）。
3. **判词不弱有实测背书**：塞 8×8 方块 diff_images 判 changed=true 且 bbox=[100,100,107,107]（M6-①两级算法，光标规则修订后小方块不丢）；同帧基线 diff 4.38ms。
4. **证据 PNG 判定**：变了→只落 crop.png（小图，可忽略）；没变→落整帧 after.png（PNG 在热路径，见 2）。**本线不主张砍证据**，只主张 PNG→BMP 换格式。
5. **计划外发现**：ctl_tree/ctl_screen 每次调用的**dispatch 事后段 ≈347ms**（wall 501 vs 服务端 elapsed 154/190，两工具一致）——时间线落盘嫌疑最大，**归 M17-C 线深挖**，本线只交数。

### 4.4 证据留痕方案（判定帧=存证 buffer 同一块）

- **帧序号**：framecache.STATS 递增，探测帧/留证帧分账（core.py:2969 注释自证「留作 diff/落盘的只有这一张」）。
- **单调钟**：每帧附 perf_counter 时刻，与 M16R 打点同钟可对齐。
- **全帧哈希**：sha256(raw bytes)（raw 1.66ms 实测），与帧同 buffer 计算，不二次抓取。
- **无损裁剪**：变化区 crop.png（core.py:2999-3011 现状即如此）。
- **人复核**：变化区裁剪图+前后全帧哈希+帧序/钟对账 ⇒ 够用（复核的是「变没变/变在哪/有没有被动过」）。
- **是不是「省了证据」**：**不是**。省的是中间探测轮次编码（探测帧本就不落盘）；判定帧、首末帧、crop、哈希全保留。**唯一需主控裁决**：B-4 把 after.png 换 BMP 属格式变化（信息量不减：无损位图），建议照做；若有人提议「不落 after.png 只留哈希」那才是省证据，本线反对。
