## 1. 裁决要点（**这是约束，不是建议**）

### 1.1 形状（改你的候选 A）

你的候选 A 是「**act 判据 + stdout 回传结论**」⇒ **改成**：

> act 侧：`_wait_effect` 继续当「唯一的等待者」⇒ 但它只做两件事：
> ① 用 framecache 的尺子判定（见 1.2）；
> ② 把「第一次变化的那一帧」回传给 core —— 回传的是**帧**，不是「变了」这个结论。
> core 侧：拿到帧 ⇒ 用**自己的** `framecache.diff_images` 判 ⇒ 落 code；
> 解析不到 / 帧不新 / 退化 ⇒ 一律**回落** `wait_change`（老路），或落 unknown(code=5)。

⇒ **判定权只有一处（core）**。act 不许替 core 下「变了」的结论。

### 1.2 ★ act 侧的尺子必须换成 framecache 那一份（**消除双实现**）

现状：`act.py:1132 _img_diff` 与 `framecache.py:420 diff_images` 是**同一规则的两份拷贝**
（act 的 docstring 自证：「口径与 framecache.diff_images 同一套规则，阈值按 1/POLL_SCALE 缩放」）。
⇒ 问题不是「现在尺子就不一样」，而是「**改了 framecache 忘了改 act 就会漂**」。

**本单要求**：act 的判差**直接用 `framecache`**（同仓同 PYTHONPATH，**零新增进程**）。

★ **framecache 的真名与值（主控已核，照抄，不许自己猜字段名）**：

| 项 | 真名 | 值 / 位置 |
|---|---|---|
| 退化阈值 | `framecache.BLANK_STDDEV` | **3.0**（`framecache.py:87`） |
| 退化判据 | `framecache.is_blank(img)` | 灰度标准差 < 3.0 ⇒ 「没有画面」（`framecache.py:176`） |
| 变化阈值 | `framecache.DIFF_STEP` | 2（`framecache.py:70`） |
| caret 窄边 / 长宽比 | `DIFF_CARET_PX` / `DIFF_CARET_ASPECT` | 8 / 2.0 |
| 最小面积 | `DIFF_MIN_AREA` | 24（`framecache.py:72`） |
| 连续帧滞回 | `HYSTERESIS` | 2（`framecache.py:74`） |

⚠️ **act 侧现在 grep `degrad`/`退化`/`BLANK` 是 0 命中** ⇒ act **没有**退化检测。
本单要 act 每轮采样后调 `framecache.is_blank()`，**只打标**（`degraded=true`），
**不许** act 自己裁「变了没」—— 那是 core 的活。

走 **C2：act stdout 多打一行 JSON**（沿用 `act.py:3467` 既有 `print(json.dumps(...))` 约定）。
建议载荷（**字段名可改，但语义不许弱**）：

    {"effect": {"frame_ref": "<第一帧变化时的客户区图路径>",
                 "first_change_ms": 312, "rounds": 7, "degraded": false,
                 "health": {"uniq": N, "mad": X}}}

- core 侧解析**失败** ⇒ **回落** `wait_change`（多等 300ms，但**不误判**）；
- `degraded=true` ⇒ **unknown** ⇒ 落 **code=5**，永不当成功；
