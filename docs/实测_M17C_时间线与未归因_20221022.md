### 4.3 真凶的机制（复刻测量，非推断）

`store.py:336 _read_tail()` 的实现是**从文件头逐行读到文件尾，每一行都 `json.loads` 解析一遍**，只为了留下最后一条：

```python
with open(path, encoding="utf-8") as f:
    for line in f:
        line = line.strip()
        if not line: continue
        try: r = json.loads(line)      # ← 每行都解析
        except Exception: continue
        last = r                        # ← 只留最后一条
```

同机复刻测量（`timeline-20261022.jsonl`，**6 258.90 KB / 8 106 条有效行**）：

| 做法 | wall | CPU |
|---|---|---|
| 复刻 `_read_tail`（全读+全解析） | **363.8 ms** | 78.1 ms |
| 只读**尾部 8 KB**再取末行（seek 方案） | **0.61 ms** | ≈0 |

⇒ wall 远大于 CPU ⇒ 这是**「等 IO」不是「在算」**：文件正被常驻进程（`agentctl.mcp_http` / `ctl_border --follow` / `brake_daemon`）并发追加，页缓存被冲刷。
⇒ **这一刀能省 ≈395 ms/动作（端到端的 26.6%），且不动三值判定、不动闸门口径、不动契约。**
