## 二、主控**实测否掉**的两条路（省得下轮再试一遍）

### ① 用 `BitBlt`（屏幕 DC 拷贝）代替 `PrintWindow` ⇒ **否**

同一窗口（2543×1520 客户区），12 次取中位：

| 方式 | 中位耗时 |
|---|---|
| `PrintWindow`（让窗口自己画） | **16.2~17.6ms** |
| `BitBlt`（从屏幕 DC 拷） | **49.9~54.2ms** |

⇒ **BitBlt 慢 3~4 倍**。原因：屏幕 DC 拷贝要过显示驱动 + 150% 缩放；
`PrintWindow` 走应用自己的渲染路径反而更快。**这条路封死。**

### ② 去掉 `perceive._print_window` 里多余的 `.convert("RGB")` ⇒ **否**

现状整链（`PrintWindow` + RGBA→RGB→L→1/4 降采样）**21.38ms**；
去掉那次全图 RGB 转换后 **21.80ms** ⇒ **省 −0.42ms（噪声内）**。**不划算。**

⇒ 与文献 L3（Microsoft Learn `PrintWindow` 页）一致：**抓帧成本在「目标应用自己的渲染」里，不是拷贝方式** ⇒
想省只能**少抓**（复用帧 / 区域 / 事件），换 API 没用。
