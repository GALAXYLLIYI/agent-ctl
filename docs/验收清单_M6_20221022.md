## 三、我独立复核的项（每项都要我自己跑一遍）

### 3.1 帧复用（①）

| 检查 | 期望 | 判据 |
|---|---|---|
| 同一 `capture_id` 复用的动作 | **抓帧次数 ≤1**、**PNG 落盘 ≤1**、**UIA 扫描 ≤1** | 三条都要断言（本地 agent 指认：原派单只断言了 UIA 那条，最贵的两笔没覆盖） |
| 版本进位后 | 必须重扫 | 有断言 |
| 变化判据：静止桌面连抓 10 帧 | **10/10 判「没变」** | 窗口A 口径 |
| 变化判据：注入 caret 闪烁 | **不得判变** | `_act_diff_of` 的窄边滤除（<8px） |
| 变化判据：动画区 | **连续 2 帧**都超阈才上报 | 本地 agent 口径，两条叠加才算完整 |
| 变化判据：真变化 | 必须判变 | 不漏 |
| `--inject` | 变红 | R4 |

### 3.2 耗时数字（我自己重测，不抄它的）

| 指标 | 怎么测 | 注意 |
|---|---|---|
| 单步感知延迟 | 同一目标、同一条动作，**≥5 次取中位数** | 报 med + min/max，不许只报一个数 |
| 一步动作总耗时 | 同上，**含回读** | 改前改后**同一动作同一目标**，否则不可比 |
| 抓帧/落盘计数 | 用判据里的计数钩子，不靠肉眼看 | —— |

**我不接受**：「体感变快了」「大概省了 X ms」这类没有口径的说法。

### 3.3 图标匹配（③）

| 检查 | 期望 |
|---|---|
| 已知图标集 top-1 命中 | **≥95%** |
| 干净桌面负样本误报 | **= 0** |
| 缩放 ±10% / 旋转 ±5° | 不崩 |
| 字体渲染路线 | **按窗口 DPI 渲染 + 关 ClearType**（本机 150%，不关会掉分） |
| `--inject` | 变红 |

### 3.4 GPU 抓帧（②，本轮只出结论）

| 检查 | 期望 |
|---|---|
| 有没有动 src | **不许动** |
| 结论是否覆盖风险 | 必须写清：DRM/受保护内容黑屏、WinRT 绑定、与屏幕不同步的可能 |
| 是否说清「为什么不值得本轮做」 | 量级：30ms 里省 10–20ms vs 一条动作 400–600ms |

## 四、判定口径

| 档 | 定义 |
|---|---|
| **算解决** | 红线一条不犯；④ 表里有可复现的计时口径；我独立复跑 3.1 的断言全过；未验项诚实 |
| **不算解决** | 判据自己说绿但我复跑不过；或数字没口径；或顺手动 contract / 引依赖 |
| **算验不了** | 环境限制导致某条测不了 ⇒ **必须点名是哪一条**，不许笼统写「环境限制」 |

## 五、复核后的动作

- 算解决 ⇒ 记事件流 `task_verified`，进 M7。
- 不算解决 ⇒ 把失败项写成**具体一条**返工单（不是「再改改」）。
- 算验不了 ⇒ 拆出「能验的那部分」先过，验不了的那部分挂账并写明代价。
