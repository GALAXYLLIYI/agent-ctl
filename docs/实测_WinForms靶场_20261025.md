# 实测：WinForms 靶场（2026-10-25 11:3x–11:5x）

> 目的：给 A/B 换一个 **UIA 有名字**的靶场（tkinter 只有无名 Pane，按名字定位不可用）。

## 做出来的东西

`tools\ab_target_winforms.ps1`：PowerShell WinForms，8 控件（TextField×3 / ComboBox×2 / CheckBox×2 / 提交按钮），
控件 `Name` = `text_1..3 / combo_1..2 / check_1..2 / submit`，提交写 JSON。

## 实测（UIA 能看见，名字全对）

| 项 | 结果 |
|---|---|
| `ctl_find`（窗口恢复+置顶后） | **83ms，23 节点**，`EditControl text_1/2/3`、`ComboBoxControl`、`CheckBoxControl`、`ButtonControl 完成` 全部有名 |
| 窗口最小化时 `ctl_find` | **code=4，并明说「窗口已最小化，UIA 树是塌的」**（诚实拒绝，不猜） |
| `ctl_fill`（eid 路径） | **code=5**：报「填字段坐标 (0,0) 不在窗口矩形」+ DPI 不一致提示（目标窗 96 DPI 在 150% 系统里） |
| `ctl_click`(xy)+`ctl_type` | **code=3（敏感窗/白名单拒绝）**——该 WinForms 窗口需**逐窗口人工放行**；之前一次临时放行只对旧进程类名有效 |

## 结论

1. **UIA 定位在 WinForms 上完全可用**（名字、类型、耗时都对）；
2. 但 **写动作被两道设计挡住**：① eid→fill 的坐标解析在这套 DPI 组合下取到 (0,0)；② 新窗口类名要走**人工放行**（code=3）。
3. 对比：**记事本路径是通的**（`text_1` 那套 skill 回放 2/2）——因为它属于默认放行/已确认的窗口。

## 对 A/B 的处置

- A/B 的 AgentCtl 侧**改用记事本/已放行窗口**，或由用户在面板上对 WinForms 窗口点一次放行；
- 靶场脚本保留（UIA 名字齐全），等放行后可直接复用；
- **不把 code=3/5 当失败**：它们是设计内的拒绝，报告里按“被拒”计，而不是“能力不足”。
