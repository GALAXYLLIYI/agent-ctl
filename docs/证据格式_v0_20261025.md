# 证据格式 v0（2026-10-25）

> 实现：`src/agentctl/evidence.py`。**只定义结构与序列化/校验，不接线** —— 不被任何现有模块 import，
> 不进 `core.py` / `action_guard.py` / 任何契约；加这个文件**不改变任何现有行为**。
> 用途：把「谁、对什么、做了什么、等了多久、判成什么、凭什么」写成一条**可复算、可复核**的记录。
> 与 `work\_actions\*\evidence.json` 的区别：那是动作现场回执（字段更散），本格式是它的**规范化子集 + 复算声明**；
> v0 不读也不写那些文件。

## 一、字段（顺序 = 序列化顺序）

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema_version` | int | 格式版本，**固定 0**。由代码填，调用方传别的值直接报错 |
| `actor` | str | 做这件事的主体（agent / 工具 / 人），不许为空 |
| `target` | dict | 作用对象：`hwnd` / 窗口名 / 元素名 / 判定区等，随动作自定 |
| `frame_hash` | str | 拍到的画面摘要（`digest.window_digest` 口径）。**取不到就写空串**，不许编 |
| `action` | dict | 动作参数（工具名、坐标、文本等），随动作自定 |
| `wait_ms` | int | 动作后等了多久才判定（等生效预算），≥0 |
| `verdict` | str | 判词：`met` / `no_effect_in_region` / `changed_outside_target` / `unknown`；不许为空 |
| `reasons` | list[str] | 判定理由（可空列表；空 = 没写理由，不代表没判） |
| `evidence_refs` | list[str] | 证据引用（前后帧、时间线 id、日志路径等），v0 只存不解析 |
| `recompute_spec` | dict | 复算参数，**至少**含 `DIFF_STEP` / `HYSTERESIS` / `need`，三者均为正整数 |
| `recomputable` | bool | 是否**结构层可复算**；**默认 False**，必须主动声明 |
| `notes` | str | 备注；`from_json` 忽略的未知字段会追加在这里 |

## 二、序列化约定

- `make_record(**kwargs) -> dict`：缺必填字段、未知字段、类型不对、`recompute_spec` 缺键、
  `schema_version` 非 0 ⇒ `ValueError`，**中文报错且指明字段名**。
- `to_json(rec) -> str`：`ensure_ascii=False`（**中文不转义**）、`sort_keys=False`，
  且**按 `FIELDS` 重排**后输出 ⇒ 同一份证据永远同一串字节；**不信输入 dict 的键序**。
- `from_json(s) -> dict`：接受 `str` / UTF-8 `bytes`；未知字段**忽略**但记入 `notes`；
  缺 `schema_version`/`recomputable`/`notes` 按默认补；最后一律 `validate()`。
- `validate(rec) -> None`：合格返回 `None`，不合格抛 `ValueError`（带字段名）。
  **未知字段在 `validate`/`make_record` 里是错误**（防拼写错静默丢字段），只有 `from_json` 宽容。
- round-trip 约定：`from_json(to_json(rec)) == rec`（前提：原文没有未知字段）。

## 三、复算分两级（这张表是本格式的全部价值）

| 级别 | 能复算什么 | `recomputable` | 复算方式 |
|---|---|---|---|
| **结构层** | 记录结构、字段值、判词归类、参数一致性 | 允许 `True` | 纯数据重放：同样的输入 + 同样的规则函数 ⇒ 同样结论 |
| **像素层** | 两帧之间到底变没变、变在哪、算不算我的 | **必须 `False`** | **不能独立复算**，只能按 `recompute_spec` 用**同一函数**重算 |

- `recomputable=True` 只给**纯数据层**：由 `make_record` 显式传入，**默认 False**。
- 凡记录涉及像素/图像参数（帧、PNG、裁剪区、bbox 等）**必须为 `False`**；
  代码对「`recompute_spec` 里出现像素类键名却声明 True」会直接报错（这是下界防手滑，不是完备判定）。

## 四、为什么像素层不能独立复算

- 算法在 `framecache.diff_images` 与 `core._causal_verdict`：阈值 **2/255**、**分块 + 并查集**、
  **caret 形状滤除**（窄边 ≤8 且长宽比 ≥2 才丢）、**最小面积 24px²**、判定区**求交**决定四态判词。
  这些是**过程**，不是结果：照着文档重写一遍，边界情形必漂移（`changed=True/False/None` 里
  `None` 与 `False` 分不清就是「没测出来」被写成「确认没变」，正是 M19 系列修过的病）。
- 因此原则与 `digest.py` 一致：**签发侧与校验侧必须调同一个函数**（调两个函数哪怕算法一样也等于没统一）。
  像素证据只带 `recompute_spec`（`DIFF_STEP` / `HYSTERESIS` / `need` …），校验方拿**原函数**重算，
  再比对 `recompute_spec` 与实际一致 ⇒ 结论才可信。
- 一句话：**像素层不可独立复算，只能按 `recompute_spec` 用同一函数重算。**

## 五、v0 明确不做

- ❌ 不接线：没有模块 import 本模块，判词/台账/闸门行为**一律不变**。
- ❌ 不定义判词枚举的强校验（`verdict` 只校验非空字符串）；判词表等 T3 接线时再收。
- ❌ 不读不写磁盘、不做哈希链、不替代 `work\_actions\` 现成回执。
- ❌ 不声称「防篡改」：格式只保证**可复算与字段稳定**，防篡改要靠时间线哈希链（`store.py`）。
